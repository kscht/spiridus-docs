# Проекты

Проект — закрытое пространство совместной работы: статьи Markdown, ресурсы (картинки, модели,
другие файлы), история и участники с ролями. У проекта есть стабильный `id`, неизменный адрес `slug`
и изменяемый заголовок `title`. Статьи и ресурсы записываются в ветку `main`.
Эта же справка доступна через `render_block_docs({lang:"projects"})` в MCP и REST.

На сайте [«Проекты»](https://v2.spiridus.ru/p/) после входа основным ключом видны свои проекты
и приглашения. `/p/<slug>/` — дерево, `/p/<slug>/<путь>.md` — статья текущей головы `main`.
`/p/<slug>/<папка>/` — папка: сначала `README.md`, при его отсутствии `index.md`, затем содержимое.
На сайте статьи читают; пишут через модель с MCP или скрипт с REST. Истории и редактора статей
на сайте пока нет. Без входа или роли проект неотличим от несуществующего.

## Получить или создать проект

Регистрация сама по себе не даёт права создавать проекты. Попросите приглашение в существующий
проект у его владельца/админа или право создания у владельца Spiridus:
[kscht@tutamail.com](mailto:kscht@tutamail.com). По умолчанию можно владеть до 10 проектов.

Подключите модель к `https://v2.spiridus.ru/mcp/p/projects` ([MCP](mcp.md)). Через `tools` можно
выбрать `tools({use:"projects"})`; это заменяет набор. Вызовы ниже — аргументы инструментов MCP;
в REST те же объекты отправляются на `POST /api/v1/tools/<имя>` с ключом из окружения.

1. `projects({})` — свои проекты, приглашения и предложения владения.
2. Если право выдано: `projects({action:"create", slug:"atlas", title:"Атлас"})`.
3. `project_read({project:"atlas", op:"tree"})` — дерево; у нового проекта `commit: null`.

```sh
curl -fsS https://v2.spiridus.ru/api/v1/tools/projects \
  -H "Authorization: Bearer $SPIRIDUS_KEY" -H 'Content-Type: application/json' \
  --data-binary '{"action":"create","slug":"atlas","title":"Атлас"}'
```

## Роли и права

Роль проверяется на каждом вызове, в том числе после ожидания очереди. Любой явный `version`
или `commit` запрещён читателю, даже если это хеш текущей головы.

| Действие | Reader (читатель) | Editor (редактор) | Admin (админ) | Owner (владелец) |
|---|---|---|---|---|
| Дерево, статьи, ресурсы, ссылки; проверка сохранённой головы | Да | Да | Да | Да |
| История, версии, проверка черновика | Нет | Да | Да | Да |
| Запись, перенос, восстановление, импорт, ресурсы, скрытие статей | Нет | Да | Да | Да |
| Список участников | Нет | Да | Да | Да |
| Журнал проекта и email приглашений | Нет | Нет | Да | Да |
| Приглашать, менять роль, исключать editor/reader | Нет | Нет | Да | Да |
| Приглашать, назначать, менять и исключать admin | Нет | Нет | Нет | Да |
| Переименовать заголовок проекта | Нет | Нет | Да | Да |
| Предложить/отменить передачу, удалить/отменить удаление, стереть историю, удалить версии ресурсов | Нет | Нет | Нет | Да |
| Выйти из проекта (`leave`) | Да | Да | Да | Сначала передать владение |

Принять или отклонить **своё** приглашение может адресат с подтверждённой почтой ещё до получения
роли. Принять владение может только назначенный действующий участник с правом создавать проекты
и свободной квотой владения. Другой владелец произвольно принять передачу не может.

Права ключа — независимое ограничение: `mcp` или `rest` для канала, `files` для `upload:`/`blob:`
и файловых инструментов, `docs` для `project_import` и прежних документов. `private:` требует
прав, записанных в метке результата. Роль ключ не расширяет; прав `project:<id>:read/write`
пока нет, `git:read/write` зарезервированы. Из Code Mode закрыты `project_hide`, `project_members`,
`invitations`, `project_admin`: вызывайте их напрямую по просьбе человека. У проектных инструментов
нет фонового режима `async=1`/`.start`.

## Записать и проверить статью

Первый `project_write` в пустом проекте:

```json
{"project":"atlas","base":null,"files":[{"path":"Начало.md","content":"# Начало\n\nПервая статья.\n"}]}
```

Один пакет статей — один коммит. Для следующей правки прочитайте статью через
`project_read({project:"atlas", op:"read", path:"Начало.md"})`, измените `content` и передайте
`commit` ответа как `base`. Автора и сообщение коммита задаёт шлюз. `unchanged: true` — успешная
запись без изменений, нового коммита нет; `commit` и `base` ответа указывают текущую голову.

Проверьте сохранённую статью:

```json
{"project":"atlas","path":"Начало.md","shots":"none"}
```

Это аргументы `render_check`. Редактор может добавить `markdown` для проверки черновика.
Снимки и результаты проверки с `project` приватны, читатель видит только сохранённую голову.
**Без `project` снимки проверки доступны публично по ссылке.** [Проверка статьи](check.md).
Адрес для человека берите из `url`; у пакета это корень проекта, `urls` содержит адреса по путям.

### Конфликт записи

Если после `base` изменились записываемые пути или исчезли цели ссылок статьи (перемещены,
скрыты, удалены), весь пакет отклоняется без записи: MCP `isError` с текстом `409: …`,
REST HTTP 422 с `data.error.code: 409`. В MCP поля доступны в `structuredContent.error`,
в REST — в `data.error`:

- `commit` — текущая голова, которую нужно перечитать; `base` — база отклонённого запроса.
- `reason: "paths-changed"` — после базы менялись пути записи, даже если изменения затем откатили.
  `reason: "targets-missing"` — исчезли цели ссылок; `paths` перечисляет эти цели.
- `reason: "base-mismatch"` — `null` не соответствует пустоте проекта;
  `"base-unavailable"` — база недоступна в текущей истории либо список изменений слишком велик.
- `paths` при конфликте путей содержит изменённые пути, пересекающиеся с запросом;
  `pathCount` — полный счётчик, `pathsTruncated` — сокращение списка до 100 путей и 32 КиБ.
  Текст ошибки показывает до 20 путей. Исходники статей в ошибку не входят.

Изменения других статей допускают прежний `base`, если пути не пересекаются и цели ссылок
не исчезли. Изменение содержимого цели, в том числе её заголовка, само по себе запись не блокирует.
Две правки **одной** статьи конфликтуют даже в разных разделах: автоматического слияния текста нет.

1. Сохраните свой текст и исходный текст, прочитанный на `base`, отдельно.
2. Перечитайте дерево и затронутые статьи через `project_read`. Для сравнения исходника можно
   вызвать `project_read({project:"atlas", op:"read", path:"Начало.md", version:"<прежний base>"})`.
   Если путь исчез, найдите новое место в дереве и истории; не создавайте старую статью вслепую.
3. Сравните три текста: исходный на прежней базе, свой и текущий. Наложите только свою разницу
   на текущий текст, сохранив изменения коллег; исправьте ссылки на исчезнувшие цели.
   При пересечении правок согласуйте итог с человеком.
4. Повторите `project_write` с `commit` **прочитанного текущего текста** как `base`, затем
   `render_check` с `project` и `path`. При новом 409 повторите чтение и слияние.

Например, вы добавили абзац в конце статьи, а коллега исправил введение. После 409 прочитайте
новую статью, сохраните исправленное введение и добавьте свой абзац; отправьте объединённый текст
с `commit` этого чтения. `commit` из ошибки — подсказка для чтения, сам по себе он не подтверждает,
что вы учли чужую работу. Не заменяйте только `base` в прежнем запросе.
При неясном исходе сетевого вызова сначала прочитайте состояние, не повторяйте запись вслепую.

## Приглашения и письма

Регистрационное приглашение от владельца системы позволяет создать учётную запись, но не даёт
роль в проекте. Проектное приглашение от owner/admin связано с email и ролью; новый адресат может
зарегистрироваться по его ссылке. Это два назначения адресов `/invite/…`.

Отправить проектное приглашение:

```json
{"project":"atlas","action":"invite","email":"colleague@example.com","role":"reader"}
```

Это `invitations`; админ может приглашать reader/editor, owner также admin. Адресат получает
письмо **«Spiridus: приглашение в проект»** со ссылкой `/invite/<token>` на **7 дней**.
Письмо одинаково для нового и существующего пользователя. Открытие ссылки само не раскрывает
email/название проекта и не даёт доступа.

- **Учётной записи нет:** на странице приглашения укажите email адресата и свободный nickname,
  подтвердите почту по письму. Ссылка подтверждения действует сутки. На странице подтверждения
  появится кнопка «Принять приглашение в …»; нажмите её. Подтверждение почты само приглашение не принимает.
- **Учётная запись есть:** войдите существующим **основным** ключом. Затем примите приглашение на
  странице или в [«Проектах»](https://v2.spiridus.ru/p/). Через MCP/REST —
  `invitations({action:"accept", id:"<id из projects>"})`; отказ — `decline`.

> **Не регистрируйтесь повторно ради приглашения, если учётная запись уже есть.** Повторное
> подтверждение регистрации заменяет основной ключ: прежний перестанет работать.

Принять может только учётная запись с приглашённым подтверждённым email. Ссылка не позволяет
передать роль другому человеку. При истечении срока попросите новое приглашение. Owner/admin
может отозвать ожидающее через `invitations({project, action:"revoke", id})`; участника исключают
через `project_members`, отзыв приглашения уже принятую роль не снимает.

По умолчанию: до 50 приглашений в сутки от отправителя, 3 одному адресу, 100 от проекта;
ожидающие приглашения резервируют места в пределе 50 участников. Завершённые/истёкшие записи
с email хранятся ещё 30 дней, уборка раз в час. [Хранение данных](data.md).

## Ресурсы и серверные блоки

Картинка — ресурс проекта по пути, например `media/схема.png`. Положите её отдельным `project_write`:

```json
{"project":"atlas","base":"<commit из project_read>","files":[{"path":"media/схема.png","ref":"upload:<id>/схема.png"}]}
```

Допустим один ресурс не `.md` с `base64` или `ref`: своя загрузка `upload:`, своя публикация
`artifact:` из `files_publish` или `private:` результата расчёта, связанного с **этим** проектом.
Личный `private:` и результат другого проекта не подходят. Предел ресурса — 12 000 000 байт.
В статье `Начало.md` пишите `![Схема](media/схема.png)`, из подпапки — путь относительно статьи.
Для ресурса доступны `put`, `move`, `copy`, `delete` и `project_read op:"versions"` (история — редакторам).
Удалить используемый ресурс нельзя: сначала исправьте ссылки из списка мешающих статей.

`project_read op:"read"` ресурса выдаёт подписанный `url` до 15 минут. **Не вставляйте его в статью
и не публикуйте: выданную подпись нельзя отозвать**, даже после исключения участника.
Из Code Mode выдаются только сведения о ресурсе без URL. Новые выдачи проверяют текущие права.

Готовые блоки `hdl`, `digitaljs`, `vcd`, `plantuml`, `structurizr`, `qet`, `qiskit`
сохраняйте через `project_write put` или `project_import`: ссылочные поля по контракту
материализуются целым набором в новый каталог, а статья получает относительные пути.
Инструмент вызывайте с `project`: вычисление и его исходники останутся закрытыми.
Свой доступный `artifact:` и обе формы адреса `/artifacts/…` тоже можно материализовать;
готовый текст статьи уже не содержит временных ссылок. У QET учитывается входной
файл `project` в JSON, включая свою `upload:` с проверкой её проектной метки.

Для остальных потребителей поддержка подключается отдельно. До неё
картинку сохраняют обычным ресурсом и вставляют Markdown-картинкой, файлы модели —
ресурсами по относительным ссылкам. Текстовый VCD/STL остаётся допустимым.
Читатель `/p` показывает сохранённые байты и локальную интерактивность без расчёта.
В статье с блоком результата оставшаяся `upload:` вне объявленного входного поля
также вызывает отказ; обычные статьи с примерами `upload:` этим не ограничены.

Зарегистрированный набор результата может показывать «заверено шлюзом»: шлюз
подтвердил исполнение указанного инструмента в точной сборке (`imageId`) и связал
отметку с полным составом файлов и их sha256 в индексе. Это происхождение результата;
соответствие текущему исходнику/параметрам проверяется отдельно, корректность расчёта
отметка не доказывает. Авторский `meta.json` не создаёт заверения. Соседний файл,
ручная загрузка или непроверенный старый результат его не наследуют; для них сведения
из meta помечаются «по данным meta.json, не заверено», без meta —
«происхождение/соответствие не проверено». Перенос неизменённого набора и его история
сохраняют отметку. Читателю она выдаётся вместе с разрешённым снимком, после проверки
роли; отдельного поиска происхождения по oid нет.

## Навигация

На сайте крошки ведут к родительским папкам. «Назад» и «Вперёд» открывают соседние статьи
в порядке дерева: папки перед файлами, числа в именах по значению. История браузера тоже работает.
«Перейти…» (`Ctrl+K` / `⌘K`) ищет по имени и пути статьи текущего проекта; стрелки выбирают
результат, Enter открывает, Escape закрывает окно и возвращает фокус. На телефоне доступна та же кнопка.
Оглавление, обратные ссылки и соседние статьи раскрываются над статьёй; учитывается только видимое содержимое.
Текущая статья не включается в свои обратные ссылки. Оглавление использует точные DOM-id
(например, `#u-детали-1` для повторного заголовка). Эти адреса работают на сайте, но отличаются
от канонических цепочек заголовков вида `#Глава%20Б#Детали`, описанных в формате статьи.
Если проект изменился между чтениями или индекс недоступен/неполон, страница сообщает об этом.

В статье: `[План](План.md)`, `[раздел](План.md#Глава%20Б)`, `[выше](#Начало)`,
`[блок](План.md#^block-1)`. Пробел в адресе кодируйте `%20`. Правила цепочек заголовков,
маркеров `^id`, старых слагов и преобразования `[[…]]`/`![[…]]` при записи —
[в формате статьи](markdown.md#ссылки-и-навигация-в-проекте).

`project_read({project:"atlas", op:"links", path:"Начало.md"})` возвращает `links`, `backlinks`,
`dangling` из головы: скрытые статьи и другие проекты не раскрываются. `count` — полный счётчик,
`truncated` — сокращение ответа (до 100 элементов на список и 64 КиБ всего).
Прочитать раздел — `op:"read", path:"План.md", fragment:"Глава%20Б#Детали"`; блок — `fragment:"^block-1"`.
Можно передать `/p/atlas/План.md#^block-1` в `path`. Ответ содержит `heading`/`block`, `method`,
границы строк, `warnings` и `url`; раздел включает подразделы. Не найден фрагмент — ошибка 422.

`put.warnings` сообщает о пропавших якорях и возможной/определённой смене цели; повторения
группируются с `count`. Смена заголовка не переписывает чужие ссылки. `navigation-unavailable`
означает, что ссылки не проверены; это не пустой список замечаний. [Поля ответа](tools.md#проекты).

### Настройки хранилища Obsidian

В **Settings → Files and links** рекомендуются:

- **Use [[Wikilinks]] — выключено**: новые ссылки сразу записываются в Markdown.
- **New link format — Relative path to file**: ссылки относительно текущей статьи.
- **Automatically update internal links — включено**: при переносе и переименовании в Obsidian
  обновляются ссылки. В Spiridus переносите статьи через `project_write op:"move"`.

Названия настроек приведены для Obsidian 1.14.5. Хранилище в Obsidian и проект Spiridus
не синхронизируются автоматически; настройки помогают сохранять совместимый исходник.
Ссылки в свойствах YAML Spiridus пока не переписывает при переносе.

## Перенос, переименование и скрытие

`project_write({project, base, op:"move", from:"Начало.md", to:"статьи/Введение.md"})` переносит
или переименовывает статью. Ссылки остальных статей на прежний путь исправляются в том же коммите,
а относительные ссылки перенесённой статьи пересчитываются от нового места. Так же переносят ресурс.

Для папки укажите её путь без завершающего `/`, например:
`project_write({project, base, op:"move", from:"главы", to:"архив/главы"})`.
Все вложенные статьи, ресурсы и зарегистрированные наборы результатов переносятся одним коммитом;
ссылки внутри и снаружи папки исправляются, включая скрытые `%%`, якоря заголовков и `#^id`.
Файлы набора результата отдельно переносить нельзя. Назначение должно быть свободно;
перенос в себя и изменение исходной папки после `base` дают отказ без частичного переноса.
Если хотя бы одна статья проекта не разобрана полностью, операция получает
`422 markdownIntegrityIncomplete` с `articles` и причинами; коммита нет.
Ссылки из других проектов и внешние закладки после переноса автоматически не исправляются.

`project_admin({project, action:"rename", title:"Новый заголовок", confirm:"atlas"})` меняет только
название проекта; `slug` и адреса не меняются.

`project_hide({project, base, paths:["статьи/Введение.md"]})` убирает статьи из `main`, сохраняя историю.
`brokenLinks` предупреждает о входящих ссылках, но не блокирует скрытие; `null` — проверить не удалось.
Вернуть — `project_write` с `op:"restore", paths, version` из истории и текущим `base`.

## Передача, удаление и стирание

У `project_admin` обязателен `confirm` — точный slug. Попросите человека явно подтвердить действие.
Владелец предлагает `action:"transfer", member:"<shadow участника>"`; адресат получает письмо
**«Spiridus: передача владения проектом»**. Открытие письма владение не меняет: адресат с правом
создавать проекты и свободной квотой явно вызывает `accept_transfer` с `id` предложения из `projects`.
Отменить предложение — `cancel_transfer`.

`delete`: единоличный проект удаляется сразу; совместный — через **7 дней** только чтения.
Участникам приходит письмо **«Spiridus: проект удаляется»** со сроком. До него владелец может
`cancel_delete` или передать владение. Повторный `delete` срок не продлевает.
Удалить учётную запись владельца совместного проекта нельзя (409): сначала передайте владение
или дождитесь завершения удаления. Единоличные проекты при удалении учётной записи удаляются сразу;
вклад и ресурсы в чужих проектах сохраняются, автор показывается как удалённый участник.

`erase` с `paths` стирает файлы **со всей историей** и производными результатами; `delete_versions`
с `path`, `version` закрывает выдачу старой версии ресурса, но не текущей в `main`.
Скрытие и обычное удаление ресурса историю не стирают. Только owner может выполнять эти операции.
Без обработчиков/реестра стираний удаление отвечает 503. Выданные подписи действуют до 15 минут;
резервные копии и нынешнее ограничение реестра описаны в [данных](data.md#проекты).

## Пределы и имена

Значения по умолчанию; установка может задавать другие пределы.

| Что | Предел |
|---|---|
| Своих проектов / участников проекта | 10 / 50 (включая ожидающие места) |
| Файлов проекта | 5000 |
| Git / ресурсы проекта | 50 МиБ / 1 ГиБ |
| Статья / ресурс | 512 КиБ UTF-8 / 12 000 000 байт |
| Запрос `project_write`/`project_import` | 16 МиБ |
| Путь / сегмент пути | 500 / 255 байт UTF-8 |
| Индекс ссылок: вход / ссылки и якоря / результат | 32 МиБ / 100 000 / 16 МиБ |
| Разбор ссылок статьи / операция | 5 с / 30 с |

Slug — 1–80 знаков: начинается с `a-z`, далее цифры/латиница и одиночные дефисы между группами;
не заканчивается дефисом и не совпадает с id вида `p-` + 24 hex. Аргументы — [аргументы](arguments.md#projects--мои-проекты).
Удалённый slug повторно не выдаётся. Пути — NFKC, латинские/кириллические буквы, цифры, пробел,
точка, `_`, `-` и `/` между сегментами. В одном слове нельзя смешивать латиницу с кириллицей
(разделители слов — пробел, `.`, `_`, `-`). Нет пустых сегментов, начальных пробелов,
конечных пробелов/точек, невидимых знаков, `.git`, `.gitattributes`, `.gitmodules`.
Регистр сохраняется; путь, неотличимый на вид от существующего, даёт конфликт 409.

## Прежние документы `/d`

Новые `/d` не создаются. Прежний документ публичен по ссылке **со всеми версиями** (`?v=…`);
`document_share {id}` обновляет свой документ, `documents_list`/`documents_catalog` находят свои,
`document_delete` удаляет, `GET /api/v1/docs/<id>.md` выгружает исходник. `editUrl` и кнопка
«✎ Редактировать» открывают живой редактор; его правки сами документ не сохраняют:
для сохранения нужен `document_share {id}` через модель или скрипт.

> **Учётная запись без проектов удаляется через 7 дней без обращений. Вместе с ней удаляются
> все `/d` и их история.** За 3 суток до срока приходит письмо со сроком и адресами своих `/d`.
> Вход на сайт основным ключом или запрос к API с действующим ключом отменяет удаление и начинает
> срок заново; публичное чтение без ключа — нет. После успешной отправки письма до удаления
> проходит не менее 3 суток; сбой почты откладывает удаление. Бессрочный ключ это не отменяет.
> Пока переносите данные или ждёте доступ к проекту, пользуйтесь ключом чаще раза в неделю
> и сохраните исходники у себя. Владельцы проектов и записи с правом создания исключены из
> удаления за простой; для остальных участников срок — 90 дней.

Перенос: `project_import({project:"atlas", id:"<id своего /d>", path:"статьи/Начало.md"})`.
Нужны роль editor и выше и право ключа `docs`; сначала получите проект или попросите право создания.
Копируется последняя версия одним коммитом, исходный `/d` не меняется. Занятый путь — конфликт 409.
Публичные `artifact:` из ссылок статьи становятся ресурсами `media/…` с исправлением относительных путей;
в коде и блоках нотаций ссылки остаются и попадают в `unavailable`. Пока они не убраны/заменены,
проверка и обычная запись статьи запрещены — учтите [нынешнее ограничение серверных блоков](#ресурсы-и-серверные-блоки).
