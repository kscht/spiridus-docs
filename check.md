# Проверка живых блоков (`render_check interact`)

`interact` проверяет подсказки, легенды, кнопки, поля, вращение и другие действия настоящим вводом Chromium.
[Формат целого документа](markdown.md). Это не замена обычной проверке: сначала соберите весь документ, затем добавьте сценарии к нужным блокам.

## Статическая и визуальная проверка

`lint_check` разбирает синтаксис и правила исходника линтерами, без отрисовки.
Передайте `code` с `lang` либо целый `markdown`/`markdown_file`; `text: true` добавляет
проверку русского текста. Ответ содержит `clean` и `issues` с полями
`line`, `lang`, `tool`, `rule`, `text`, `hint`.

`render_check` собирает весь Markdown тем же рендером, что у читателя, в Chromium:
находит ошибки блоков, формул, картинок и консоли, наложения и обрезку подписей,
слишком широкие или мелкие рисунки. Ширины по умолчанию — 760 и 390 точек.
Вход — весь документ в `markdown` (не `document` или `text`) либо `markdown_file`.
Файл до 512 КБ можно загрузить через `files_upload` или REST `POST /api/v1/files`.

`built` означает, что блоки собраны; `clean` также учитывает проваленные шаги `interact`.
По умолчанию замечания к оформлению и тексту не меняют `clean`;
для приёмки задайте `strict: ["warning", "layout"]`, при необходимости добавьте `text` и `lint`.
`totals` содержит числа замечаний по видам и шагов сценариев, `frameConsole` — ошибки консоли
фреймов запускателя. Исправляйте `issues`, итог пользователю пересказывайте из `verdict`.
После проверки покажите Markdown целиком; `preview` в ответе — снимок для показа картинкой.

Повторная проверка: `brief: true` убирает подсказки и список файлов;
`shots: "none"` исключает снимки. Первый вызов по умолчанию показывает проблемные блоки,
`shots: "page"` — страницу. Формат сценариев — ниже.
Приватный результат читается по ключу; временная ссылка для браузера —
`GET /api/v1/private/<id>/<имя>?sign=1` с ключом.

## Сценарий

```json
{
  "markdown": "# Документ\n\n```echarts\n...\n```",
  "interact": [{
    "line": 3,
    "width": 760,
    "steps": [
      {"hover": [0.5, 0.5], "read": true},
      {"click": {"text": "Москва"}, "shot": true},
      {"key": "Enter", "after": 500}
    ]
  }]
}
```

- `line` — строка открывающего fence блока; для таблицы — строка заголовка.
- `width` — ширина окна 320–1600; без неё берётся первая из `widths`.
- `steps` — 1–40 шагов по порядку; сценариев может быть до шести.

## Точки и действия

Точка — `[x, y]` с долями рамки от 0 до 1, CSS-селектор (`"button.py-btn"`) либо
`{"text":"Москва"}` для видимой подписи на странице или внутри фрейма.

Один шаг задаёт действие: `hover`, `click`, `dblclick`, `rightclick`, `tap`,
`drag: {from, to}`, `wheel: {at, dx, dy}`, `key` с необязательными `modifiers`,
`type`, `wait`, `waitFor` с `timeout`. Дополнительно шаг может запросить `read: true`,
`clipboard: true` или `shot: true`; `after` задаёт паузу после действия в миллисекундах.

Снимок шага сообщает `changed`: отличается ли он от исходного или предыдущего снимка.
Проваленный шаг делает `clean: false`; итог пользователю пересказывайте из `verdict`.

## Отключённые проверки

`issues` может содержать `kind: "check-off"`: общая проверка неприменима к нотации,
а `text` объясняет причину из `checks.<имя>.off` её манифеста. Это пояснение не входит
в `totals`, не влияет на `built`, `clean` и `strict` и не вызывает снимков проблемных блоков.
Явно запрошенные снимки страницы (`shots: "page"`) и сценариев сохраняются.
Ошибку сборки отключить нельзя.

## Проверка статьи проекта

Для статьи проекта всегда указывайте `project` (id или slug) и `path` (путь `.md`):

```json
{"project":"my-project","path":"chapters/start.md","widths":[760,390]}
```

Без `markdown` шлюз читает сохранённую статью. Редактор, админ и владелец могут передать
`markdown` для проверки правки или `commit` для старой версии. Читатель проверяет только
сохранённый текст текущей `main`, без явного `commit`.

Относительные ссылки Markdown, определения ссылок и адреса в HTML проверяются внутри проекта.
Абсолютные пути `/p/<свой slug>/…` также проверяются как внутренние. Остальные абсолютные
пути и URL не считаются ошибкой ссылки проекта; их доступность эта проверка не проверяет.
Недоступная статья или ресурс дают `issues` с `rule: "project-link"` и делают `built` и `clean`
ложными. В отрисовке пути становятся `/p/<slug>/<путь>`. Ресурсы читает шлюз от имени
вызывающего с проверкой текущей роли, версии, указателя и индекса ресурсов; в Chromium без
сети передаются только проверенные байты нужных файлов.

Снимки, `meta.json` и результаты тяжёлых блоков сохраняются в `private:`
проекта. Ответ содержит `private`, `refs` и временные ссылки `files`. Читатель может получить
новую подпись только на снимок сохранённой статьи текущей `main`; снимок присланной правки
ему недоступен. Исключённый участник новую подпись не получит. Уже выданные ссылки работают
до своего срока, не больше 15 минут. По `private:` можно скачать результат с ключом через
`GET /api/v1/private/<id>/<имя>`; `?sign=1` выдаёт новую временную ссылку по текущим правам.
Удаление проекта и стирание удаляют производные результаты и их кеш.
`files_publish` отказывает для снимков проекта и результатов Code Mode с меткой проекта:
публикация из проекта наружу — пока запрещена.

Без `project` проверка и ссылки `/artifacts/…` остаются публичными. Не проверяйте закрытую
статью без `project`.

Как и остальные вызовы проектов, `render_check` с `project` не принимает `async=1`.
