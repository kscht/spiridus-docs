# Источники данных проекта: SQLite, JSONL и REST

Пакеты описываются декларациями `sources/<имя>/source.json`;
прежний `datasource.json` заменён. Декларация задаёт издателя, права, область,
версии, модель и грамматику цитат. Она не создаёт подключения и не утверждает
рецепты или credentials. Пакеты `sqlite`/`jsonl` описывают демонстрационную
выборку FDC, `rest` — FDC API; общий обработчик файлов поддерживает и другие
разрешённые SQLite/JSONL. Подключение и запросы используют прежний
`project_datasource` по правилам ниже.

Пилот включается оператором флагом `DATASOURCE_PILOT=1`; по умолчанию выключен.
Нужны проекты v1, хранилище ресурсов, реестр стираний и сборка песочницы
`datasource-1.0.0`. Production включается только отдельной выкладкой из main
после ревью. REST включается отдельным флагом `DATASOURCE_REST=1` и выполняется
отдельной сетевой службой; SurrealDB и Code Mode пока недоступны. Вызов доступен в пресете проектов и REST:
`POST /api/v1/tools/project_datasource`.

Источник принадлежит одному проекту. Сначала загрузите файл обычным ресурсом
через `project_write`: SQLite (`.sqlite`, `.sqlite3`, `.db`), `.jsonl`, `.jsonl.gz`
или `.jsonl.zst`. Затем подключите его по пути. SQLite должен быть самостоятельным
снимком БД без необходимого внешнего WAL. Источник читается из текущей головы;
обновление файла — явная запись проекта. Объявленные запросы и политика хранятся
служебно вне Git: правка статьи или файла не меняет утверждённый рецепт.

> Данные снимков становятся частью проекта и будут видны участникам и гостевым
> ссылкам; ответственность за персональные данные — на владельце проекта.
> Ответ запроса также получает ваш клиент и его LLM. Предупреждение возвращается
> при подключении, запросе, сохранении и создании гостевой ссылки.

## Действия и права

Общие аргументы: `project`, `datasource` — имя внутри проекта; `action`:

| Действие | Параметры | Owner/Admin по умолчанию | Editor | Reader | Гость |
|---|---|---|---|---|---|
| `connect` | `type`, `path`, `acknowledge:true` | да | нет | нет | нет |
| `credentials` | REST: write-only `credential`, `null` — отзыв; `acknowledge:true` | да | нет | нет | нет |
| `operations` | `operations:{имя: запрос}`; полная замена рецептов | да | нет | нет | нет |
| `policy` | полная матрица ниже | да | нет | нет | нет |
| `detach` | отключить будущие запросы | да | нет | нет | нет |
| `describe` | схема/язык и имена рецептов | да | да | для файлов только имена разрешённых операций; REST недоступен | нет |
| `describe` с `operation` | контракт выбранной именованной операции файлов | да | да | да | нет |
| `execute` с `operation` | имя рецепта, `params` | да | да | да, к голове сохранённого файла; REST недоступен | нет |
| `execute` с `query` | прямой SQL или JSONL-запрос | да | нет | нет | нет |
| Читать сохранённый снимок результата | обычный ресурс проекта | да | да | голова по обычным правилам | голова в вебе |

Матрица настраивает `describe`, `execute_named`, `execute_direct`,
`manage_connection`, `manage_operations`, `manage_policy`; для REST также
`manage_credentials`. Каждое значение —
массив ролей в пределах умолчаний таблицы. Матрица может только сужать доступ:
direct и управляющие действия нельзя передать editor/reader. Эта граница проверяется
и для служебных записей, сохранённых прежней версией пилота. Права независимы: доступ к
управлению подключением не даёт менять политику. Новое подключение получает
безопасные умолчания. `connect` не перезаписывает существующее подключение.
Для смены файла/типа — `detach` и новое подключение; старые снимки сохраняются.

Сужение управляющей роли применяется к следующим операциям: например, admin
с действующим `manage_policy` может оставить это право только owner, и наоборот.
Сам переход проверяется по исходной политике и текущему членству; следующий
управляющий вызов уже требует права по новой политике.

Reader по умолчанию может выполнить объявленный запрос к сохранённому файлу. Пилот фиксирует commit
текущей головы и читает неизменяемые байты локального ресурса: reader не выбирает
историю, внешний live-доступ или чужой проект. Запись снимка результата всё равно
требует проектного права editor+. Гостю запросы и схема недоступны при любой
матрице. Изменение политики/рецептов/членства, стирание или смена версии файла
отзывают незавершённый запрос; перед ответом и коммитом права проверяются повторно.

Для reader файлового источника `describe` без `operation` возвращает `limited:true`, `revision` и
`operations` — только имена разрешённых рецептов. Затем `describe` с `operation`
возвращает `operation:{id,revision,parameters,result}`. `parameters` и `result` —
JSON Schema: обязательные имена параметров, допустимые JSON-типы и форма результата.
Параметры пилота — скалярные JSON-значения без defaults/enum; более узкий тип из SQL
не угадывается. SQLite описывает строки как объекты скалярных значений без обещания
заранее известных имён колонок; JSONL указывает явные колонки select/aggregate,
а их неизвестные типы оставляет открытыми. Для SQLite имена привязок определяет сам
SQLite через `EXPLAIN`, без выполнения рецепта; JSONL проверяет декларацию без
чтения строк. SQL, условия, константы, путь файла и общая схема БД reader не выдаются.
Отключение `execute_named` скрывает список и описание операций даже при `describe`.
Ранее сохранённая политика не расширяется автоматически: владелец меняет её явно.

## Языки запросов и пределы

SQLite: один запрос SQL только на чтение, параметры — именованные значения
`:food`, без подстановки SQL-фрагментов. Допустимы SELECT и чтение таблиц/схемы;
функции ограничены `count`, `sum`, `avg`, `total`, `min`, `max`, `abs`, `round`,
`coalesce`, `nullif`, `lower`, `upper`, `length`, `substr`, `typeof`, `trim`.
ATTACH, PRAGMA пользователя, загрузка расширений, запись, DDL, файловые функции
и рекурсивные CTE отклоняются authorizer SQLite. Читаются только обычные таблицы
и представления из системного списка SQLite; виртуальные таблицы, их shadow-таблицы
и модули без объявления в схеме (`dbstat`, `sqlite_dbpage`, `pragma_*`) закрыты.
`describe` показывает только доступные обычные таблицы и представления. Дополнительно включены
`query_only`, `trusted_schema=OFF`, `immutable`, пределы SQL/выражений/числа инструкций.
Сложные запросы могут быть отклонены даже при небольшом ответе.

JSONL использует **`jsonl-filter-v1`**, декларативный JSON:

```json
{
  "where": [{"field":"fdc_id","op":"eq","value":321358}],
  "select": ["nutrient","amount","unit"],
  "limit": 1000
}
```

`where` — AND до 16 сравнений верхнеуровневых полей (`eq`, `ne`, `lt`, `le`,
`gt`, `ge`). Типы не приводятся; числовые int/float совместимы; отсутствующее
поле — null. Сравнения порядка допустимы только для чисел/строк одинакового
типа. Проекция — до 32 полей. Вместо `select` допускается до 16 агрегатов:

```json
{"aggregate":{"count":{"op":"count"},"average":{"op":"avg","field":"amount"}}}
```

`count` считает отфильтрованные строки; `sum`, `avg`, `min`, `max` пропускают
null, остальные значения должны быть числами. На пустом наборе count=0,
остальные агрегаты=null. Группировки, сортировки, регулярные выражения,
вложенные пути, скрипты и функции пользователя не входят в язык. У именованного
рецепта `value:{"param":"food"}` берёт значение из `params.food`. В прямом
JSONL-запросе значения задаются непосредственно в `where`.

Выбран этот язык вместо jq или загрузки всего JSONL в СУБД: фильтр и агрегаты
работают за один проход с ограниченной памятью, код пользователя не исполняется.
Сжатый файл остаётся сжатым до песочницы; gzip/zstd читаются потоком, без полной
распаковки в память/на диск. Это пределы пилота, а не поддержки всего архива FDC:

| Предел | Значение |
|---|---|
| Файл ресурса на входе, в том числе сжатый | 12 МиБ |
| Распакованные байты / число строк / строка JSONL | 64 МиБ / 100000 / 64 КиБ |
| Глубина JSON / целые числа | 32 / от −(2⁵³−1) до 2⁵³−1 |
| Окно Zstandard | 32 МиБ |
| Выход / число строк | 1 МиБ / 1000 |
| Память / процессор / процессы контейнера | 256 МиБ / 1 vCPU / 128 |
| Время контейнера / всего запроса | 20 с / 30 с |
| Источники / снимки на проект | 16 / 1024 |
| Общая служебная запись настроек и зависимостей снимков проекта | 512 КиБ |

Пределы нельзя поднять запросом. JSONL дочитывается до конца даже после `limit`:
повреждённый хвост, повтор ключа, NaN, превышение размера/строк или ошибка
декомпрессии отвергают весь ответ. `truncated:true` означает ограниченную
выборку: такой ответ нельзя сохранить снимком. Для полного снимка сузьте фильтр
или используйте агрегат. SQLite выдаёт не более 1000 строк и отмечает усечение.
Целые числа вне указанного диапазона отклоняются, чтобы JSON-клиент не округлял
их молча; расширенное кодирование int64/decimal/binary в пилоте не поддерживается.
Общий предел служебной записи может сработать раньше пределов числа источников
или снимков. Превышение отклоняется до замены настройки или сохранения снимка;
прежнее состояние остаётся читаемым, отключение источника и стирание доступны.

## Пример: нутриенты продукта

Пакет `data/fdc-foundation` содержит 40 строк: восемь продуктов Foundation Foods
из выпуска USDA 29.10.2026, по пять нутриентов, в SQLite и JSONL.zst.
Автор: **U.S. Department of Agriculture, Agricultural Research Service**;
лицензия **CC0-1.0**, источник — [FoodData Central](https://fdc.nal.usda.gov/).
Пакет выключен по умолчанию, как локальные пакеты вне deployment profile.
Для его раздачи добавьте `"fdc-foundation":"1.0.0"` в `data` своего профиля.
Файлы можно также загрузить из рабочей копии как ресурсы проекта.

После загрузки `data/nutrients.sqlite` в свой проект:

```json
{"project":"nutrition","datasource":"fdc","action":"connect","type":"sqlite","path":"data/nutrients.sqlite","acknowledge":true}
```

Администратор утверждает рецепт:

```json
{"project":"nutrition","datasource":"fdc","action":"operations","operations":{"nutrients":"SELECT nutrient, amount, unit FROM nutrients WHERE fdc_id=:food ORDER BY nutrient_id"}}
```

Редактор вызывает:

```json
{"project":"nutrition","datasource":"fdc","action":"execute","operation":"nutrients","params":{"food":321358}}
```

Хумус, промышленного производства (FDC 321358), количество на **100 г**:

| Нутриент | Количество | Единица |
|---|---:|---|
| Белок | 7,35 | г |
| Жиры | 17,1 | г |
| Углеводы по разности | 14,9 | г |
| Кальций | 41 | мг |
| Натрий | 438 | мг |

Это демонстрационная выборка, не полный состав и не рекомендация по питанию.
Для JSONL подключите `data/nutrients.jsonl.zst` с `type:"jsonl"`, утвердите
приведённый выше фильтр/проекцию; вместо 321358 можно объявить параметр `food`.

Чтобы сохранить результат, передайте в `execute` также
`"snapshot":"snapshots/hummus.json"`, `"base":"<commit из project_read>"`,
`"acknowledge":true`. Создаются два новых обычных ресурса одним коммитом:
данные и `.meta.json` (источник, хеши, сборка, дата, полнота). SQL/параметры в
метаданные не записываются. Старый снимок не перезаписывается. В статье можно
использовать полученную таблицу, явно указав дату данных; чтение статьи запрос
не запускает. Новый запрос и обновление статьи — отдельные явные действия.

## Изоляция, журнал и стирание

Драйвер работает в изолированной песочнице без сети, с read-only корнем, непривилегированным
пользователем, временными входом/выходом и фиксированным образом. В журнале
шлюза остаются действие, id проекта, коды, время, размеры; запросы, параметры,
строки, пути, `task` и сырой stderr туда не попадают. Кеш запросов и постоянные
CAS-копии пилот не создаёт. Содержимое ответов считается недоверенными данными.

Стирание пути источника через `project_admin` с `action:"erase"` расширяется
на зависимые снимки и их метаданные до записи в реестр 0049. Переписывается
история, освобождаются блобы, чистятся служебные рецепты; поздний worker не может
сохранить ответ. При стирании любого пути настройки источников проекта
сбрасываются; оставшиеся снимки и зависимости сохраняются. Удаление одной версии
источника с зависимыми снимками отклоняется: используйте стирание пути с историей.
Обычное удаление файла/отключение источника сохраняет историю и снимки.
Подтверждённый отказ сохранения снимает регистрацию зависимости этой попытки.
При потере ответа исход сверяется с историей и ожидаемыми хешами снимка и
метаданных: независимый файл на повторно использованном пути не становится
производным. Если исход ещё неизвестен и голова не сменилась с исходного `base`,
стирание отклоняется с 409; повторите после подтверждения записи либо после
обычной правки проекта, закрывающей возможность поздней записи со старым `base`.
Ошибка чтения истории не считается доказательством отсутствия снимка.
Перемещение подключённого источника, сохранённого снимка, его метаданных или
содержащего их каталога отклоняется (409): пилот сохраняет исходные пути для
стирания с историей. При наличии снимков запрет действует и после отключения
источника или флага пилота. Остальные файлы проекта перемещаются обычным способом.

При восстановлении применяется реестр до открытия шлюза. Срок ухода старых
резервных копий задаёт оператор; уже скачанные клиентом байты вернуть нельзя.
Для self-hosted оператор отвечает за обработку данных установки, владелец
проекта — за состав источников/снимков и выдачу доступа. Самостоятельные копии
через обычные операции ресурсов живут по правилам своих проектов; пилот не
обещает отозвать разрешённые копии у других владельцев.


## Внешние REST-источники

Нужны оба флага `DATASOURCE_PILOT=1` и `DATASOURCE_REST=1`, утверждённые оператором
endpoint и отдельная служба. Endpoint — имя из allowlist установки, без URL,
прокси или произвольного хоста в аргументах проекта. Для нашего экземпляра
оператор регистрирует `serviceRef` за одним project; ввод внутреннего IP участником
не разрешён. Настройка хоста/порта/API prefix и способ передачи ключа (`header`
либо `query`, например `api_key`) находятся у оператора.

```json
{"project":"nutrition","datasource":"fdc","action":"connect","type":"rest","endpoint":"fdc","acknowledge":true}
```

Администратор передаёт тестовый ключ через отдельный `credentials` вызов:
`credential` — строка, `acknowledge:true`. Ключ используется **от имени проекта**
всеми участниками, которым разрешён execute_named; чтения ключа нет ни у одной
роли. Не помещайте ключ в статью, параметры запроса, URL, пример с реальными
значениями или журнал клиента. `credential:null` отзывает ключ в Spiridus;
у поставщика его отзывает владелец. `manage_credentials` независимо от
`manage_connection`.

REST доступен owner/admin/editor в пределах матрицы, reader и гостю live-запрос
недоступен. `execute_direct` у REST всегда пуст; политика не может расширить
эту границу, включая ранее сохранённые записи. Reader читает сохранённый
JSONL.zst обычными средствами проекта.

Запросы только именованные. Администратор утверждает `operations` с объектами:

```json
{
  "details": {
    "method":"GET",
    "path":"/food/{fdcId}",
    "parameters":{"fdcId":{"type":"integer","in":"path","required":true,"minimum":1}}
  },
  "search": {
    "method":"GET",
    "path":"/foods/search",
    "parameters":{
      "query":{"type":"string","in":"query","required":true,"maxLength":256},
      "pageSize":{"type":"integer","in":"query","default":2,"enum":[2]},
      "dataType":{"type":"string","in":"query","default":"Foundation","enum":["Foundation"]}
    },
    "rows":"foods",
    "pagination":{"parameter":"pageNumber","start":1,"totalPages":"totalPages","pageSize":2}
  }
}
```

Это значение поля `operations`, а не весь вызов. `parameters` допускает типы string/integer/number/boolean, `required`, `default`,
`minimum`, `maximum`, `maxLength`, `enum`, размещение `in:path|query|body`.
Необязательный параметр с default остаётся необязательным. Лишние параметры,
подмена `api_key`, URL/`..`/разделители пути и неизвестные placeholders отклоняются.
`GET` передаёт query, `POST` — объявленные body и query; POST разрешать только
для проверенных методов чтения API. Произвольного forward или свободного REST
нет, даже у admin. `rows` выбирает массив верхнего уровня; без него весь объект
становится одной строкой, либо принимается массив объектов.

`pagination` задаёт численный параметр страницы, начало 0 или 1, размер страницы
и необязательное поле `totalPages`. Без totalPages конец — страница короче
pageSize; `next` URL и cursor не исполняются. Параметр страницы формирует служба,
клиент его не подменяет. При достижении maxPages/maxRows ответ помечается
`truncated:true`; его нельзя сохранить снимком. Страницы FDC не образуют согласованный снимок меняющегося каталога.

Редактор выполняет рецепт:

```json
{"project":"nutrition","datasource":"fdc","action":"execute","operation":"details","params":{"fdcId":321358}}
```

Для сохранения полного ответа добавить `snapshot:"snapshots/food.jsonl.zst"`,
`base` текущей головы и `acknowledge:true`. Создаются обычные JSONL.zst и
`.meta.json` одним коммитом; старый путь не перезаписывается. Метаданные: имя
источника, версия настройки/API и драйвера, хеш строк/сжатых байтов, автор/лицензия
при регистрации оператором, время первоначального получения, полнота и
`consistency:"best-effort"`. Ключ, endpoint, параметры и строки в метаданные не
попадают. API FDC не даёт согласованной версии живого каталога; дата cache hit
не становится датой нового получения. Чтение статьи/снимка не запускает сеть.

Пределы REST: 10 внешних запросов/мин одновременно на project и endpoint,
1 МиБ ответов, 20 с, 5 страниц, 1000 строк, не более 4 активных query на службу.
Каждая страница расходует запрос. При connect поле `limits` может уменьшить
`requestsPerMinute`, `maxBytes`, `timeoutMs`, `maxPages`, `maxRows`, `cacheSeconds`;
оператор может установить более строгие пределы. Кеш до 60 с/256 записей/32 МиБ
на службу, с ключом по проекту, версии рецепта/подключения/endpoint/драйвера,
поколению credential, параметрам и пределам; права проверяются заново. 429 и
сетевые ошибки не повторяются автоматически. USDA по умолчанию ограничивает
1000 запросов/час/IP, DEMO_KEY — 30/час и 50/день/IP; наши минутные пределы не
заменяют квоту поставщика. Массовый анализ Foundation/SR/FNDDS удобнее делать
через выгрузку → JSONL.zst; REST полезен для поиска, деталей и свежих Branded.
Experimental не обещается как фильтр общего API. Автор FDC — U.S. Department
of Agriculture, Agricultural Research Service, лицензия CC0-1.0; первичные
основания — [API Guide USDA](https://fdc.nal.usda.gov/api-guide/).

Стирание пути снимка включает его метаданные и историю. Стирание любого пути
проекта также очищает credentials/кеш REST и служебные рецепты проекта;
независимые готовые снимки сохраняются по правилам 0049. Отзыв/ротация ключа и
изменение прав/настройки отменяют поздний ответ; обычный detach сохраняет снимки.
Установка, защита сети и восстановление описаны в README хостинга.
