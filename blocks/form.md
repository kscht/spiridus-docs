# `form` — анкеты, проверочные вопросы и учебные задания

Тело блока — YAML в профиле GitHub Issue Forms: `name`, `description`, `body`.
Поддерживаются `input`, `textarea`, `dropdown` (включая `multiple` и индекс `default`),
`checkboxes`, поясняющий `markdown`, `validations.required` и `options[].required`.
У поля ввода нужен уникальный `id`. У `markdown` — только `attributes.value`.

````markdown
<!-- spiridus: {"id":"question"} -->
```form
name: Проверяем понимание
description: Выберите источник состояния задачи
body:
  - type: dropdown
    id: source
    attributes:
      label: Где хранится завершённость?
      options: [В отметке GFM, В status статьи, В записи доски]
    validations:
      required: true
```
````

Служебный id относится к статье: пометка должна непосредственно предшествовать блоку;
дубликат запрещает отправку. Атрибутов ограждения нет. Теги, anchors/aliases, merge,
дубликаты YAML-ключей, неизвестные ключи и неподдерживаемые возможности запрещают отправку.
Поля назначения issue (`labels`, `assignees` и другие) не выполняются. Пределы:
32 КиБ схемы, 64 поля, 64 варианта на поле, 64 КиБ ответа, 16 КиБ текста поля.
Текст документа не исполняется; HTML очищает общий Markdown-конвейер.

На приватной странице проекта зарегистрированный reader+ сохраняет свой ответ или черновик.
**Текущие и будущие editor/admin/owner видят все ответы проекта**, читатель — только свои.
До отправки интерфейс показывает это предупреждение и срок хранения.
Ответы не записываются в статью, историю git, поиск, ресурсы или журнал вызовов.

По умолчанию экземпляр — анкета: «Сохранить ответ» меняет один текущий ответ.
Преподаватель в «Управлении заданием» отдельно задаёт режим `exercise` и закрытые правила
для каждого поля. Конфигурация передаётся отдельной операцией, не в YAML формы:

```json
{"mode":"exercise","rules":{"source":{"kind":"exact","expected":"В отметке GFM"}}}
```

`exact` сравнивает строку/выбор/массив boolean; набор `dropdown multiple` сравнивается без порядка.
`normalized` применим к тексту: NFKC, удаление крайних пробелов, свёртка пробельных последовательностей
и сравнение без учёта регистра. `manual` не содержит `expected`, объяснение ждёт преподавателя.
Эталон хранится отдельно от ответов и не возвращается при чтении. Произвольные проверяющие
программы и LLM не поддерживаются. Без настроенной проверки успешного вердикта нет.

«Проверить попытку» сдаёт неизменяемый снимок схемы и ответа. Повтор — новая попытка;
сетевой повтор с тем же `requestId` не расходует лимит. Черновик редактируется до сдачи.
Вердикты: «Верно», «Неверно», «Ожидает преподавателя», «Проверка не выполнена».
Ручной вердикт дописывается; прежние ответы не меняются. Новая схема/настройка — новая ревизия,
старые результаты не пересчитываются. Итог — последняя завершённая попытка текущей ревизии.

Editor+ доступны сводка, ручная проверка и CSV; формулы CSV нейтрализованы.
Скачанный CSV сервер не отзывает. Свои данные во всех формах можно стереть досрочно;
после исключения из проекта доступен отдельный канал личного стирания
`POST /api/v1/form/erase-mine` с пустым JSON и cookie вошедшего пользователя на том же сайте.
Весь экземпляр с эталонами стирает owner. Перемещение сохраняет экземпляр; копия получает новый,
без ответов и эталона. Hide/удаление блока закрывают доступ; после восстановления нужно явное открытие.

Возможность имеет статус `next`; серверный флаг `FORM_ANSWERS=1` **выключен по умолчанию**.
Включение требует внешнего реестра стираний и утверждения владельцем сроков и пределов установки.
Вне приватного проекта, у гостя, на публичном сайте, в печати и `render_check` доступны только
вопросы и локальное заполнение полей; отправка, проверка и чтение настоящих ответов отсутствуют.

Для проверки интерактива `render_check` передайте `interact` с номером строки ограждения:
`click` по тексту варианта checkbox, `key` для навигации dropdown, `type` в textarea,
затем `read` и `shot`. Пример: `{"interact":[{"line":2,"steps":[{"click":"select"},{"key":"ArrowDown"},{"key":"Enter"},{"read":true},{"shot":true}]}]}`.
