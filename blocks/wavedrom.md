# `wavedrom` — временны́е диаграммы, регистры, логические схемы

[WaveDrom](https://wavedrom.com/) 3: описание в WaveJSON (JSON5: ключи без кавычек, одинарные
кавычки, комментарии). Три вида — по ключу верхнего уровня:

- `signal` — временна́я диаграмма: такты, уровни, шины с данными, группы, стрелки между событиями;
- `reg` — поля регистра по битам;
- `assign` — логическая схема по выражению.

```wavedrom
{signal: [
  {name: "clk",   wave: "p......"},
  {name: "valid", wave: "01...0."},
  {name: "data",  wave: "x345.x.", data: ["D0", "D1", "D2"]},
  {name: "ready", wave: "1..01.."}
]}
```

## Временна́я диаграмма: `signal`

Каждый знак строки `wave` — один такт (период). Знаки:

| Знак | Что |
|---|---|
| `0` `1` | низкий и высокий уровень |
| `.` | то же, что в прошлом такте |
| `x` | не определено (штриховка) |
| `z` | высокий импеданс (третье состояние) |
| `=` `2`…`9` | значение шины — подпись из `data` по порядку; цифры — цвет |
| `p` `n` | такт: начинается фронтом / спадом; `P` `N` — со стрелкой на фронте |
| `h` `l` | высокий и низкий с резким фронтом (для тактов, `hl` — импульс) |
| `u` `d` | подтяжка вверх и вниз |
| `\|` | разрыв (пропуск тактов) |

- **Длины строк** всех сигналов должны совпадать: иначе события не стоят друг под другом. Удобно
  писать по два знака на бит, когда данные меняются по спаду, а читаются по фронту.
- **Группы** — вложенный список с именем первым: `["Ведущий", {name: "SCLK", …}, {name: "MOSI", …}]`.
- **Пустая строка** между сигналами — `{}`.
- **Стрелки между событиями**: у сигнала `node: ".a...b"` (метки под тактами), у диаграммы
  `edge: ["a~>b задержка", "a-|->b"]` (`~` — кривая, `-` — прямая, `-|` — с изломом).
- **Масштаб**: `config: {hscale: 2}` — такт вдвое шире; `head: {text: "Заголовок", tick: 0}` —
  заголовок и номера тактов сверху; `foot: {text: "…"}` — подпись снизу.
- **Сдвиг**: `period: 2` у сигнала — такт вдвое длиннее, `phase: 0.5` — сдвиг на полтакта влево.

## Поля регистра: `reg`

Поля — от младшего бита к старшему. У поля `bits` (ширина), `name`, `attr` (подпись под полем:
`"RW"`, `"RO"`, `"W1C"` или список строк), `type` (цвет: 2–7). Поле без `name` — резерв.

```wavedrom
{reg: [
  {bits: 1, name: "EN", attr: "RW"},
  {bits: 2, name: "MODE", attr: "RW"},
  {bits: 5},
  {bits: 8, name: "DIV", attr: "RW", type: 4}
], config: {bits: 16}}
```

`config`: `bits` — ширина регистра (по умолчанию сумма полей), `lanes` — сколько строк (32 бита в
две строки по 16 — `lanes: 2`), `hspace` — ширина в точках, `fontsize`.

## Логическая схема: `assign`

Выражение — вложенными списками: операция первой. Операции: `&`, `|`, `^`, `~` (не), `~&`, `~|`,
`~^`, `=` (буфер). Слева — имя выхода.

```wavedrom
{assign: [["y", ["|", ["&", "a", ["~", "s"]], ["&", "b", "s"]]]]}
```

## Что учесть

- Подписи по-русски можно; длинные имена сигналов сдвигают всю диаграмму вправо — лучше короче
  (`CS#`, `SCLK`), а пояснение — в тексте или `head`.
- Колонка документа — 760 точек: у диаграммы с `hscale: 1` это ~35 тактов. Длиннее — `|`
  (разрыв), несколько диаграмм или `hscale` меньше 1 нельзя — лучше разбить.
- Тема — `config: {skin: "narrow"}` (узкие такты), `"lowkey"`, `"dark"`.
- Рисунок — картинкой; кнопка «⤢» открывает её крупно. Код в исходнике не выполняется: функции и
  вычисления — ошибка разбора.
- Не больше 64 КБ.

## Как чинить замечания `render_check`

- `label-overlap` у значений шины — подписи в `data` короче (`A0` вместо `адрес 0`) или `config: {hscale: 2}`.
- `label-crossed` у подписей стрелок `edge` — другие метки `node`, чтобы стрелка шла мимо надписей, или подпись короче.
- `too-wide` — меньше тактов в одной диаграмме (разрыв `|`), без `hscale`; регистр — `lanes: 2`.
