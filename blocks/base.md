# Представления статей и задач (`base`)

Профиль [Obsidian Bases](https://help.obsidian.md/bases/syntax): строка — статья проекта,
задачи — её принятые GFM-пункты `- [ ]` и `- [x]`. Редакторский `status` из YAML-шапки
не завершает задачу. Таблица, канбан и дорожная карта доступны только для чтения.

Нотация имеет статус `next`, по умолчанию выключена. Для проектных данных также нужен
флаг установки `PROJECTS_PROPERTIES=1`. Вне проекта, на публичном сайте и у гостя —
заглушка с названиями представлений.

## Свойства статьи

```markdown
---
status: review
assignee: null
labels: [план]
start: 2026-11-05
due: 2026-11-09
estimate: 3
---
# Подготовить документ
- [ ] Подготовить документ
  - [x] Согласовать структуру
  - [ ] Проверить примеры
```

`parent: ../общая.md` связывает единственный корневой пункт с родительской статьёй;
`blocked_by: [проверка.md]` задаёт блокирующие статьи с единственным корнем.
Пути относительны статье, без `[[…]]`, внутри проекта. Штатное перемещение статьи,
папки или источника ссылки переписывает эти значения вместе с текстом; остальные байты
и комментарии YAML сохраняются. Aliases, anchors, merge, теги и дубликаты не поддерживаются.
Неизвестные поля остаются свойствами, не становятся ссылками.

## Профиль представления

```base
filters:
  and:
    - 'file.inFolder("tasks")'
    - 'note.labels.contains("план")'
properties:
  note.status:
    displayName: Этап подготовки
views:
  - type: table
    name: Таблица
    order: [file.name, note.status, note.start, note.due, note.estimate]
    summaries:
      note.estimate: Sum
  - type: kanban
    name: Доска
    groupBy:
      property: note.status
      direction: ASC
    order: [file.name, note.due]
  - type: table
    name: Сроки
    order: [file.name, note.start, note.due]
```

`filters` блока и вида соединяются через AND. Выражения: `== != < <= > >=`,
`&& || !`, скобки, строки в двойных кавычках, числа, `true/false/null`,
`note.<поле>`, `file.path/name/ext`, `file.inFolder("tasks")`,
`note.labels.contains("план")`. Группы фильтров — `and`, `or`, `not` со списком условий.
Неизвестная функция, ключ или неверный фильтр даёт ошибку, не расширяет выборку.
`formulas`, `this`, JS и DQL не поддерживаются.

`order` задаёт колонки. `properties.<свойство>.displayName` меняет подпись.
`groupBy.property` и `direction: ASC/DESC` задают группы; канбан требует свойство статьи.
`groupOrder` задаёт порядок и скрывает неуказанные группы. `summaries` поддерживает
`Sum` для чисел и `Filled` для непустых значений. `limit: 1…1000` ограничивает показ строк,
не суммы, число совпавших статей и прогресс. По умолчанию — 1000 строк; усечение обозначено.

Дорожная карта включается кнопкой над любым видом. Нужны реальные `start` и `due`
в формате `YYYY-MM-DD`, `start ≤ due`; остальные статьи остаются в разделе «Без дат».
Сортировка выбирается рядом с видом. Настройки живут до закрытия страницы,
не сериализуются в YAML; `type: roadmap`, `sort` и сохранённой раскладки нет.
Клавиатура: Tab к спискам и кнопкам, стрелки выбирают пункт, Enter/Space нажимают кнопку.

На карточке видны исходные отметки, прогресс конечных потомков и блокировки.
Вложенные сводные узлы не удваивают знаменатель. Checked-родитель с открытыми детьми
получает предупреждение; отметка родителя сама не меняется. При нескольких корнях виден
список и предупреждение. Пустая статья — «Нет задач», а не выполненная задача.
Фильтр работает по свойствам статьи; вычисленного `note.completed` нет.

Права применяются до графа, затем считаются прогресс и блокировки, затем фильтр,
группы/суммы и ограничение показа. Доступный потомок или блокер вне фильтра продолжает
участвовать в расчёте. Недоступная цель — «Связь недоступна», без её имени и оценки.
Неполный индекс, ошибка запроса и пустая выборка различаются.

## MCP и проверка

`render_block_docs` с `lang: "base"` возвращает эту справку, если нотация включена профилем.
`project_read` с `op: "properties"` при флаге установки читает согласованный разрешённый
снимок свойств и GFM-прогресса головы main (editor+ может указать `version`). `project_write` и обычные отметки меняют исходник;
следующее чтение обновляет индекс. Записи и перетаскивания с доски нет.

`render_check` с теми же `project` и `path` получает закреплённый снимок, включая свойства
всего разрешённого проекта, без живых запросов из Chromium. Смена головы,
стирание или отзыв доступа закрывает прежний результат. Печать использует тот же снимок.
Публичный сайт показывает заглушку, пока нет учёта опубликованных зависимостей представления.

Пределы: 5000 статей, 512 КиБ на статью, 32 МиБ исходников, 32 КиБ YAML/64 свойства,
100000 узлов/ссылок, 8 видов, 64 условия, 16 колонок; превышение — явный отказ.
