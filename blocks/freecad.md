# `freecad` — модель FreeCAD с параметрами

3D-модель из FreeCAD и таблица её параметров. Читатель меняет значения в полях под моделью и
нажимает «↻ пересчитать»: песочница открывает тот же документ FreeCAD, вписывает значения и
выгружает новую модель. Блок целиком даёт `cad_run`, если модель построена от таблицы параметров
(`block` в ответе):

```freecad
model: artifact:37824fa8d7b7f745/model.FCStd
result: artifact:37824fa8d7b7f745/model.stl
build: freecad-1.1.4-timashkovy
| Параметр | Значение | Что это |
|---|---|---|
| length | 120 mm | длина пластины |
| width | 60 mm | ширина |
| thick | =length / 20 | толщина (формула) |
| hole | 8 mm | радиус отверстия |
```

- `model:` — документ FreeCAD (`artifact:<id>/model.FCStd` из `cad_run`): из него пересчитывается
  модель. Остаётся тем же и после пересчёта — меняются значения в таблице.
- `result:` — модель для показа (`artifact:<id>/model.stl`); после пересчёта — новая строка.
- Таблица — параметры: имя (алиас ячейки в таблице FreeCAD), значение как в ячейке (число, можно с
  единицей: `120 mm`, `30 °`; или формула `=length / 20`), пояснение. Первая строка — шапка.
- `section`, `cut`, `hatch` — сечения и вырез, как у [`stl`](stl.md). Положение плоскости можно
  задать от параметров таблицы: `section А-А: x = length / 2` — сечение посередине при любой
  длине; `cut: z < thick / 2 slider` — вырез, который читатель двигает ползунком. Вырез из двух
  плоскостей: `cut: x < length / 2 & y < width / 2`.
- В строке забора — как у `stl`: ` ```freecad touch=views gyro=on ` (сенсорный экран), `build=`.

Модель показывается, как у `stl`: вращается, «⤢» — на весь экран, кнопки скачать FCStd, STEP и
сценарий. Под ней — поля параметров; изменённое поле подсвечено, Enter — пересчитать. Модель
посчитана с другими значениями, чем в таблице, — блок скажет, какими.

**Пересчёт без входа.** Пересчитать с другими параметрами может любой читатель, без ключа: это
пересчёт уже готового документа FreeCAD с сервера, а не свой код. Готовое из кеша — сразу. В
редакторе новые значения и строка `result:` попадают в текст документа; на странице документа —
показываются, документ не меняется.

**Сценарий `cad_run`** — FreeCAD 1.1.4 на Python в песочнице без сети (1 ГБ, 120 с). Сценарий создаёт
документ (`App.newDocument`) и объекты в нём; выгружаются тела верхнего уровня — объекты с формой, которые
не входят в другие.
- Модель будут править в FreeCAD — стройте параметрическими объектами (`doc.addObject("Part::Box", …)`,
  `Part::Cut`, эскизы, PartDesign): в FCStd останется дерево с размерами. `Part.makeBox` + `Part.show` и
  `obj.Shape = …` дают замороженную форму без параметров.
- Булевы операции с B-сплайнами (лофт, протягивание) часто ломаются молча — объединяйте и вычитайте с
  допуском: `a.fuse(b, 0.01)`, `a.cut(b, 0.01)`.
- Габариты в своих `print` — `s.optimalBoundingBox()`, а не `s.BoundBox`: тот у B-сплайнов шире формы.
- Ответ: по каждому телу объём, площадь, точные габариты (`bbox`), `valid`; `warnings` — объём с минусом
  (тело вывернуто), невалидная форма, незамкнутая сетка, сетка больше 60 000 треугольников, ссылка на ячейку
  по адресу; `output` — что напечатал `print` (последние 4000 знаков); ссылки на `model.stl`, `model.step`,
  `model.FCStd` (в нём и сам сценарий — текстовый объект `script.py`) и `script.py`; `block` — готовый
  ```` ```stl ````, а у модели от таблицы параметров — ```` ```freecad ```` и `params` (имя, значение,
  пояснение из ячейки слева); пересчёт с другими значениями — `cad_recompute`.

**Как сделать модель с параметрами** (сценарий `cad_run`): таблица `Spreadsheet::Sheet`, у каждой
ячейки-параметра — **псевдоним** (`setAlias`), размеры — формулами от псевдонимов. Пояснение — в
ячейке слева от значения.

- Параметр — только ячейка с псевдонимом. Его имя в блоке и при пересчёте — псевдоним, адрес ячейки
  (`B1`) нигде не записывается: строки таблицы можно переставлять, параметры останутся теми же.
  Ячейка без псевдонима параметром не считается и в таблицу блока не попадает.
- Есть таблица с именем `Params` (или «Параметры») — параметры читателя берутся **только из неё**;
  промежуточные формулы с псевдонимами держите в другой таблице (`Calc`): формулы модели на них
  ссылаются, а в блок они не попадают и полем не меняются. Таблицы `Params` нет — параметры из всех.
- Параметр-текст (надпись, имя исполнения) меняется полем как текст. Числовой — только числом
  (можно с единицей): «abc» вместо 120 mm — ошибка.
- В формулах — только псевдоним: `Params.length`, а не `Params.B1`. Ссылку по адресу `cad_run`
  отметит в `warnings`: такой размер не пересчитать полем.

```python
import FreeCAD as App
doc = App.newDocument("Plate")
p = doc.addObject("Spreadsheet::Sheet", "Params")
p.set("A1", "длина пластины"); p.set("B1", "120 mm"); p.setAlias("B1", "length")
p.set("A2", "радиус отверстия"); p.set("B2", "8 mm"); p.setAlias("B2", "hole")
b = doc.addObject("Part::Box", "Plate")
b.setExpression("Length", "Params.length"); b.Width = 60; b.Height = 6
c = doc.addObject("Part::Cylinder", "Hole")
c.setExpression("Radius", "Params.hole"); c.Height = 10; c.Placement.Base.z = -2
c.setExpression(".Placement.Base.x", "Params.length / 2"); c.Placement.Base.y = 30
cut = doc.addObject("Part::Cut", "Result"); cut.Base = b; cut.Tool = c
doc.recompute()
```

**Надписи на детали** — гравировка, выпуклый текст, таблички, — `Draft.make_shapestring` и выдавливание.
Шрифты с кириллицей есть в песочнице: `font("имя", bold=False, italic=False)` даёт путь к файлу, `fonts()` —
список. Чертёжный ГОСТ 2.304 — свой шрифт Spiridus `"Timashkovy GOST Type B"` и `"Timashkovy GOST Type A"`,
прямой и наклонный (75° к строке): `font("Timashkovy GOST Type B", italic=True)` — сверен с чертежами стандарта
(в допуске ±0,5 мм); есть и `"GOST 2.304 Type A"`, `"GOST 2.304 Type B"` (OpenGOST, OFL-1.1, наклонный — производная
от него; прямой и под исходным именем `"OpenGost Type A TT"`). Ещё PT Sans,
PT Serif, PT Mono, Liberation Sans/Serif/Mono, DejaVu, Noto Sans/Serif, Linux Libertine и Biolinum, CMU,
FreeSans/FreeSerif, JetBrains Mono, Ubuntu, osifont. Шрифта нет — ошибка со списком.
`Size` у `make_shapestring` — высота прописной буквы в мм (замерено), а не кегль: размер шрифта по ГОСТ
2.304 (2,5; 3,5; 5; 7; 10; 14 мм) пишется как есть — `Size=5` даёт прописную 5 мм у любого шрифта.
Чертёжный шрифт (`GOST…` в имени) с размером не из ряда `render_check` отмечает (`gost-size`, линтер
`spiridus`); 1,8 мм — «допускается, но не рекомендуется».

```python
import FreeCAD as App, Draft
doc = App.newDocument("Sign")
plate = doc.addObject("Part::Box", "Plate"); plate.Length = 120; plate.Width = 30; plate.Height = 3
ss = Draft.make_shapestring(String="Шухов ГОСТ 2.304", FontFile=font("OpenGost Type A TT"), Size=7)
ss.Placement.Base = App.Vector(4, 4, 3)
doc.recompute()
ex = doc.addObject("Part::Extrusion", "Text"); ex.Base = ss; ex.Dir = App.Vector(0, 0, 1.2); ex.Solid = True
fu = doc.addObject("Part::MultiFuse", "Sign"); fu.Shapes = [plate, ex]
doc.recompute()
```

Гравировка вглубь — `Part::Cut` вместо `MultiFuse`. Размер и текст можно вынести в таблицу параметров:
`ss.setExpression("Size", "Params.text_h")`, текст — `ss.setExpression("String", "Params.label")`.

Пересчитать без документа — MCP-инструмент `cad_recompute`: `model` — ссылка на FCStd, `params` —
новые значения (`{"length": "200 mm"}`). Ошибка называет параметр: такого нет, не число, с такими
значениями модель не строится.

**Перебор вариантов** (сценарий `cad_run`) — циклом в одном сценарии: варианты считаются формами `Part`
без документа, в документ — только выбранный, сводка — одной строкой `print`. Пример —
`render_block_docs code`, раздел «Цепочки и циклы в песочнице».


## Пошаговый сеанс

`cad_session_open {}` создаёт пустой документ в долгом ядре FreeCAD. Необязательный `build`
выбирает сборку; `model` принимает FCStd из artifact/upload до 190 КиБ: исходная модель включается
в сценарий. Для больших FCStd используйте `cad_recompute`.

- `cad_exec {session, code}` исполняет Python в том же интерпретаторе; `App`, `FreeCAD`, `font()` и
  `fonts()` уже доступны. После шага документ пересчитывается. Сумма сценариев — до 256 КиБ.
- `cad_inspect {session}` возвращает дерево объектов, свойства, объём, площадь, габариты и valid.
- `cad_view {session, view: "top"|"front"|"right"}` сохраняет SVG с проекцией рёбер текущей модели.
- `cad_session_save {session}` выгружает STL, STEP, FCStd, `script.py` и готовый блок. Сценарий можно
  передать обычному `cad_run`; новый документ в нём создаётся автоматически. Сам сеанс он кладёт в ваши
  приватные файлы: `ref` — пакет `upload:<id>/session.json` (виден только вам).
- `cad_session_open {from: "upload:<id>/session.json"}` позже открывает **новый** сеанс из этого пакета:
  тот же документ и переменные, можно продолжать `cad_exec`.
- `session_close {session}` сохраняет состояние и освобождает контейнер; после него сеанс поднимается
  только из пакета. `session_list` показывает свои сеансы. Общий `session_call` тоже принимает шаг `code`
  или `action: "objects"`.

Пакет — документ FCStd с простыми переменными (точка сохранения), шаги сеанса и свои файлы `/out`;
выгрузки экспорта и вида (`model.*`, `meta.json`, `view.svg`) в него не входят — их пересоздаст
`cad_session_save`. Если переменные сложнее простых или точка не уместилась (файл больше 32 МиБ, в ответе
`warning`), при открытии шаги проигрываются заново. Сборку
пакет помнит: если она заменена, устарела или пересобрана, открытие отказывает, а
`session_open {from, rebuild: true}` проигрывает шаги на основной сборке («результаты могут отличаться»).
Если пакет не сохранился (больше предела загрузки, кончилось место, у ключа нет права `files`),
модель всё равно выгружена, а в ответе `warning`.

Точка сохранения — FCStd и JSON с простыми переменными, ссылками на объекты документа и модули.
Если Python-переменные сложнее этого или открыто несколько документов, восстановление использует
полный журнал успешных команд. Произвольные объекты Python через pickle не загружаются.
Необработанная ошибка шага останавливает ядро; следующий шаг восстанавливает предыдущее успешное
состояние. Пределы сеансов — в справке `render_block_docs code`.


## Рекомендованные диапазоны и ползунки

В `cad_run` и `cad_exec` доступен помощник `param`: он создаёт именованную ячейку
в `Params`. Диапазон хранится в свойстве таблицы `SpiridusRanges` (JSON), входит
в `meta.params[].min/max/step` и сохраняется в FCStd при скачивании и `cad_recompute`.
Значение параметра ссылается на ячейку обычным выражением `Params.height`.

```python
import FreeCAD as App
doc = App.newDocument("Vase")
param("height", "180 mm", min=120, max=260, step=5, note="высота вазы")
param("radius", "40 mm", min=30, max=60, step=2, note="радиус")
param("wall", "1.6 mm", min=1.2, max=2.4, step=0.4, note="толщина стенки")
# Далее — параметрические объекты с setExpression(..., "Params.height").
```

Задавайте геометрически осмысленные границы: модель должна строиться на всём
диапазоне. Для печати выбирайте диапазоны без свесов больше 45° и стенок тоньше
сопла. Шаг должен давать заметное, полезное изменение: например, 5 мм для высоты,
1 для числа граней, 0.4 мм для стенки при сопле 0.4 мм.
Перед публикацией вызовите `cad_recompute` на минимуме и максимуме каждого
параметра; для связанных размеров проверьте также крайние сочетания. Проверяйте
`valid`, габариты, предупреждения и вид модели. Рекомендация не гарантирует
печатаемость при произвольном сочетании параметров.

Готовый `freecadBlock` добавляет диапазоны в таблицу и включает `sliders`, когда
они есть. В написанном вручную блоке ползунки включаются флагом `sliders` или
`sliders=on`; `sliders=off` отключает их. Без атрибута остаются обычные поля.

````markdown
```freecad sliders
model: artifact:0123456789abcdef/model.FCStd
result: artifact:0123456789abcdef/model.stl
| Параметр | Значение | мин | макс | шаг | Что это |
|---|---|---|---|---|---|
| height | 180 mm | 120 mm | 260 mm | 5 mm | высота вазы |
| sides | 6 | 3 | 8 | 1 | число граней |
| twist | 120 deg | -180 | 180 | 15 | закрутка |
| wall | 1.6 mm | 1.2 mm | 2.4 mm | 0.4 mm | толщина стенки |
```
````

`min/max/step` — английские синонимы колонок `мин/макс/шаг`. Числа могут быть с
единицей (`20 mm`), запятой (`1,2`) и простой дробью (`1/16 in`). Единица диапазона —
у границ, без неё — единица значения. `param()` запоминает единицу значения, и
готовый блок пишет её в границы (`20 mm`): после пересчёта со значением `4 cm`
диапазон остаётся в миллиметрах. В поле можно вводить другую единицу той же величины
(мм, см, м, дюймы; градусы и радианы) — сравнение с диапазоном и шаги идут в единице
диапазона, а ползунок и стрелки пишут значение в ней: `4 cm` → ▶ → `45 mm`.
Без шага целый параметр с целыми границами получает шаг 1, остальные — около
сотой доли диапазона, округлённой вверх к 1, 2 или 5 × степени десяти.

Ползунок и стрелки ставят значение на сетку `мин + k·шаг`, с числом знаков шага и
той же десятичной запятой, что в поле: `1,6 mm` при шаге `0,4` → `2 mm`. Со значения
вне сетки стрелка ведёт к соседней точке: `1,37` → ▶ → `1,6`, ◀ → `1,2`. Шаг
выбирайте кратным точности изготовления, например стенку — кратной ширине линии сопла.
Формулы и строки без обеих границ остаются без ползунков. Поле ввода свободно:
можно ввести значение вне рекомендаций и пересчитать; ползунок останется на
краю, появится пометка. Движение ползунка само не запускает тяжёлый пересчёт.
Кнопка «↻ пересчитать» отправляет текущие значения полей.

Стрелки ◀ ▶ меняют значение на шаг, удержание повторяет. Для ползунка доступны
стрелки клавиатуры, PageUp/PageDown (10 шагов), Home/End (границы). На телефоне
управление располагается под полем, в печати остаются значения и диапазоны текстом.

его к себе и при необходимости загрузите снова; проверка scopes, метки проекта и imageId остаётся.
[Сохранение и повторная загрузка](https://github.com/kscht/spiridus-docs/blob/main/sessions.md#сроки-и-восстановление).

## Сетка и результаты инструментов

`cad_run` выполняет обязательный `script` (Python, до 256 КиБ) без сети: 1 ГБ, 120 с.
Выгружаются тела верхнего уровня: `volume`, `area`, `bbox`, `valid`, а также `warnings`,
вывод `print` в `output`, файлы `model.stl`, `model.step`, `model.FCStd` и `script.py`.
`block` — готовый `stl`, а при таблице параметров — `freecad` вместе с `params`.

`cad_recompute` принимает обязательные `model` (FCStd до 32 МБ) и `params`:
имя ячейки Spreadsheet → число или строка с единицей, например `{"length":"200 mm","holes":6}`.
Пустой `params: {}` возвращает текущие параметры, остальные значения сохраняются.
Результаты — STL, STEP, FCStd и блок с новой таблицей значений; ошибка называет параметр:
неизвестное имя, не число или модель не строится. Собственный Python исполняет `cad_run`,
а работа в одном интерпретаторе по шагам начинается с `cad_session_open`.

`deflection` задаёт точность сетки STL в мм (по умолчанию 0.1).
`max_triangles` — от 1000 до 250000, по умолчанию предел 250000 действует и без аргумента.
При превышении предела песочница огрубляет линейную и угловую точность;
у тонких цилиндров и стержней число треугольников зависит от угловой точности.
Использованные значения — `deflection` и `angularDeflection` в ответе.
Для документа обычно достаточно автоматического выбора: вместе с полной сеткой
выгружаются уровни примерно на 30 и 8 тысяч треугольников (`lods`),
просмотрщик выбирает подходящий устройству.

## Модель и результат в проекте

В `/p/` `model:` — входной FCStd, `result:` — готовый STL, оба относительны
к статье и читаются из одного commit. Запись/импорт материализует доступные
`artifact:`, `private:` и формы `/artifacts/`. Своя загрузка `upload:`
допускается только в `model:`: проверяются владелец, scopes и текущая метка
проекта, повторно перед commit. Для `result:` загрузка запрещена.

Модель и результат могут происходить из разных доступных наборов. Для новых
расчётов сверяется SHA-256 входного FCStd независимо от его пути и таблица
параметров; перенос не меняет соответствие. У старого результата без хеша
сверка входа явно помечена как непроверенная. Формулы и section/cut/hatch
работают с текущими параметрами. Сохранённые LOD и скачивания берутся только
из состава набора; показ не запускает генерацию LOD или пересчёт.
Заверение исполнения и соответствие текущим входам — отдельные сведения.

Сборку выбирают явно: `cad_run {build: "…", script: "…"}`, `cad_recompute {build: "…", …}`,
`cad_session_open {build: "…"}` или `build:` в блоке. Сеанс сохраняет одну сборку и её imageId;
для другой сборки откройте новый сеанс. Основная `freecad-1.1.4-timashkovy` не меняется.

### Балка: CalculiX против Elmer

Проверяемый учебный рецепт уже установлен в FEM-сборке. Передайте в `cad_run`:

```python
from freecad_queue1 import beam
print(beam())
```

Это одна консоль 1000×20×40 мм, E=210000 Н/мм², ν=0,3, полный запрет перемещений на x=0,
равномерная нагрузка 100 Н в направлении −z на x=1000. Одна явно построенная сетка hexa8
используется как C3D8 в CalculiX и через Gmsh 2.2 → ElmerGrid в Elmer. Сетки: 400/1800/6400
элементов. Euler–Bernoulli: 1,488095 мм; тонкая сетка: около 1,47401 мм у обоих решателей.
Реакция ≈100 Н, допуск 0,5%; прогиб к эталону ≤3%, между решателями ≤2%.
Напряжение сравнивается при x=100 мм, на внешних волокнах: эталон 16,875 МПа,
Elmer ≈16,928 МПа, CalculiX ≈17,080 МПа. Максимум на ребре заделки не является эталоном.

В том же вызове задайте `result_files`:
`["beam.png","beam.csv","beam.vtu","beam.msh","beam.inp","beam.sif","beam-summary.json"]`.
PNG показывает прогиб без увеличения (×1) и сгущение сетки; VTU сохраняет исходное поле.

### Теплопроводность Elmer

Сборка — та же FEM. Сценарий `cad_run`:

```python
from freecad_queue1 import heat
print(heat())
```

Брусок 0,1×0,02×0,02 **м**, k=10 Вт/(м·K), торцы x=0 / 0,1 м имеют 300 / 400 **K**,
остальные грани адиабатические. Три сетки: T(x)=300+1000x, мощность −4/+4 Вт,
ошибка температуры ≤0,5 K, баланс ≤1%. Единицы solver — SI; геометрия FreeCAD сохранена в мм.
`result_files`: `["heat.png","heat.csv","heat.vtu","heat.msh","heat.sif","heat-summary.json"]`.
CSV включает qₓ=−k·dT/dx в Вт/м², PNG — температуру и поток.

### Листовой металл, крепёж и передача

В `freecad-1.1.4-mechanical-r1` установлен общий проверяемый пример:

```python
from freecad_queue1 import mechanical
example = mechanical()
print(example["result"])
```

Он строит и сохраняет три небольших примера в одном документе:

- Лист: один гиб 90°, t=1 мм, внутренний R=2 мм, K=0,4 по **ANSI**. Прямые участки
  40 и 30 мм заданы до касательных. Настоящий `SheetMetalNewUnfolder.getUnfold` даёт
  BA=(π/2)(R+Kt)=3,769911 мм и длину развёртки 73,769911 мм; допуск 0,1 мм.
  Измеренная длина проверяет обратное восстановление прямого участка. Есть DXF и closed/valid тела.
- Крепёж: болт ISO4017 M6×20, шайба ISO7089 M6, гайка ISO4032 M6; геометрия создаётся
  `FastenersCmd.FSScrewObject`. `Thread=False` у резьбовых деталей — упрощённая резьба.
  Пример проверяет геометрию крепежа, сохранение и recompute, а не прочность соединения.
- Передача: два `freecad.gears.involutegear.InvoluteGear`, 20/40 зубьев, модуль 2 мм,
  угол давления 20°, межосевое расстояние 60 мм, отношение 2. Позы ведущей шестерни
  0/45/90°; ведомая — 4,5°−φ/2. Проверяется отсутствие объёмного пересечения зубьев.
  Это заданная кинематика, не решение ограничений Assembly и не расчёт прочности.

`result_files`: `["unfold.dxf","mechanical.png","mechanical-summary.json"]`.
FCStd сохраняет объекты и их аддоны; повторный пересчёт выбирайте той же сборкой.

### Сохранение дополнительных результатов

Необязательный `cad_run.result_files` — явный список имён созданных файлов непосредственно
в `/out`: до 48 уникальных имён, каждое не длиннее 64 символов вместе с точкой и расширением;
12 МиБ каждый файл, 64 МиБ вместе. Допустимы поля/входы решателей,
CSV/PNG/DXF/JSON и ограниченные журналы; пути с каталогами и служебные `model.*`, `meta.json`,
`script.py`, `params.json` запрещены. Отсутствующий файл или превышение размера даёт отказ
до сохранения набора. Посторонние файлы рабочей папки автоматически не публикуются.
В `meta.resultFiles` записаны имена, размеры и SHA-256. Обычный экспорт модели остаётся прежним.

Для проекта вызывайте инструмент с `project`: модель, рецепт и выбранные поля сохраняются одним
доступным этому проекту набором. При записи статьи используйте штатную материализацию 0053,
которая создаёт новый каталог целиком; `private:` — только транспорт, в тексте статьи его не оставляют.
Читатель получает сохранённые PNG/CSV/модель без запуска solver. `cad_recompute` пересчитывает
геометрию FCStd; новые FEM-поля получают новым явным `cad_run`, сохраняя новый набор.
