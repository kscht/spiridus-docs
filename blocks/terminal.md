# Учебный терминал

Блок `terminal` — личный bash участника проекта курса. Учебный пилот выключен по умолчанию;
нужны `TERMINAL_SESSIONS=1` и явная политика курса. Гость запустить его не может.
Код документа и ANSI обрабатываются в изолированном фрейме на volkodlak.ru без кук.
Показ документа, прокрутка и снимок не создают учебных сред.

Содержимое — JSON версии 1. `id` уникален в статье, `title` — условие, `build` —
`shell-debian-13`. `setup` создаёт входы в `/home` один раз при старте или сбросе;
`solution` — эталон для серверной авторской приёмки. После паузы `/tmp` пуст, setup
не повторяется. Эталон и тесты открытые. Журнал попыток курса хранит серверные вердикты;
контракт официальной ведомости и скрытые тесты в этот этап не входят.

````markdown
```terminal
{
  "version": 1,
  "id": "even-numbers",
  "title": "Сохраните чётные числа из data/numbers в answer.txt",
  "build": "shell-debian-13",
  "setup": "mkdir -p /home/data; seq 1 10 > /home/data/numbers",
  "solution": "grep -E '[02468]$' /home/data/numbers > /home/answer.txt",
  "criteria": [{"type":"file","path":"answer.txt","equals":"2\n4\n6\n8\n10\n"}]
}
```
````

Файловый критерий `file` сравнивает точное UTF-8 содержимое `equals` побайтно, без
нормализации. Пути относительны `/home`; symlink вместо файла или каталога не принимается.
Критерий `program` запускает сданный bash-файл `path` без PTY на 2–20 входах
`cases: [{stdin, stdout, exitCode}]`. У каждого запуска чистые HOME/cwd в копии `/home`,
PATH=/usr/bin:/bin, LC_ALL=C, SEED=0 и pipefail. stdin берётся из case; stdout сравнивается
побайтно, stderr отделён. Контейнер программы не получает эталон. Лимиты: 15 секунд,
256 МиБ, 0,25 CPU, 64 PID, вывод до 64 КиБ. Неверный ответ — ✗; сбой checker — ошибка проверки.

Кнопки «Начать», «Продолжить», «Пауза», «Проверить» и «Сбросить» принадлежат доверенной
странице. «Проверить» кратко замораживает все процессы только этой среды, подтверждает
ограниченный снимок и сразу отвечает «На проверке». Студент продолжает работу или уходит; <!-- docs-check: ok -->
вердикт появится при опросе работы. ✓ относится к конкретной серверной попытке и хешу снимка. История изменяема
студентом, доступна ему и преподавателям курса только для анализа. До старта показываются
срок хранения и предупреждение. «Сбросить» и «Удалить» удаляют текущую среду/историю,
сохраняя сданные снимки и append-only журнал курса. Предел попыток считается по журналу
для студента и закреплённой версии задания; сброс или повторный старт его не обнуляет.
Преподаватель может перепроверить сохранённую сдачу. Эти записи стираются каскадом
удаления аккаунта/проекта или стирания истории проекта по 0049.
История живого терминала выдаётся из последней подтверждённой точки, поэтому может
отставать от текущего ввода; чтение не останавливает процессы. Чтения преподавателя
журналируются без содержимого. Один живой терминал
на человека в общих квотах сеансов. При нехватке ресурсов — очередь без вытеснения.

`render_check` обязательно выполняет серверную A/B-приёмку даже с `lint:false`:
чистый setup не должен пройти, setup+solution должен пройти. Оба контроля повторяются
после паузы и восстановления без setup; эталон также завершает восстановленный контроль A.
Приёмка идёт фоновым заданием, не более одного на автора; до двух определений terminal
на документ и общий дедлайн 180 секунд, включая очередь. Превышение лимита, неполная
приёмка и инфраструктурные ошибки блокируют принятие задания. При выключенном
`TERMINAL_SESSIONS` документ с terminal явно отклоняется: A/B недоступна, пропуска
семантического этапа нет. Документы без terminal проверяются как обычно.
