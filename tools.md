# Инструменты

Для статей начните с [проектов](projects.md) и `/mcp/p/projects`; этот каталог объясняет назначение инструментов.

Что умеет Spiridus — по инструментам. Они одни и те же в [MCP](mcp.md) и [REST API](api.md); все
аргументы с типами и пределами — [arguments.md](arguments.md) (машинно — `GET /api/v1/tools`,
`/api/v1/openapi.json`), здесь — зачем он и что получится.

`/mcp` показывает ядро: документный цикл, файлы и публикацию, учётную запись, `code_run` и `projects`.
Прямые вызовы инструментов нотаций доступны в пресетах ([подключение](mcp.md)):

| Адрес | Инструменты сверх ядра |
|---|---|
| `/mcp/p/cad-steps` | `cad_session_open`, `cad_exec`, `cad_inspect`, `cad_view`, `cad_session_save`, `session_list`, `session_close`, `sandbox_builds` |
| `/mcp/p/cad` | `cad_run`, `cad_recompute`, `sandbox_builds` |
| `/mcp/p/diagrams` | `plantuml_run`, `structurizr_run`, `render_shapes`, `render_icons`, `render_media`, `render_recipes`, `fonts_list` |
| `/mcp/p/docs` | документный цикл, как `/mcp/lite` |
| `/mcp/p/electric` | `qet_run`, `qet_symbols`, `qet_tools`, `qet_call`, `qet_save`, `sandbox_builds` |
| `/mcp/p/electronics` | `hdl_synth`, `hdl_sim`, `sandbox_builds` |
| `/mcp/p/graphics` | `blender_run`, `ffmpeg_run`, `hlsl_compile`, `blender_session_open`, `blender_exec`, `blender_inspect`, `blender_view`, `blender_session_save`, `session_list`, `session_close`, `sandbox_builds`, `image_view` |
| `/mcp/p/jobs` | `job_status`, `job_cancel`, `image_view` |
| `/mcp/p/modelica` | `modelica_run`, `modelica_session_open`, `modelica_simulate`, `modelica_session_save`, `session_list`, `session_close`, `sandbox_builds` |
| `/mcp/p/projects` | `project_read`, `project_write`, `project_import`, `project_hide`, `project_members`, `invitations`, `project_admin` |
| `/mcp/p/proofs` | `lean_check`, `lean_session_open`, `lean_session_command`, `lean_session_tactic`, `lean_session_goals`, `lean_session_close`, `lean_session_save`, `sandbox_builds` |
| `/mcp/p/quantum` | `quantum_run`, `sandbox_builds` |

Нужный инструмент можно добавить через `tools({add:"session_call"})` в MCP-сессию либо вызвать
через Code Mode (`/mcp/code`, `code_run`), если он разрешён из кода. `session_call` и `search`
в Code Mode не входят: шаг сеанса Python из кода — `code_run` с `session`.
REST-каталог и `/api/v1/openapi.json` описывают все REST-инструменты; MCP-only `tools` в них нет.

У обычных предметных инструментов есть необязательное поле `task` — 2–3 предложения о том, какую просьбу
пользователя модель сейчас выполняет. В обычных вызовах оно пишется в журнал, в проектных —
исключается; регистрации и ключевых инструментов этот общий контракт не касается. На результат не влияет ([data.md](data.md)).

Обычный порядок — у модели и у человека, который зовёт инструменты сам: узнать, какие блоки есть и как
их писать ([формат документа](markdown.md)) → написать документ → проверить → поправить замечания →
проверить снова → сохранить статьёй проекта (`project_write`) → пригласить человека и дать ссылку `/p/…`. Блоки, которые рисуются на сервере (PlantUML, схемы ПЛИС, модели…),
вне проекта отправляются на отрисовку с готовой ссылкой в документе.
В проекте серверные блоки с `artifact:` пока не работают: картинку сохраняйте ресурсом,
модель приложите файлом. [Ограничение](projects.md#ресурсы-и-серверные-блоки).

## Справка и примеры

| Инструмент | Зачем | Что в ответе |
|---|---|---|
| `render_blocks` | узнать, какие наглядные блоки есть: диаграммы, схемы, формулы, химия, ноты, 3D, карты… | список языков блоков с короткими пояснениями |
| `render_block_docs` | справка: синтаксис и ограничения языка блока | справка: синтаксис, ограничения, рабочий пример |
| `render_examples` | найти готовый образец под задачу («диаграмма последовательности с ветвлением», «карта с раскраской областей») | 2–3 блока, которые проходят проверку, и ссылки на страницы примеров |
| `render_recipes` | как починить конкретное замечание проверки в конкретной библиотеке | проверенные приёмы — и отмеченные как не помогающие |
| `render_icons` | иконки для схем Mermaid и D2: сетевые устройства, ИТ, логотипы | имена иконок и как их вставить |
| `render_shapes` | готовые анатомические контуры и карты для диаграмм ECharts | названия карт и их частей, автор и лицензия |
| `render_media` | картинки, которые можно вставить в документ | список с автором, лицензией и строкой для вставки |

## Проверка

| Инструмент | Зачем | Что в ответе |
|---|---|---|
| `render_check` | отрисовать документ так, как его увидит читатель — на компьютере и на телефоне, — и найти, что не так | `built` — блоки собраны, `clean` — собраны и сценарии `interact` прошли (строже — `strict`: какие ещё замечания считать провалом), `totals` — замечания по видам, `verdict` — итог одной фразой; список замечаний со строкой документа: блок не собрался, подписи налезают друг на друга, рисунок шире колонки или слишком мелкий, формула с ошибкой, опечатки и стиль текста ([russian.md](russian.md)); по желанию — снимки блоков и страницы |
| `lean_check` | проверить доказательства Lean 4 и Mathlib ([справка](blocks/lean.md)) | сообщения по строкам, цели, дерево тактик, зависимости и аксиомы |
| `lint_check` | быстро проверить линтерами один блок кода (`code` и `lang`) или весь документ — без отрисовки; `text: true` — и русский текст | `clean`, замечания `{ line, tool, rule, text, hint }`; у блока строки — по его коду |

Для статического разбора исходника выберите `lint_check`; раскладку, подписи и действия
читателя проверяет `render_check` в Chromium. [Подробности и экономия повторных вызовов](check.md).

Документ передаётся целиком, одной строкой, в поле `markdown`. Можно проверить и поведение живых блоков:
нажать кнопку, щёлкнуть по входу схемы — и посмотреть, что изменилось ([сценарии и статьи проектов](check.md)).

## Рисование на сервере

Экспериментальный `tts_run` (нотация `tts`, включается профилем) синтезирует русский
и английский текст выбранной моделью и голосом, возвращает аудио и разметку фраз
для сохранения набором ресурсов проекта. Читатель только проигрывает готовую запись.
Синтаксис и лицензии моделей — `render_block_docs tts`; для закрытого текста обязателен `project`.

Эти блоки собираются на сервере, потому что для них нужна полноценная программа. Ответ — рисунок или
результат расчёта и готовая строка, которую вставляют в блок документа. Одинаковый запрос второй раз
отвечает сразу, из готового: `"cached": true`, без очереди. Синхронный вызов не тратит лимит;
`.start` и REST `async=1` расходуют квоту при принятии даже при попадании в кеш ([api.md](api.md#кеш-результатов)).

| Инструмент | Зачем | Что в ответе |
|---|---|---|
| `plantuml_run` | схемы PlantUML: UML, C4, сети, mind map, диаграммы Ганта | схема SVG, предупреждения или ошибка со строкой |
| `structurizr_run` | архитектура по модели C4 на языке Structurizr DSL | каждый вид модели — рисунком, ошибки со строкой |
| `quantum_run` | квантовые схемы OpenQASM | схема, вероятности исходов, сферы Блоха, ZX-диаграмма и её упрощение |
| `hdl_synth` | Verilog, SystemVerilog, VHDL: проверка и синтез | схема RTL, живая схема для щелчков по входам, ресурсы ПЛИС и предельная частота |
| `hdl_sim` | симуляция тестбенча | осциллограммы для блока и вывод тестбенча |
| `hlsl_compile` | HLSL/Slang: Slang 2026.19 или DXC 1.9.2609 | GLSL ES 3.00, диагностика, ползунки и живая картинка через glsl |
| `modelica_run` | расчёт модели Modelica: механика, электрика, тепло; `set` — другие значения параметров | графики переменных, у механизмов — анимация |
| `cad_run` | 3D-модель по сценарию FreeCAD на Python | модель STL и STEP, объём, площадь, габариты; модель от таблицы параметров (ячейки с псевдонимами) — `params` и блок ```` ```freecad ```` с полями для читателя |
| `cad_recompute` | пересчитать готовую модель FreeCAD (FCStd) с другими значениями параметров, без сценария | то же, что у `cad_run` |
| `ffmpeg_run` | перекодировать видео, собрать HLS, при явном выборе — NVENC/NVDEC | видео и сегменты; файлы GPU-сборок видны администраторам общего вычислительного узла, GPU недоступен проектам и сеансам |
| `blender_run` | сцена Blender: кадр, конвертация моделей | картинка или файлы моделей; меши в сцене — `model.stl` и готовый блок ```` ```stl ```` (`max_triangles` огрубляет сетку), `scene.blend` — сцена целиком |
| `qet_run`, `qet_symbols` | электрические схемы и символы QElectroTech; поиск символа в библиотеке | листы схемы, проект для скачивания |
| `qet_tools`, `qet_call`, `qet_save` | пошаговая работа со схемой QElectroTech, когда нужны все её инструменты | результат каждого шага, сохранённые листы |
| `text_parse` | синтаксический разбор русских предложений; анализатор — параметром `parsers` ([russian.md](russian.md)) | готовый блок с деревом разбора, части речи и члены предложения |

`ffmpeg_run` перекодирует свой `input` в HLS: `blob:sha256/<хеш>` — до предела
хранилища (до 5 ГиБ на объект) на CPU, upload/artifact — до 32 МиБ.
На общем GPU входы, включая `blob:`, остаются до 32 МиБ без монтирований файлов сервера.
Большой вход передаётся потоком на узел, повтор использует копию. На CPU с CAS дисковый
выход — до 1024 МиБ с учётом файловой системы, результат передаётся потоком в `private:`.
Ответ содержит ссылки `files`/`playlist` и подписанные `urls` до 15 минут. При чтении
приватного HLS-плейлиста подписи сегментов обновляются. Без CAS и на GPU выход — до 256 МиБ. Вызовы с данными проектов используют прежний
путь с пределом 256 МиБ и проверками версии/стирания проектного хранилища.
Синхронный срок — **300 с**: 4K и тяжёлое видео могут не успеть. Для них нужен фоновый
вызов (`?async=1`, `job_status` или Code Mode `.start`): CPU batch — до **2 часов** после
старта, при недостаточной доле batch узла остаётся интерактивный срок 300 с.
Профиль HLS — 720p, до 10 минут. По умолчанию
`ffmpeg-7.1.5` использует CPU; `ffmpeg-7.1.5-nvenc` — общий GPU-узел вне проектов.
`codec`: `libx264`, `h264_nvenc`, `hevc_nvenc`. Оба NVENC-кодека требуют явного
`build: ffmpeg-7.1.5-nvenc`; иначе вызов отклоняется до чтения файла и запуска задачи.
При занятой GPU можно повторить
позже или выбрать CPU-сборку явно. `blender-5.2.2-gpu` аналогично выбирается
явно в `blender_run`; помощник `render()` использует CUDA, `params.gpu_backend`
может выбрать `OPTIX`. Список доступных образов — `sandbox_builds`.


Долгие (секунды–минуты) удобнее звать асинхронно — [api.md](api.md#асинхронные-вызовы).

## Сценарии (Code Mode)

| Инструмент | Когда | Что в ответе |
|---|---|---|
| `search` | только `/mcp/code`: `{}` — пространства имён, `{query, ns?, limit?}` — поиск, `{describe: [имена]}` — до восьми сигнатур | `structuredContent` с совпадениями или сигнатурами и примерами; большой текст явно усечён |
| `execute` | то же, что `code_run`, под коротким именем профиля `/mcp/code`; в коде доступны `tools.search`, `tools.describe` и выборочное `tools.read` | только явно возвращённый итог и обрезанный лог; промежуточные ответы больше 16 КиБ — через `private:` владельца или затронутого проекта; для браузера — [временная подпись](code.md#выборочное-чтение-больших-ответов) |
| `code_run` | связать несколько вызовов кодом на JavaScript или Python: построить деталь → проверить объём → пересчитать → проверить документ; посчитать по результату (numpy, scipy, sympy, pandas) — без промежуточных ответов в контексте модели ([code.md](code.md)) | `value` — то, что вернул `return`, и последние строки лога |

## Долгие сеансы

[Сравнение шести ядер, сроки, сохранение и возврат позже](sessions.md).

| Инструмент | Когда | Что в ответе |
|---|---|---|

| `session_save`, `session_open` с `from` | вернуться к сеансу Python позже (для хранения дольше суток скачайте пакет): пакет — шаги, ответы инструментов, файлы `/out` и seed — в своих приватных файлах; открытие проигрывает шаги без повторных вызовов инструментов ([code.md](code.md#сохранить-сеанс-и-открыть-позже)) | ссылка `upload:<id>/session.json`; новый сеанс, `warning` и при `refresh` — `differences` |
| `lean_session_open`, `lean_session_command`, `lean_session_tactic`, `lean_session_goals`, `lean_session_save`, `lean_session_close` | доказательства по шагам в загруженной среде Mathlib | среда, состояния целей и сообщения Lean |
| `cad_session_open`, `cad_exec`, `cad_inspect`, `cad_view`, `cad_session_save` | строить деталь FreeCAD по шагам: документ остаётся в памяти, шаг — миллисекунды; смотреть дерево и вид, сохранить модель и сценарий для `cad_run` ([freecad](blocks/freecad.md)) | итог шага; объекты со свойствами, объёмами и габаритами; SVG-проекция; STL, STEP, FCStd, `script.py` и готовый блок |
| `blender_session_open`, `blender_exec`, `blender_inspect`, `blender_view`, `blender_session_save` | сцена Blender по шагам: сцена и переменные остаются в памяти, шаг — миллисекунды; смотреть объекты и кадр, сохранить приватный пакет, модель и сценарий для `blender_run` ([sandbox](blocks/sandbox.md#blender-сценарий-blender_run)) | итог шага; объекты сцены и камера; кадр PNG; `model.stl`, `scene.blend`, `script.py` и готовый блок |
| `modelica_session_open`, `modelica_simulate`, `modelica_session_save` | серия расчётов одной модели Modelica: собрать один раз, считать с другими параметрами без перекомпиляции ([modelica](blocks/modelica.md)) | изменяемые параметры; `final`, `result.csv` и строки блока |

Не больше двух открытых сеансов; после 15 минут простоя — выгрузка и восстановление следующим шагом.
У QET закрытие уже после 30 минут без команд. Blender/Modelica — сборки `next`; переносимые пакеты
есть у Python/FreeCAD/Lean, у остальных сохранение файлов имеет другой смысл ([таблица](sessions.md#выбрать-ядро)).

## Свои файлы

| Инструмент | Зачем | Что в ответе |
|---|---|---|
| `files_upload` | загрузить свой файл: модель для Blender, проект QElectroTech, документ для проверки | ссылка `upload:<id>/<имя>`; с `size` — прямой PUT/multipart и после `action: "finish"` ссылка `blob:sha256/<хеш>` |
| `files_publish` | сделать видимым читателю свой `private:` из Code Mode или загруженную картинку/шрифт `upload:`, до 10 МиБ, включая private | общая ссылка `artifact:<id>/<имя>` и готовая Markdown-строка |
| `files_unpublish` | снять свою опубликованную картинку — только если пользователь сам попросил | что снято |
| `files_list`, `files_delete` | свои файлы и занятое место; удалить ненужное | список со ссылками и размерами |
| `image_view` | посмотреть картинку PNG, JPEG или SVG до 20 МиБ по ссылке без повторного расчёта — например кадр фонового `blender_run` из `job_status`; `artifact:` — любому со ссылкой, `private:`, `upload:`, `blob:` — по тем же правам, что вход инструментов. Пресеты `/mcp/p/jobs` и `/mcp/p/graphics` | уменьшенная копия: сторона до 1024 px (по умолчанию 768, `max`), не больше 192 КиБ; в Code Mode — только ссылка и размер |
| `account_register` | регистрация по email и обязательному nickname; доступен в MCP без ключа, в REST — `POST /api/v1/register`. Письмо подтверждения, ключ выдаётся только человеку на странице | инструкция по подтверждению, без ключа |
| `account_delete` | удалить свою учётную запись (владелец совместного проекта сначала передаёт его или дожидается удаления; иначе 409) — только если пользователь сам попросил; в `confirm` — почта. Есть только в MCP и только с ключом учётной записи; в REST — `DELETE /api/v1/me` | что удалено |

До 10 МБ — `data_base64`. Для больших файлов передайте `name`, `size` в байтах и `type`;
клиент отправляет байты по выданным ссылкам в S3. Докачка — `action: "status"`, завершение —
`action: "finish"`, отмена — `action: "cancel"`, с `upload_id` из первого ответа.
Подробнее — [свои файлы](api.md#свои-файлы) и [протокол больших загрузок](api.md#большие-загрузки-в-s3).

Имена загрузок `POST /api/v1/files` и `files_upload` допускают обычные пробелы внутри:
`Pasted image 20261024011820.png`. Прежний алфавит (латиница, цифры, `._-`) и предел
64 знака сохраняются; пробелы по краям, табы, переводы строк, разделители путей,
кодированные разделители и невидимые знаки запрещены. В URL скачивания имя кодируется
через `encodeURIComponent`. У проектных путей свой более широкий алфавит с кириллицей;
правило внутренних пробелов одинаковое. `project_write` сохраняет выбранное имя ресурса.
При `files_publish` пробелы заменяются на `_` для формата публичных `artifact:`;
ответ явно возвращает `originalName`, `name` и фактическую `ref`.

QET принимает `upload:…/My circuit.qet` в `qet_run` (`qet_project` при работе с
проектом Spiridus), в значениях `put` у `qet_call` и во входном поле JSON-блока
при `project_write`. Ключ `put` — отдельное имя внутри песочницы, например
`project.qet`, с прежним запретом пробелов. Пакеты сеансов (`from` у `session_open`,
`blender_session_open`, `cad_session_open`, `lean_session_open`, `modelica_session_open`)
по-прежнему принимают только `upload:…/session.json`, выданный сохранением сеанса.

## Поделиться документом

|---|---|---|

| `document_delete` | удалить документ со всеми версиями — только если пользователь сам попросил | что удалено |

Подробнее — [api.md](api.md#поделиться-документом).

## Проекты

[Модель, матрица ролей, приглашения и конфликт записи](projects.md). `rename` доступен owner/admin;
`transfer`, `cancel_transfer`, `delete`, `cancel_delete`, `erase`, `delete_versions` — только owner;
`accept_transfer` — назначенному участнику с правом создания и свободной квотой.

Проекты доступны только с ключом учётной записи.
Проект — папки и статьи `.md` с историей правок; роли — владелец, админ, редактор, читатель. Без права
ответ тот же, что «нет такого» (`404: …` в тексте ошибки). Из Code Mode закрыты `project_hide`, `project_members`,
`invitations` и `project_admin`; REST — без `async=1`.

Коды ниже (`404`, `409`, `422` и другие) — причины **в тексте ошибки инструмента**;
REST-обёртка возвращает HTTP 422. Недоступность — отдельный HTTP 503; `Retry-After: 5`
есть только при временной занятости ([ошибки REST](api.md#ошибки)).

| Инструмент | Зачем | Что в ответе |
|---|---|---|
| `projects` | свои проекты с ролями, ожидающие приглашения и передачи владения; `action: "create"` — новый проект со `slug` и `title` (нужно право создавать проекты от владельца системы, до 10 своих проектов) | списки `projects`, `invitations`, `transfers` или созданный проект |
| `project_read` | дерево (`op: "tree"`, ресурсы — `resource: true`), статья или ресурс (`"read"`, `path`), раздел/блок статьи (`"read"`, `path`, `fragment`), исходящие и обратные ссылки (`"links"`, `path`, только голова), история (`"history"`) или версии ресурса (`"versions"`, `path`); `version` — старая версия, читателю — только голова `main` | `commit` — `base` для записи, `files`, `content` или `commits` с текущими никами; у статьи — `url`, при чтении фрагмента — `heading`/`block`, `method`, `warnings`; у links — `links`, `backlinks`, `dangling`, `count`, `truncated`, `warnings`; у ресурса — `url` (подписанная ссылка, не дольше 15 минут, не отзывается; из Code Mode её нет), `size`, `type`, `version` |
| `project_write` | один коммит: `put` — `files [{path, content}]` или один ресурс `{path, base64}` / `{path, ref}` (до 12 000 000 байт; `ref` — своя загрузка `upload:`, своя публикация `artifact:` из `files_publish` или `private:` результата этого проекта при праве чтения его версии и правах ключа из метки результата; личный `private:` и результат другого проекта — отказ), `move` — `from` → `to` (ссылки статей на перемещаемый путь правятся тем же коммитом; у статьи её ссылки пересчитываются от нового места), `restore` — `paths` статей из `version` (до 50), `delete` — один ресурс в `paths` (на него не должны ссылаться статьи), `copy` — ресурс `from` из проекта `source` (по умолчанию этот) и `version` в `to`; `base` обязателен; после него изменились пути записи или исчезли цели ссылок статьи (перемещены, скрыты, удалены) — 409 с текущим `commit`, прежним `base`, `reason` и `paths`: перечитать и слить правки. Правка содержимого цели не мешает. Новый путь, неотличимый на вид от существующего (`сах.md` кириллицей рядом с `cax.md`), — 409 | `commit`, `base`, автор, `url`, `urls` по путям; у put — `warnings` о пропавших якорях и смене цели; `articles` — статьи, где поправлены или мешают ссылки |
| `project_import` | последняя версия своего `/d/<id>` в новую статью: `project`, `id`, `path` (`.md`); один коммит от тени вызывающего, занятый путь — 409. Любой публичный `artifact:` из своего `/d`, включая файл другого автора, копируется ресурсом `media/<имя>` (у `project_write put` — только свой `artifact:` из `files_publish`) (при совпадении — суффикс), ссылки переписываются относительно статьи; `/d` не меняется. Разрешён из Code Mode | `commit`, `base`, `path`, `url`, `urls`, `files` (пути и размеры), `unavailable` (`{ref, reason}`: ссылки, оставленные в тексте) |
| `project_hide` | убрать статьи из `main` (`base`, `paths`); в истории остаются, вернуть — `restore` | `commit`, `brokenLinks` (группы входящих из оставшихся статей; скрытие не блокируют) |
| `project_members` | участники и роли; `role`, `remove` — админ и владелец (админов назначает только владелец); `leave` — выйти; `journal` — приглашения, роли, передачи | `members` или `events` |
| `invitations` | свои приглашения: `list`, `accept`, `decline` по `id`; с `project` — приглашения проекта, `invite` по email с ролью, `revoke`. Письмо одно и то же, есть ли такой адрес | список или `status` |
| `project_admin` | `rename`, передача владения (`transfer`, `cancel_transfer`, `accept_transfer`), `delete` и `cancel_delete`, `erase` (стереть `paths` со всей историей), `delete_versions` (старая версия ресурса: `path`, `version`; только владелец); в `confirm` — slug проекта, без него ничего не меняется | итог действия |

При устаревшем `base` `structuredContent.error` (MCP) / `data.error` (REST) содержит
`code: 409`, `message`, текущий `commit`, прежний `base`, `reason`. Для `paths-changed`
и `targets-missing` есть `paths`, полный `pathCount` и `pathsTruncated` (до 100 путей и 32 КиБ).
Другие причины — `base-mismatch` и `base-unavailable`.
[Рецепт слияния](projects.md#конфликт-записи): перечитать, сравнить старый/свой/текущий текст,
сохранить изменения коллег и повторить с базой прочитанного текста. Автослияния одной статьи нет.

`project_read` принимает путь статьи или адрес `/p/<slug>/<путь>#…` в `path` (того же проекта).
`fragment` — отдельное поле для раздела (`Глава%20Б#Детали`), старого слага или блока (`^block-1`);
в адресе и поле одновременно его задавать нельзя. Декодирование фрагмента — ровно один раз.
Раздел включает подразделы до следующего заголовка того же или более высокого уровня;
в цитате или пункте списка — не дальше конца этого контейнера. Чтение fragment разбирает только
выбранную статью и не зависит от индекса всего проекта.
Блок — весь владелец `^id`, включая маркер. `heading`/`block` и `method` показывают выбор,
`warnings` — конкурирующие кандидаты и совместимость только по слагу. Ненайденный фрагмент — 422.

`links` и `backlinks` содержат `source`, `target`, `fragment`, `status`, выбранную цель `selected`,
способ `method` и `issues`. Каждый список (`links`, `backlinks`, `dangling`) содержит до 100 записей,
вместе — до 64 КиБ JSON; `count` содержит полные количества по именам списков, `truncated` —
признак усечения. Статусы: `resolved`, `missing-path`, `missing-fragment`, `unindexed-target`.
Индекс учитывает только ссылки внутри проекта; внешние и другие проекты не проверяет и не раскрывает.
Front matter, `%%` и код не участвуют в навигации; незавершённые вики-ссылки перечислены в `dangling`.
Скрытая статья недоступна для links и чтения фрагмента; права повторно проверяются после ожидания пула.
У ссылки на слишком тяжёлую цель — `unindexed-target`, у её links — предупреждение `unindexed-article`.

`url` записи — адрес статьи `/p/…`; у пакета — корень проекта, а `urls` содержит адрес каждого пути.
Это адреса для участников проекта, без подписи доступа к ресурсам.
`put.warnings` группируются по цели, фрагменту и коду, `count` — число входящих ссылок:
`missing-anchor`, `possible-target-change` при конкурирующих кандидатах до или после записи,
`target-changed` при однозначной смене заголовка или способа разрешения. Идентичность логического
раздела не гарантируется; ссылки других статей при переименовании заголовка не переписываются.
`project_hide.brokenLinks` группируются по `source`, `target`, `fragment` с `count`;
источники, скрываемые тем же вызовом, исключены. Предупреждения не отменяют запись/скрытие.
Если проверка упёрлась в пределы индекса, пул занят, снимок устарел или истёк срок
подготовки снимка (250 мс) или отдельный срок сравнения (5000 мс от начала compare), ответ записи содержит
`warnings: [{code: "navigation-unavailable", message: …}]`, а у hide — `brokenLinks: null`.
Это означает, что ссылки не проверены; пустой список означает выполненную проверку без замечаний.

Удаление проекта, стирание с историей и удаление версий ресурса записываются в реестр стираний; без него
(и без хранилища вложений) отвечают 503 (REST: HTTP 503; `Retry-After` только при временной занятости). Сейчас реестр — временная заглушка на той же машине, от отката машины
из резервной копии он не защищает ([data.md](data.md)). Без хранилища вложений инструменты ресурсов отвечают
503, статьи работают. Журнал вызовов проектов —
только служебные поля ([data.md](data.md#журнал-вызовов-и-проекты)).

## Сборки песочниц: версии программ

Всё, что считает сервер, — в **сборке**: версия программы с набором модулей. У программы может быть
несколько сборок — разные версии (прежняя и новая на пробу) или разные варианты одной версии. Нужную
называют параметром `build` у инструмента или строкой `build:` в блоке документа; без неё берётся
сборка по умолчанию. Как это устроено, состояния сборок и переход на новую версию —
[blocks/sandbox.md](blocks/sandbox.md).

| Инструмент | Зачем |
|---|---|
| `fonts_list` | какие шрифты есть: свои Timashkovy GOST (состояние и сколько знаков каждого набора уже нарисовано) и сторонние шрифты сайта — с готовым блоком ```` ```font ```` (`file: fonts:<id>`); семейства шрифтов в сборках песочниц (FreeCAD: `font()`); `own: true` — только свои |
| `sandbox_builds` | какие сборки есть сейчас: программа, версия, вариант, модули, состояние (`default`, `stable`, `next`, `deprecated` с датой отключения); фильтры `program`, `version`, `module` |

Актуальные сборки, состояния, модули и даты отключения смотрите через `sandbox_builds({})`.
Например, `sandbox_builds({program:"text"})` показывает варианты проверки текста, а
`sandbox_builds({program:"freecad"})` — FreeCAD. Полный ответ доступен и в REST:

```sh
curl -sS https://v2.spiridus.ru/api/v1/tools/sandbox_builds \
  -H "Authorization: Bearer $SPIRIDUS_KEY" -H 'content-type: application/json' -d '{}'
```

Новая версия программы появляется отдельной сборкой `next`, а не заменяет прежнюю: документ со строкой
`build:` и дальше считается в своей сборке, пока она не отключена; об устаревшей сборке ответ
предупреждает заранее, с датой.

## Для чатов: укороченное описание

Модели в чате (Open WebUI и т. п.) проще выбирать из меньшего числа операций. Для них —
`https://v2.spiridus.ru/api/v1/openapi-chat.json`: только инструменты модели, без служебных адресов.
Ещё короче — свой набор: `openapi-chat.json?tools=render_block_docs,render_examples,render_check`.

Типизированные ответы доступны для render_check, cad_run/cad_recompute, plantuml_run,
structurizr_run, lint_check, document_share и render_block_docs. Имена и значения полей прежние;
полный результат MCP — в structuredContent, схема — outputSchema в tools/list.
Подробнее — [MCP](mcp.md#структурированные-результаты) и [REST API](api.md#типизированные-результаты-инструментов).

MCP prompt `diagram_review` — готовая инструкция для цикла проверки документа и исправления
схем через `render_check` и `render_block_docs`. Это prompt сервера, не отдельный инструмент.
`image_view` допускает до 4 одновременных вызовов на клиента.
