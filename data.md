# Данные и их использование

Spiridus — исследовательский проект. Статьи, ресурсы и вычислительное состояние сохраняются
для работы сервиса. Обычные запросы и результаты используются для улучшения проверок: линтеров,
`render_check`, проверки текста и правил починки.

**Проектные вызовы имеют отдельный режим:** журнал сохраняет служебные поля, без текстов,
путей, email и `task`, включая помеченный Code Mode. Это не отменяет хранения самой статьи,
ресурсов и состояния ядра. Подробности — [«Журнал вызовов и проекты»](#журнал-вызовов-и-проекты).
У регистрации и управления ключами также свой контракт, не полный журнал обычного запроса.

В обычных вызовах сохраняются исходники, запросы, результаты и описание просьбы пользователя
в `task`; сама переписка с моделью остаётся в вашем клиенте. Не отправляйте секреты,
чужие тексты/код без права использования и персональные данные других людей.

**Адрес почты** нужен только для доступа: на него приходит ссылка подтверждения; ключ показывается один раз на странице после подтверждения. Для улучшения проверок он не
используется. IP-адреса не хранятся — кроме одного: у каждого ключа запоминается, когда и с какого адреса
им пользовались последний раз. Этот адрес видите только вы (страница «Ключи», `keys_list`); в журналах
вызовов его нет.

## Кто видит

- **Проект** закрыт: статьи, ресурсы, история и производные результаты доступны только участникам
  с соответствующей ролью. Скрытие не стирает историю; для удаления сведений нужен `erase` владельца.
- **Проверка без `project` и `files_publish` делают файлы публичными по ссылке.** Для закрытой статьи
  всегда передавайте `project` и `path`; картинку кладите ресурсом проекта, не публикуйте наружу.

- **Результаты инструментов** (рисунки, модели, файлы — ссылки `https://v2.spiridus.ru/artifacts/…`)
  открываются по ссылке без ключа: так их показывает документ у любого читателя. Ссылка случайная и
  длинная, перебором её не найти, но кому вы её дали — тот увидит.
- **Опубликованные документы** (`document_share`, ссылки `https://v2.spiridus.ru/d/…`) — по ссылке
  без ключа, со всеми прежними версиями, у любого, кому её передали. Ссылка случайная, в поисковики
  страница не отдаётся. Менять и удалять документ можете только вы. Новые такие
  документы не создаются; прежние открываются как раньше и обновляются по `id` ([mcp.md](mcp.md#новые-d-не-создаются)).
- **Опубликованные картинки** (`files_publish`) видны по ссылке без ключа, как рисунки инструментов.
  Живут, пока жива учётная запись: удаляются вместе с ней; снять раньше — `files_unpublish`.
- **Свои файлы** (`upload:<id>/<имя>`) — только владельцу с его ключом, во всех инструментах и при
  скачивании. Знание ссылки доступа не даёт; чужая загрузка отвечает так же, как несуществующая.
  id получается из содержимого, но проверить по нему наличие чужой загрузки нельзя. Чтобы показать
  картинку или шрифт читателям документа, владелец публикует файл через `files_publish` и использует
  полученную ссылку `artifact:`. Удаление исходной загрузки опубликованную копию не трогает.

Front matter (YAML в начале документа) доступен читателю в свёрнутом блоке «Свойства».
Комментарии `%%…%%` скрыты при чтении, но **не являются тайной**: они остаются в исходнике,
`project_read`, выгрузке и истории git и доступны всем с соответствующим правом чтения.
Для удаления сведений используйте стирание с историей, описанное ниже.

## Проекты

Модель проекта, [роли](projects.md#роли-и-права), приглашения и
[удаление/стирание](projects.md#передача-удаление-и-стирание) описаны на отдельной странице.
Статья живёт вместе с проектом; вклад и ресурсы в чужом проекте сохраняются после удаления
учётной записи автора. Дальше — подробности хранения для тех, кому нужны точные гарантии.

### Как устроено хранение

Проекты доступны с 27.10.2026: инструменты `projects`, `project_*` и `invitations` работают. Проект — приватный репозиторий движка с веткой `main`. В git хранятся статьи,
их пути, содержимое и история правок. Метаданные проекта (стабильный id, неизменный slug,
заголовок), участники и роли, журнал приглашений/ролей/передач и связи авторов с учётными
записями хранятся **в отдельном каталоге шлюза**, вне git. Их нельзя изменить правкой статьи.
Бинарные ресурсы (картинки, модели, любые файлы не `.md`) — тоже файлы проекта по путям: в git по пути
лежит указатель (хеш и размер), содержимое — в хранилище вложений, один раз на одинаковое содержимое.
Ресурс принадлежит проекту: удаление файлов или учётной записи автора его не трогает. Шлюз выдаёт
ресурс только по пути и только участнику проекта, проверяя роль и версию при каждом запросе (читатель —
только текущую версию), — подписанной ссылкой на несколько минут. **Выданную ссылку отозвать нельзя:
после исключения из проекта, понижения роли или удаления версии она действует до своего срока, не
дольше 15 минут.** Новую ссылку исключённый участник уже не получит.

Импорт `project_import` копирует только свой `/d` в проект одной новой версией вместе с доступными
ресурсами `artifact:`; исходный публичный документ и его история остаются прежними. Недоступные
ссылки сохраняются в тексте и перечисляются в ответе. Копии ресурсов принадлежат проекту,
удаление `/d`, публикации файла или учётной записи автора их не удаляет.

История ресурса — история указателей по его пути. Старую версию может удалить только
владелец проекта; текущую версию пути в `main` так удалить нельзя. История git остаётся,
но удалённая версия больше не выдаётся. Размер освобождается в проекте после удаления
последней его действующей ссылки на это содержимое: другая версия или путь сохраняют место.
Другой проект или старая версия опубликованного `/d` сохраняют само содержимое. Ссылка
`blob:` в `/d` удерживает объект, только если при сохранении автор документа владел этим
ключом; знание чужого хеша не создаёт держателя. После
последнего держателя физическая уборка ждёт срок сироты (по умолчанию 24 часа) и повторно
проверяет держателей. Сбой записи ресурса разбирает фоновая уборка: неподтверждённая загрузка
временно резервирует место, затем освобождается, если коммита нет.
Удаление версий записывается в реестр стираний (ниже); без реестра операция закрыта.

Автор и коммитер в git — случайная тень `u-…` с техническим адресом
`u-…@noreply.projects-engine`; настоящая почта и nickname туда не записываются.
Сообщения коммитов задаются шаблонами шлюза по операции и путям, свободного текста нет.
При показе истории шлюз находит текущее имя участника по отдельной связи. Журнал проекта
тоже ссылается на тени, без копий email/nickname; участников видят участники с правом записи,
журнал и email приглашений — владелец и админы.

Приглашение в проект действует 7 дней и хранит email адресата в отдельном каталоге шлюза. Открытие
ссылки не раскрывает email и название проекта и не добавляет участника. Принятое,
отклонённое или отозванное приглашение хранится ещё 30 дней после перехода в это
состояние; истёкшее — 30 дней после окончания срока. Затем фоновая уборка (раз в
час) удаляет email и всю запись приглашения. В журнале остаются события с тенями
и непрозрачным id приглашения, без email. При удалении учётной записи email её
приглашений стирается сразу, ожидающие отзываются.

Удаление связи тени с учётной записью меняет показ истории и журнала на «удалённый
участник», сохраняя вклад и прежние коммиты. **Содержимое статей, пути и даты коммитов
при этом остаются**. Не называйте статьи именами людей, если имя не должно оставаться
в истории. Владелец проекта может **стереть файлы с историей**: история переписывается без
этих путей (сообщения коммитов, где они упомянуты, заменяются), старые объекты git удаляются,
вместе с ними — снимки проверки, кеш результатов проекта и ресурсы, которые больше ничем в проекте
не удерживаются. Даты и авторы-тени коммитов и пути остальных файлов остаются. Ресурс с тем же
содержимым в другом проекте или в `/d` его автора сохраняется у них.

Стирания, удаления проектов, версий ресурсов и учётных записей записываются в **реестр стираний** —
журнал только для дописывания: номер, вид операции, id проекта или учётной записи, коммит и HMAC
путей; ни путей, ни содержимого, ни email. После восстановления шлюз применяет записи реестра до
открытия доступа. **Сейчас реестр временный: он лежит на той же машине, что и проекты**, и при
восстановлении сервера из резервной копии откатывается вместе с ней — стёртое после момента копии
вернётся. Перенос реестра на другой сервер запланирован; сейчас это ограничение сохраняется.

Резервные копии сервера хранятся по своему сроку: стёртое исчезает из действующей системы сразу
после соответствующей операции, из резервных копий — по окончании их срока хранения.

Снимки `render_check` с `project`, его `meta.json`, результаты тяжёлых блоков
принадлежат проекту и хранятся в `private:`. Шлюз проверяет текущую роль
и версию при скачивании с ключом и при выдаче каждой новой подписи. Читателю доступны
только снимки сохранённого текста текущей `main`; снимки несохранённых правок и старых
коммитов доступны редакторам, админам и владельцу. Удаление проекта и стирание удаляют
производные файлы и их кеш. Закрываются и стираются также сеансы ядер участников, помеченные
этим проектом: код, ответы инструментов, состояние и снимки. Сеанс стирается целиком, даже
если в нём смешаны данные нескольких проектов. Недоступный узел дочищается при возвращении;
до этого шлюз запрещает использование и восстановление сеанса. Служебные события сеансов на вычислительных узлах
с техническим идентификатором вызывающего и id сеанса хранятся до семи дней (уборка при старте и раз в час), при стирании
сеанса его события удаляются сразу. Записи одноразовых вычислительных заданий сохраняются целиком
90 дней для учёта использования сборок. Без `project` проверка остаётся
публичной: её снимки и `meta.json` доступны по ссылке `/artifacts/…`, если вызов не помечен проектом.

Результаты остальных инструментов из помеченного вызова (в том числе после `project_read` в Code Mode
и в фоновом задании) тоже принадлежат **проекту**, сохраняются в `private:` и удаляются при
удалении проекта и стирании. Результат читателя закрепляется за прочитанной головой `main`
и доступен читателям, пока она не сменилась. Если проект изменился во время расчёта — `409: …` в тексте ошибки инструмента (REST: HTTP 422)
с просьбой повторить. Прочитанная версия сохраняется в пометках ядра сеанса и файлов:
повторный вызов с прежними данными не заменяет её новой головой `main`. При смешении версий
или старой пометке без версии читателю нужно перечитать проект в новом сеансе и заново получить входные файлы.
Расчёты редактора, админа и владельца могут использовать историю
и черновики, поэтому читателям не выдаются; текущая роль и версия перепроверяются. Исключённый участник получает `404: …` в тексте ошибки инструмента (REST: HTTP 422);
при передаче своей помеченной загрузки инструменту — пояснение «файл связан с недоступными вам данными проекта».
Пометка общая для одинакового содержимого: совпадение видно владельцу такого же файла, даже загруженного независимо от проекта.
Если вызов использует несколько проектов, сохранение результата запрещено.
Публичной копии в `/artifacts` нет. `private:` читается с ключом; для открытия в браузере
получите подпись до 15 минут через `GET /api/v1/private/<id>/<имя>?sign=1` с ключом.
Кеш разделён по вызывающим и проектам и проверяет доступность файлов перед выдачей.

Запрет публикации из проекта наружу действует по пометкам: `files_publish` и
`document_share` отказывают вызову с пометкой проекта, в том числе полученной при чтении
загрузки или результата проекта либо по ссылкам на них внутри документа. Новую версию
существующего `/d` так записать тоже нельзя. Текст, вручную перенесённый моделью в
непомеченный вызов без помеченных ссылок, шлюз отличить от обычного текста не может.

Страницы проекта на сайте (`/p/…`) открываются только после входа кукой сайта: личное
пространство (свои проекты и приглашения), дерево и статьи текущей головы `main`, без истории и старых
версий. Права проверяются на каждый запрос страницы и каждой картинки статьи: после исключения следующий
запрос отвечает так же, как на несуществующий проект. Картинки и файлы статьи страница берёт у шлюза,
он отвечает переадресацией на подписанную ссылку хранилища — та же выдача, что у `project_read`.
Код блоков статьи на основном домене не исполняется: живые блоки — во фреймах `volkodlak.ru`, где кук нет.

Подписанные ссылки на закрытые файлы (результаты `private:`, ресурсы
проектов) действуют **до 15 минут** и не отзываются: после исключения из проекта, понижения
роли, удаления версии или стирания уже выданная ссылка работает до своего срока, новую шлюз
не выдаёт.

### Журнал вызовов и проекты

Вызовы `projects`, `project_*`, `invitations` и
`render_check` с `project` попадают в журнал **только служебными полями**: инструмент,
операция, id проекта, роль, коммиты, размеры, исход (`ok`), длительность, код ошибки, у
`render_check` — число замечаний по видам и правила без цитат. Тексты и пути статей, email,
nickname, slug и заголовок проекта, поле `task`, а также программа клиента (User-Agent),
присланный клиентом номер сессии и название своего набора инструментов из этих вызовов не
пишутся. Так же — только служебными полями — пишется выполнение Code Mode, код которого
обратился к проекту или прочёл сохранённый из проекта результат, и все его вложенные вызовы;
в долгом сеансе — все следующие выполнения в том же ядре до его закрытия. Пометка идёт и
дальше по следам: ядро другого сеанса, которому такой вызов передал данные, папка сессии
песочницы, результат, загрузка, опубликованный документ и результат фонового задания,
записанные им, помечают каждый вызов, который их потом прочтёт. Для этого шлюз хранит пустые
метки с номерами таких результатов, загрузок и документов (без владельца и содержимого); метка
удаляется вместе с загрузкой, опубликованной картинкой, документом и учётной записью. Готовый ответ из
кеша результатов помечает вызов так же, как новый расчёт. Остальные вызовы, в том числе
`render_check` без `project`, журналируются, как раньше.

**Кем подписана запись.** До 27.10.2026 09:53 UTC журнал был подписан номером учётной записи, который
вычисляется из адреса почты: зная адрес, его можно вычислить заново, так что это не
обезличивание. С этого момента запись подписана **случайным псевдонимом**, не связанным с
почтой; связь «псевдоним — учётная запись» хранится только в самой учётной записи и
удаляется вместе с ней. После удаления записи её вызовы остаются в журнале под псевдонимом,
по которому человека уже не найти.

**Граница перехода — 27.10.2026 09:53 UTC**.
Записи до этого момента не переписываются под псевдонимы: они перенесены в закрытый проект
владельца системы «Архив журнала до v1» (`pre-v1-journal`; читает только владелец системы)
и удалены из действующего журнала. В архиве они остаются под прежним номером из почты,
и удаление учётной записи их не обезличивает. Резервные копии сервера, снятые до переноса, хранят
прежний журнал до окончания своего срока (выше).

Чтобы уборка места по-прежнему берегла результаты владельца системы, на которые ссылались
перенесённые записи, перед их удалением из журнала шлюз сохранил **служебный индекс ссылок**:
время вызова, прежний номер учётной записи и номера результатов (`artifact:…`) — без текстов,
аргументов и ответов. Индекс лежит рядом с журналом на сервере шлюза и учитывается с тем же
окном, что и журнал (90 дней от вызова).

## Сколько хранится

Сейчас **альфа-тестирование**. Для проектов:

| Объект | Срок и удаление |
|---|---|
| Статьи, ресурсы и история | Пока жив проект; скрытие историю не стирает |
| Единоличный / совместный проект после `delete` | Сразу / 7 дней только чтения с письмом участникам; до срока возможны отмена или передача |
| Приглашение | 7 дней на принятие; ещё 30 дней после завершения/истечения, уборка раз в час |
| Подписанная ссылка | До 15 минут, выданную подпись нельзя отозвать |
