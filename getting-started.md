# Первые шаги

Spiridus — статьи и ресурсы в закрытых проектах. Модель пишет через [MCP](mcp.md),
скрипт — через [REST](api.md), человек читает на сайте после входа.

## 1. Зарегистрируйтесь

На `v2.spiridus.ru` сейчас регистрация **по приглашениям**. Попросите регистрационную ссылку
у владельца: [kscht@tutamail.com](mailto:kscht@tutamail.com), либо проектное приглашение у
админа проекта. Обычные `account_register` и `POST /api/v1/register` без приглашения закрыты;
скрипт `register.sh` предназначен для установок с открытой регистрацией.

Откройте `/invite/…` в браузере, укажите email и свободный nickname. Регистрационное приглашение
не добавляет в проект; проектное привязано к email адресата. Если запись уже есть, **войдите
существующим ключом**, не регистрируйтесь повторно: повторное подтверждение сменит основной ключ.
[Оба случая проектного приглашения](projects.md#приглашения-и-письма).

Nickname: 1–64 знака `A–Z`, `a–z`, `0–9`, внутри также `.`, `-`, `_`; начало и конец — буква
или цифра. Имя уникально без учёта регистра. Любое занятое имя даёт 409, даже для своего email.
Письмо приходит с `nobody@spiridus.ru`; ссылка подтверждения действует сутки. Проверьте «Спам».

## 2. Подтвердите почту и сохраните ключ

Откройте письмо, нажмите «Согласен, подтвердить». Основной ключ показывается **один раз**.
Сохраните его в менеджере паролей; для команд ниже задайте `SPIRIDUS_KEY` вне репозитория,
не вводя секрет в историю команд. Не отправляйте ключ в разговор с моделью.

Основной ключ бессрочный и имеет все права. Потеряли его или он утёк — обратитесь к владельцу
за действующим регистрационным приглашением для перевыпуска с тем же email и свободным nickname.
После подтверждения прежний основной ключ перестанет работать, nickname сохранится;
остальные ключи останутся, при утечке отзовите их отдельно.

**Где хранить ключ.** Ключ — как пароль: кто его знает, работает от вашего имени.

- Не вписывайте его в файлы проекта — `mcp.json`, `.mcp.json`, скрипты, документы: их легко
  закоммитить. В примерах ключ всегда берётся из переменной окружения `SPIRIDUS_KEY`.
- Переменную задавайте вне репозитория: в менеджере паролей, в настройках оболочки (`~/.zshrc`, если
  он не лежит в публичном репо dotfiles), в файле `.env`, который есть в `.gitignore`.
- Закоммитили по ошибке — считайте ключ утёкшим: отзовите его на странице «Ключи» (для замены основного обратитесь к владельцу системы).
  Удаление коммита из истории ключ не спасает — его могли уже скопировать.

Подтверждая, вы соглашаетесь с тем, как Spiridus обращается с данными: [data.md](data.md).

## 3. Войдите на сайт

Откройте [главную](https://v2.spiridus.ru/) или [«Проекты»](https://v2.spiridus.ru/p/), в форме входа
введите **основной** ключ. Сайт ставит куку `HttpOnly`; узкий ключ программы для такого входа не годится.
Выход — кнопка «выйти» (`POST /api/logout`). Проверьте доступ: увидите свои проекты и приглашения.

Для программы выдайте отдельный ключ на странице [«Ключи»](https://v2.spiridus.ru/api/keys), с правами
`mcp` или `rest`, при необходимости `files`, `docs`. [Сроки и ограничения](api.md#ключи).

## 4. Получите проект и подключите модель

Примите приглашение на странице подтверждения или в «Проектах». Если своего проекта нет,
попросите приглашение или право создания (по умолчанию до 10 своих проектов).
При выданном праве вызовите `projects({action:"create", slug:"atlas", title:"Атлас"})`.

Для статей подключите `/mcp/p/projects`:

```sh
claude mcp add --transport http spiridus https://v2.spiridus.ru/mcp/p/projects \
  --header "Authorization: Bearer $SPIRIDUS_KEY"
```

Если модель уверенно пишет JavaScript/Python, можно выбрать `/mcp/code`. В `/mcp/lite`
есть справка и проверка, но новую статью там не сохранить. [Выбор адреса](mcp.md#выбор-адреса).
Ожидаемый результат: `projects({})` возвращает ваш проект и роль.

## 5. Запишите и проверьте статью

Попросите модель прочитать `render_block_docs({lang:"markdown"})` и дерево через
`project_read({project:"atlas", op:"tree"})`, затем записать статью через `project_write`.
`base` — `commit` прочитанного дерева; у пустого проекта `null`:

```json
{"project":"atlas","base":null,"files":[{"path":"Начало.md","content":"# Начало\n\nПервая статья.\n"}]}
```

После записи — `render_check({project:"atlas", path:"Начало.md", shots:"none"})`.
`built` означает сборку блоков, `clean` — также успех сценариев; для замечаний оформления задайте
`strict:["warning","layout"]`. Ожидаемый результат — проверенная статья с `url` для участника.
Снимки без `project` публичны по ссылке. [Запись, ресурсы и рецепт конфликта](projects.md#записать-и-проверить-статью).
Готовые блоки песочниц с `artifact:` в проект пока не вставляются; картинки сохраняйте ресурсами.

## 6. Пригласите коллегу

Owner/admin вызывает `invitations({project:"atlas", action:"invite", email:"colleague@example.com",
role:"reader"})` и даёт ссылку статьи `/p/atlas/Начало.md`. Коллега получает письмо на 7 дней,
входит или регистрируется, затем **явно принимает** приглашение. Ожидаемый результат — статья
открывается ему после входа. [Что увидит адресат](projects.md#приглашения-и-письма).

Полный путь скриптом — [project.sh](examples/project.sh). Прежний `/d` переносится через
`project_import`; учтите [предупреждение о 7 днях простоя без письма](projects.md#прежние-документы-d).
