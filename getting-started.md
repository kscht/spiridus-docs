# Первые шаги

Spiridus рисует наглядные блоки в документах Markdown — диаграммы, схемы, формулы, модели, ноты — и
проверяет, что получилось. Работать с ним можно двумя путями, по одному ключу:

- **MCP** — подключить к своей модели (Claude Code, Cursor, любой клиент MCP), она сама вызывает
  инструменты: справку по блокам, примеры, проверку `render_check`, песочницы. Подробнее — [mcp.md](mcp.md).
- **REST API** — обычные HTTP-запросы: из скрипта, из своей программы, из модели без MCP.
  Подробнее — [api.md](api.md).

## 1. Зарегистрируйтесь

```sh
curl -sS -X POST https://v2.spiridus.ru/api/v1/register \
  -H 'content-type: application/json' \
  -d '{"email": "you@example.com"}'
```

Или скриптом: [`examples/register.sh`](examples/register.sh) `you@example.com`.

Ответ всегда один и тот же — «если адрес верный, на него ушло письмо». Письмо придёт с
`nobody@spiridus.ru` (загляните в «Спам»); ссылка в нём действует сутки.

## 2. Подтвердите и сохраните ключ

Откройте ссылку из письма в браузере и нажмите **«Согласен, подтвердить»** — страница покажет ключ
вида `sp_…`. Он виден **один раз**: сохраните его, например в переменную окружения:

```sh
export SPIRIDUS_KEY=sp_...
```

Потеряли ключ или он утёк — зарегистрируйтесь той же почтой ещё раз: придёт новый, старый перестанет
работать.

Подтверждая, вы соглашаетесь с тем, как Spiridus обращается с данными: [data.md](data.md).

## 3. Проверьте, что ключ работает

```sh
curl -sS https://v2.spiridus.ru/api/v1/me -H "Authorization: Bearer $SPIRIDUS_KEY"
```

## 4. Первый вызов: нарисовать и проверить документ

`render_check` рисует документ так же, как его увидит читатель, и возвращает замечания: блок не
собрался, подписи налезают друг на друга, рисунок шире колонки, опечатки в тексте.

```sh
curl -sS -X POST https://v2.spiridus.ru/api/v1/tools/render_check \
  -H "Authorization: Bearer $SPIRIDUS_KEY" -H 'content-type: application/json' \
  -d '{"markdown": "# Проба\n\n```mermaid\nflowchart LR\n  Идея --> Черновик --> Проверка\n```\n", "shots": "none"}'
```

В ответе `data.clean` — `true`, если замечаний нет, и список `data.issues` со строкой и пояснением.
