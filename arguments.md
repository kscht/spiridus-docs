# Аргументы инструментов

Что принимает каждый инструмент — одинаково в MCP (`tools/call`) и в REST
(`POST /api/v1/tools/<имя>`, тело — JSON с этими полями). Машинное описание тех же схем —
`GET /api/v1/tools` и `/api/v1/openapi.json`; зачем какой инструмент — [tools.md](tools.md), лимиты,
время работы и ответы — [api.md](api.md).

Каталоги MCP и REST различаются: `tools`, `account_register`, `account_delete`, `keys_list` и
`key_revoke` вызываются через MCP; в REST для регистрации, учётной записи и ключей — отдельные адреса.
Тип ссылки перечисляет префиксы входной схемы; ограничения конкретного обработчика — в описании.

У всех инструментов есть ещё необязательный `task` — 2–3 предложения: какую просьбу пользователя
выполняет вызов. Он пишется в журнал (см. [data.md](data.md)) и на результат не влияет.

У инструментов песочниц `build` — сборка программы (версия и набор модулей): список — `sandbox_builds`,
как устроены сборки — [blocks/sandbox.md](blocks/sandbox.md). Без `build` — сборка по умолчанию.
Ссылки `artifact:<id>/<файл>` — результат прошлого вызова, `upload:<id>/<файл>` — свой загруженный файл
([api.md](api.md#свои-файлы)).


## Проекты

### `projects` — Мои проекты

Проекты, где вы участник (с ролью), ваши ожидающие приглашения и предложения передать вам владение. action: "create" со slug (латиница, цифры, дефис; неизменен) и title создаёт проект — нужно право создавать проекты от владельца системы. Работа внутри проекта — пресет /mcp/p/projects: project_read, project_write и другие.

| Аргумент | Обязателен | Тип | Что |
|---|---|---|---|
| `action` |  | `list`, `create` | list — по умолчанию; create — новый проект |
| `slug` |  | строка до 80 знаков | для create: адрес проекта, a-z0-9 и дефис, неизменен |
| `title` |  | строка до 200 знаков | для create: заголовок, его можно переименовать |

### `project_read` — Прочитать проект

Дерево папок и статей проекта (op: "tree", по умолчанию; ресурсы — resource: true), статью или её раздел/блок (op: "read", path, fragment), ссылки и обратные ссылки (op: "links", path; только голова) или историю правок (op: "history"). read ресурса (не .md) — подписанная ссылка url до 15 минут, не публикуйте её (из code_run — без url); "versions" — версии ресурса по path. commit ответа — base для project_write. version — хеш старой версии; истории и старых версий у читателя нет. path принимает /p/<slug>/<путь>#…; fragment отдельно — URL-форма раздела или ^id. Ответ статьи содержит url; замечания разрешения — warnings. Статьи проверяйте render_check с теми же project и path.

| Аргумент | Обязателен | Тип | Что |
|---|---|---|---|
| `project` | да | строка до 80 знаков | slug или id проекта (p-…) |
| `op` |  | `tree`, `read`, `links`, `history`, `versions` | tree — дерево, read — статья или ресурс, links — ссылки статьи в голове, history — история, versions — версии ресурса |
| `path` |  | строка до 4000 знаков | путь статьи/ресурса или адрес /p/<slug>/<путь>#… |
| `fragment` |  | строка до 4000 знаков | для read статьи: раздел (Глава#Детали), слаг или ^id блока; URL-форма, без начального # |
| `version` |  | строка `^(?:[a-f0-9]{40}\|[a-f0-9]{64})$` | хеш версии вместо головы main; не для читателя |

### `project_write` — Записать в проект

Один коммит в main проекта. Если все файлы совпадают, коммита нет: unchanged: true, commit и base — текущая голова. base — commit из project_read (null — пустой проект); после base изменились пути записи или исчезли цели ссылок статьи — 409 с текущим commit: перечитайте. op "put" — files [{path, content}] создать или заменить статьи .md; ресурс (не .md, до 12 МБ) — один файл {path, base64} или {path, ref: свой "upload:…", "artifact:…" из files_publish или "private:…" расчёта с этим проектом}, в статье — относительная ссылка ![]\(media/x.png); "move" — from → to (ссылки статей на этот путь шлюз правит сам, у статьи — и её ссылки от нового места); "restore" — paths статей из version; "delete" — ресурс paths[0] (на него не должны ссылаться статьи); "copy" — ресурс from из проекта source (по умолчанию этот) и version в to. Ответ: url (для пакета — корень проекта), urls по путям; put — warnings о пропавших якорях и смене цели, сгруппированные по фрагменту. Сообщение и автора коммита задаёт шлюз.

| Аргумент | Обязателен | Тип | Что |
|---|---|---|---|
| `project` | да | строка до 80 знаков | slug или id проекта (p-…) |
| `base` | да | строка `^(?:[a-f0-9]{40}\|[a-f0-9]{64})$` или любое | commit, от которого сделана правка; null — первый коммит |
| `op` |  | `put`, `move`, `restore`, `delete`, `copy` | put — по умолчанию |
| `files` |  | массив до 5000: объект { path, content, base64, ref } | для put: статьи .md с content или один ресурс с base64 или ref (upload:, artifact:, private: этого проекта) |
| `files[].path` | да | строка до 500 знаков |  |
| `files[].content` |  | строка |  |
| `files[].base64` |  | строка |  |
| `files[].ref` |  | строка до 300 знаков |  |
| `from` |  | строка до 500 знаков | для move и copy: прежний путь |
| `to` |  | строка до 500 знаков | для move и copy: новый путь |
| `paths` |  | массив до 50: строка до 500 знаков | для restore: пути, до 50; для delete: один ресурс |
| `version` |  | строка `^(?:[a-f0-9]{40}\|[a-f0-9]{64})$` | для restore и copy: хеш версии источника |
| `source` |  | строка до 80 знаков | для copy: проект источника |

### `project_import` — Импортировать свой документ в проект

Скопировать последнюю версию своего /d/<id> в новую статью path проекта одним коммитом от вашего имени. Чужой /d и занятый путь — отказ. Публичные artifact: в ссылках статьи переносятся ресурсами media/<имя> (при совпадении — суффикс), ссылки переписываются относительно статьи. В блоках/коде artifact: не переносятся и не переписываются. Оставленные ссылки — unavailable [{ref, reason}]; они блокируют render_check и запись статьи: уберите или замените ссылки из unavailable. Исходный /d не меняется. Доступно из Code Mode.

| Аргумент | Обязателен | Тип | Что |
|---|---|---|---|
| `project` | да | строка до 80 знаков | slug или id проекта (p-…) |
| `id` | да | строка `^[\w-]{22}$` | id своего /d/<id> |
| `path` | да | строка до 500 знаков | новый путь статьи .md |

### `project_hide` — Скрыть статьи проекта

Убрать статьи из main одним коммитом: в истории они остаются, вернуть — project_write op "restore" с прежней version. base — commit из project_read. brokenLinks — ссылки из оставшихся статей, сгруппированные по источнику, цели и фрагменту; скрытие не блокируют. Вызывайте, только если пользователь попросил убрать статьи.

| Аргумент | Обязателен | Тип | Что |
|---|---|---|---|
| `project` | да | строка до 80 знаков | slug или id проекта (p-…) |
| `base` | да | строка `^(?:[a-f0-9]{40}\|[a-f0-9]{64})$` | commit, от которого сделана правка |
| `paths` | да | массив до 200: строка до 500 знаков | пути статей |

### `project_members` — Участники проекта

Участники и роли (action "list"); "role" — сменить роль участника (member, role); "remove" — исключить; "leave" — выйти самому (владелец — сначала передача); "journal" — журнал проекта: приглашения, роли, передачи (владелец и админ). Владельца нельзя исключить или понизить.

| Аргумент | Обязателен | Тип | Что |
|---|---|---|---|
| `project` | да | строка до 80 знаков | slug или id проекта (p-…) |
| `action` |  | `list`, `role`, `remove`, `leave`, `journal` | list — по умолчанию |
| `member` |  | строка `^u-[a-f0-9]{24}$` | участник: shadow из project_members |
| `role` |  | `admin`, `editor`, `reader` | для role: новая роль |

### `invitations` — Приглашения в проекты

Свои приглашения (action "list") и ответ на них: "accept" или "decline" по id — только по просьбе приглашённого. С project: "list" — приглашения проекта, "invite" — пригласить по email с role, "revoke" — отозвать по id (владелец и админ). Ответ на invite одинаков, есть ли такой адрес.

| Аргумент | Обязателен | Тип | Что |
|---|---|---|---|
| `action` |  | `list`, `accept`, `decline`, `invite`, `revoke` | list — по умолчанию |
| `project` |  | строка до 80 знаков | slug или id проекта (p-…) |
| `id` |  | строка `^[a-f0-9]{64}$` | приглашение из list |
| `email` |  | строка до 254 знаков | для invite: email адресата |
| `role` |  | `admin`, `editor`, `reader` | для invite: роль |

### `project_admin` — Управление проектом

Действия владельца и админа; confirm — slug проекта, без него ничего не меняется. rename (title); transfer — предложить владение участнику member, cancel_transfer, accept_transfer — принять предложение id из projects; delete — удалить (с участниками — 7 дней только чтение), cancel_delete; erase — стереть пути paths со всей историей (только владелец); delete_versions — удалить старую версию ресурса (path и version из project_read op "versions"; только владелец, последнюю версию в main нельзя). Только по явной просьбе пользователя.

| Аргумент | Обязателен | Тип | Что |
|---|---|---|---|
| `project` | да | строка до 80 знаков | slug или id проекта (p-…) |
| `action` | да | `rename`, `transfer`, `cancel_transfer`, `accept_transfer`, `delete`, `cancel_delete`, `erase`, `delete_versions` |  |
| `confirm` | да | строка до 80 знаков | slug проекта — подтверждение |
| `title` |  | строка до 200 знаков | для rename: новый заголовок |
| `member` |  | строка `^u-[a-f0-9]{24}$` | для transfer: будущий владелец (shadow) |
| `id` |  | строка до 128 знаков | для accept_transfer: id предложения из projects |
| `paths` |  | массив до 5000: строка до 500 знаков | для erase: пути, которые нужно стереть во всей истории |
| `path` |  | строка до 500 знаков | для delete_versions: путь ресурса |
| `version` |  | строка `^(?:[a-f0-9]{40}\|[a-f0-9]{64})$` | для delete_versions: версия ресурса из project_read op "versions" |

## Учётная запись и ключи

### `account_register` — Регистрация в Spiridus

Отправить письмо подтверждения email. Обязателен nickname: 1–64 ASCII знака, буква или цифра по краям, внутри также . _ -. Ключ показывается только человеку на странице подтверждения; не просите присылать его в разговор.

| Аргумент | Обязателен | Тип | Что |
|---|---|---|---|
| `email` | да | строка до 254 знаков |  |
| `nickname` | да | строка до 64 знаков |  |

### `account_delete` — Удалить свою учётную запись

Удалить учётную запись Spiridus, её ключи, сайты, загрузки, приватные результаты и опубликованные документы (ссылки /d/… перестанут открываться). Вызывайте, только если пользователь сам прямо попросил удалить регистрацию. В confirm — почта учётной записи, как подтверждение. Ключи после этого перестают работать сразу; нужен основной ключ. Единоличные проекты удаляются с историей, вклад в чужие обезличивается, их ресурсы сохраняются. При совместном проекте — 409 до передачи владения или конца семи дней удаления; без обязательных обработчиков или подтверждения реестра стираний — 503. Успешный ответ включает projectsDeleted.

| Аргумент | Обязателен | Тип | Что |
|---|---|---|---|
| `confirm` | да | строка до 254 знаков | почта учётной записи — подтверждение, что удалить нужно именно её |

### `keys_list` — Мои ключи

Ключи своей учётной записи без секретов: имя, начало ключа, права, адреса, срок, последнее использование; current — ключ этого клиента. Чужие lastIp — только основным ключом. Новый ключ — только человек на https://v2.spiridus.ru/api/keys.

Без аргументов.

### `key_revoke` — Отозвать ключ

Отозвать свой ключ: which — id из keys_list, others — все, кроме ключа этого клиента, all — все сразу (при утечке; новый основной ключ — повторной регистрацией). Узкий ключ отзывает только себя; другие ключи, others и all — только основным ключом. Действует сразу; открытые этим ключом сеансы ядер закрываются (занятые — после текущего шага, недоступные — после восстановления связи). Вызывайте только по просьбе пользователя.

| Аргумент | Обязателен | Тип | Что |
|---|---|---|---|
| `which` | да | строка до 20 знаков | id ключа (k-…), others или all |

### `sandbox_builds` — Сборки песочниц

Какие сборки есть у песочниц (render.check — Chromium, blender.run — Blender, и песочницы нотаций: cad.run — FreeCAD, modelica.run — OpenModelica, plantuml.run — PlantUML, structurizr.run — Structurizr …): версия программы, модули и плагины, состояние (default — по умолчанию, stable, next — новая на пробу, deprecated — устаревшая, с датой отключения sunset), план replaces и проверенная замена replacedBy. Вызов имени с replacedBy исполняется на новой сборке и возвращает replaced: {from, to}; строка build документа сама не меняется. У одной версии бывает несколько вариантов — разный набор верстаков и плагинов, другие опции компиляции: имя сборки — программа-версия[-вариант] (freecad-1.1.4, text-2026.10-openblas). Фильтр: program, version, module — подстрока в названии модуля (верстака, библиотеки). Сборку называют параметром build у инструментов песочниц (cad_run, modelica_run, blender_run, plantuml_run, text_parse…) и строкой build: в блоке документа; в ответе каждого из них build — фактическая сборка, в которой посчитано.

| Аргумент | Обязателен | Тип | Что |
|---|---|---|---|
| `program` |  | строка до 40 знаков | FreeCAD, OpenModelica, Blender |
| `version` |  | строка до 40 знаков | версия, например 1.1.4 |
| `module` |  | строка до 60 знаков | модуль, верстак или плагин: FEM, Cycles, Modelica… |

## Проверка

### `render_check` — Проверить документ

После проверки покажите Markdown с блоками; preview — снимок для показа картинкой. Документ — в аргументе markdown (не document, не text): весь Markdown одной строкой, например { "markdown": "# Заголовок\n\n```mermaid\nflowchart LR\n  A --> B\n```\n" }. Отрисовать документ (Markdown с блоками) тем же рендером, что у читателя, в headless Chromium в песочнице и вернуть замечания: какие блоки не собрались и почему (с номером строки в исходнике), какие рисунки шире колонки или ужаты так, что мелко читать, формулы с ошибкой, картинки, которых нет в пакете, ошибки консоли. Проверка — при нескольких ширинах (по умолчанию 760 — компьютер и 390 — телефон). Снимки проблемных блоков приходят картинками в ответе; ошибки консоли фреймов запускателя — в frameConsole. Живые блоки (подсказки графика, кнопки, легенда, вращение 3D, запуск Python) проверяются сценариями interact: щелчки, наведение, касания, колесо, клавиши, ввод, чтение текста и снимки после шагов. Вызывайте после того, как написали или поправили документ, и исправляйте по замечаниям. В ответе: built — блоки собраны; clean — собраны, шаги interact выполнены и нет замечаний из strict (по умолчанию замечания к оформлению и тексту clean не меняют); kind: "check-off" — пояснение отключённой общей проверки с причиной; оно не влияет на totals, built, clean и выбор снимков. totals — замечания по видам (error, warning, layout, text, lint) и шаги сценариев; verdict — итог одной фразой («блоки собраны; 4 замечания к оформлению; не выполнено шагов сценария: 1 из 3») — его и пересказывайте пользователю; строгая приёмка — strict: ["warning", "layout"]. Повторная проверка: brief: true; большой документ — markdown_file (загрузить через files_upload или REST POST /api/v1/files). private: читается по ключу; для браузера получите подпись GET /api/v1/private/<id>/<имя>?sign=1 с ключом.
