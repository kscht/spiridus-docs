# Аргументы инструментов

Здесь приведена **полная схема аргументов обработчика**. В REST
(`POST /api/v1/tools/<имя>`, тело — JSON) используется эта схема; внешние каталоги MCP
могут её сокращать. Машинное описание полных REST-схем —
`GET /api/v1/tools` и `/api/v1/openapi.json`; зачем какой инструмент — [tools.md](tools.md), лимиты,
время работы и ответы — [api.md](api.md).

Каталоги MCP и REST различаются: `search` (Code Mode), `tools`, `account_register`, `account_delete`, `keys_list` и
`key_revoke` вызываются через MCP; в REST для регистрации, учётной записи и ключей — отдельные адреса.
| Вход | Видимая схема | Проверка вызова |
|---|---|---|
| REST | Полная, для доступных REST-инструментов | Полная |
| MCP `/mcp` и предметные пресеты | Сокращённые описания, `interact` у `render_check` и часть полей загрузки | Полная исходная схема |
| MCP `/mcp/lite`, `/mcp/p/docs` | Только обязательные поля и разрешённые дополнительные; сокращённые описания | Полная; у `render_check` по умолчанию `brief:true, shots:"page"` |
| MCP `/mcp/code` | `search` и `execute` (внутренний `code_run`); сокращены ограничения и описания | Полная; вложенные `tools.*` проверяют свои полные схемы |

Точный список lite — [контракты](contracts.md#каталог-mcp-lite).
Справка описывает возможности текущей версии исходников; доступность на конкретном сервере
подтверждают отдельно перед публикацией. Матрица флагов и профилей — [каталог](public-catalog.md).
В сценарии сборки справки включены ядра сеансов, выпуск проектов, поиск, комментарии, предложения и публичные сайты. Это не свидетельство включения возможностей на конкретной установке.
`project_search` доступен **только при `PROJECT_SEARCH_ENABLED=1`**; при выключенном флаге
его нет в REST/OpenAPI и MCP. Фактический каталог смотрите на своём сервере.
Тип ссылки перечисляет префиксы входной схемы; ограничения конкретного обработчика — в описании.

У обычных предметных инструментов есть ещё необязательный `task` — 2–3 предложения: какую просьбу пользователя
выполняет вызов. В обычном вызове он пишется в журнал, но в проектном не сохраняется
(см. [data.md](data.md)); на результат не влияет. У регистрации и управления ключами свой контракт.

У инструментов песочниц `build` — сборка программы (версия и набор модулей): список — `sandbox_builds`,
как устроены сборки — [blocks/sandbox.md](blocks/sandbox.md). Без `build` — сборка по умолчанию.
Ссылки `artifact:<id>/<файл>` — результат прошлого вызова, `upload:<id>/<файл>` — свой загруженный файл
([api.md](api.md#свои-файлы)).

### `project_read` — Прочитать проект

Темы spiridus/theme.json и spiridus/theme.public.json в папках: read возвращает текст JSON в content без URL/ref; дерево помечает theme: true. Дерево папок и статей проекта (op: "tree", по умолчанию; ресурсы — resource: true), статью или её раздел/блок (op: "read", path, fragment), ссылки и обратные ссылки (op: "links", path; только голова) или историю правок (op: "history"). read ресурса (не .md) — подписанная ссылка url до 15 минут, не публикуйте её (из code_run — без url); "versions" — версии ресурса по path. commit ответа — base для project_write. version — хеш старой версии; истории и старых версий у читателя нет. path принимает /p/<slug>/<путь>#…; fragment отдельно — URL-форма раздела или ^id. Ответ статьи содержит url; замечания разрешения — warnings. У links — count и truncated. op properties — свойства и GFM-прогресс полного разрешённого снимка (за флагом), до фильтров представления. Статьи проверяйте render_check с теми же project и path. op visibility — текущие свойства видимости статьи path или папки folder (пустая строка — корень): explicit, effective/source, policyCommit, published и предупреждения; для участников, без version и гостевого доступа.

| Аргумент | Обязателен | Тип | Что |
|---|---|---|---|
| `project` | да | строка до 80 знаков | slug или id проекта (p-…) |
| `op` |  | `tree`, `read`, `links`, `history`, `versions`, `properties`, `visibility` | tree — дерево, read — статья или ресурс, links — ссылки статьи в голове, history — история, versions — версии ресурса; visibility — видимость с источником для участника, за PUBLIC_SITES_ENABLED |
| `path` |  | строка до 4000 знаков | путь статьи/ресурса или адрес /p/<slug>/<путь>#… |
| `folder` |  | строка до 500 знаков | Только visibility: папка; пустая строка — корень, вместо path |
| `fragment` |  | строка до 4000 знаков | для read статьи: раздел (Глава#Детали), слаг или ^id блока; URL-форма, без начального # |
| `version` |  | строка `^(?:[a-f0-9]{40}\|[a-f0-9]{64})$` | хеш версии вместо головы main; не для читателя |
| `view` |  | `published`, `accepted`, `markup` | выгрузка: как опубликовано (по умолчанию), всё принято или с разметкой; два последних — editor+ |
| `clean` |  | `true` / `false` | удалить скрытые служебные пометки из выгрузки |
| `result` |  | `auto`, `ref` | только Code Mode: ref всегда возвращает private: JSON независимо от размера; tools.read(ref, {pointer:"/content"}) читает статью, cursor продолжает выборку; auto — прежний порог 16 КиБ |

### `project_stats` — Статистика публичного сайта

Статистика публичного сайта: read — дневные счётчики статей отдельно для людей и роботов; только текущий владелец проекта. settings с enabled включает или выключает сбор проекта; по умолчанию выключен. from/to — дни UTC последних 90 дней. collect для проекта stat — только служебной учётной записи stat-bot: дневной сборщик и обновление закрытых отчётов. Отключение сохраняет историю до срока; стирание статей/проекта удаляет производные по 0049. Из Code Mode недоступно.

**Условная доступность: `USAGE_STATS_ENABLED=1` либо сохранённая конфигурация `USAGE_STATS_BOT_ACCOUNT` для уборки после выключения.**

| Аргумент | Обязателен | Тип | Что |
|---|---|---|---|
| `project` | да | строка до 80 знаков | slug или id проекта (p-…) |
| `action` |  | `read`, `settings`, `collect` | По умолчанию: "read". |
