# MCP

Сервер MCP Spiridus — `https://v2.spiridus.ru/mcp` (Streamable HTTP). Ключ — тот же, что для REST API
([getting-started.md](getting-started.md)), в заголовке `Authorization: Bearer sp_...`.

Без ключа сервер показывает только `account_register`, но на `v2.spiridus.ru` сейчас
регистрация по приглашениям: начните со ссылки от владельца или админа проекта.
[Регистрация и вход на сайт](getting-started.md#1-зарегистрируйтесь).

Для MCP-клиента лучше выдать отдельный ключ с правом `mcp` (и, по желанию, только с вашего адреса) — на
странице [«Ключи»](https://v2.spiridus.ru/api/keys); права, срок и адреса ключей — [api.md](api.md#ключи).
Ключ без права `mcp` получает 403, с чужого адреса — 401 «ключ не действует с этого адреса»; права `files`
и `docs` нужны и инструментам `files_*`, `document_*` — в том числе вызванным из `code_run`. В ядре `/mcp` есть `keys_list` (свои ключи без секретов) и `key_revoke`
(`which`: id ключа, `others` или `all`) — список и отзыв. В `/mcp/code` и `/mcp/lite` их нет. Узкий ключ видит только свой `lastIp` и отзывает только себя по id; чужие адреса и отзыв другого
ключа, `others` и `all` доступны только основному ключу. Нового ключа через MCP нет: его видит только
человек на странице.

## Как уточнить поиск похожих инструментов

В `search` называйте нужную операцию и её вход: статический синтаксис, отрисовку в Chromium,
правку статьи или импорт своего `/d`. Справка раскрывается отдельно через `render_block_docs`.

| Задача | Инструмент |
|---|---|
| Найти синтаксические ошибки исходника линтером | `lint_check` |
| Проверить раскладку, подписи и действия читателя в отрисованном документе | `render_check` |
| Создать или обновить статью, переместить либо восстановить файл проекта с `base` | `project_write` |
| Скопировать свой опубликованный `/d` с ресурсами в свободный путь `.md` проекта | `project_import` |
| Прочитать синтаксис, ограничения и примеры кода языка блока | `render_block_docs` |
| Подобрать готовый анатомический контур или карту из пакета shapes для ECharts | `render_shapes` |

Одноразовый сценарий FreeCAD — `cad_run`, изменение параметров готовой FCStd без сценария —
`cad_recompute`, работа с переменными одного интерпретатора — `cad_session_open` → `cad_exec`.
У QElectroTech `qet_run` строит схему из операций, `qet_tools` описывает внутренние инструменты,
`qet_call` вызывает их в папке сеанса, `qet_save` сохраняет его файлы для документа.
Это разные этапы работы. У `qet_run` входной файл задаёт `qet_project`, а `project` —
проект Spiridus, в котором сохраняется результат. Старые вызовы с файлом в `project` совместимы.
Подробности: [проверка](check.md), [FreeCAD](blocks/freecad.md), [QElectroTech](blocks/qet.md),
[проекты](projects.md). Короткий каталог сохраняет назначение и ограничения, рецепты — в справке.

## Подключить

**Claude Code:**

```sh
claude mcp add --transport http spiridus https://v2.spiridus.ru/mcp/p/projects \
  --header "Authorization: Bearer $SPIRIDUS_KEY"
```

Ключ сохранится в ваших настройках Claude Code (`~/.claude.json`), не в проекте. Не добавляйте с
`--scope project`: тогда он попадёт в `.mcp.json` в папке проекта и легко уйдёт в git. Если сервер нужен
в общем `.mcp.json` проекта — только с подстановкой из окружения: `"Authorization": "Bearer ${SPIRIDUS_KEY}"`.

**Claude Messages API, MCP connector.** Для пресета `/mcp/p/diagrams` можно включить серверный tool search
и отложенную загрузку схем. MCP connector требует beta `mcp-client-2025-11-20`: передайте её в `anthropic-beta`
или как `betas: ["mcp-client-2025-11-20"]` в SDK. `authorization_token` передавайте только со своего сервера:

```json
{
  "mcp_servers": [{
    "type": "url",
    "name": "spiridus",
    "url": "https://v2.spiridus.ru/mcp/p/diagrams",
    "authorization_token": "${SPIRIDUS_KEY}"
  }],
  "tools": [
    { "type": "tool_search_tool_bm25_20251119", "name": "tool_search_tool_bm25" },
    {
      "type": "mcp_toolset",
      "mcp_server_name": "spiridus",
      "default_config": { "defer_loading": true }
    }
  ]
}
```

**OpenAI Agents SDK.** Если нужна только часть ядра или пресета, отфильтруйте каталог на стороне клиента:

```js
import { MCPServerStreamableHttp, createMCPToolStaticFilter } from "@openai/agents";

const spiridus = new MCPServerStreamableHttp({
  url: "https://v2.spiridus.ru/mcp/p/projects",
  requestInit: { headers: { Authorization: `Bearer ${process.env.SPIRIDUS_KEY}` } },
  toolFilter: createMCPToolStaticFilter({
    allowed: ["render_block_docs", "render_check", "project_read", "project_write"]
  })
});
```

`toolFilter` сокращает набор, видимый модели, но не заменяет авторизацию на сервере.

**Cursor, Windsurf и другие клиенты с файлом настроек** (`mcp.json`) — ключ не вписывайте в файл,
подставляйте из переменной окружения; в Cursor это `${env:ИМЯ}`:

```json
{
  "mcpServers": {
    "spiridus": {
      "url": "https://v2.spiridus.ru/mcp/p/projects",
      "headers": { "Authorization": "Bearer ${env:SPIRIDUS_KEY}" }
    }
  }
}
```

Как пишется подстановка в вашем клиенте — смотрите его документацию. Если клиент её не умеет и ключ
приходится вписать в файл — держите этот файл вне проекта (в настройках пользователя, а не в
`.cursor/mcp.json` репозитория) или добавьте его в `.gitignore`.

**Open WebUI** — двумя путями:

- как сервер инструментов OpenAPI (Settings → Tools / Tool Servers): URL `https://v2.spiridus.ru`,
  спецификация `api/v1/openapi-chat.json` (только инструменты модели; полная — `api/v1/openapi.json`),
  авторизация Bearer — ваш ключ. Каждый инструмент
  Spiridus станет инструментом модели; удобнее, если модели нужны асинхронные задачи;
- как сервер MCP (Streamable HTTP), если ваша версия Open WebUI это умеет: адрес `https://v2.spiridus.ru/mcp`
  и тот же ключ.

Open WebUI часто зовёт инструменты прямо из браузера — тогда добавьте адрес своего Open WebUI к
учётной записи: [api.md](api.md#вызовы-из-браузера-свой-сайт). Модели — любые с вызовом функций (Qwen3,
Llama, Mistral, DeepSeek, gpt-oss…); у мелких лучше включить «Native» function calling.

**Модель без зрения** (только текст): добавьте к адресу `?images=0` — `https://v2.spiridus.ru/mcp?images=0`
(или заголовок `X-Spiridus-Images: off`). Картинки из ответов выпадают, ссылки на них в тексте
остаются: так не тратятся токены на то, чего модель не увидит, и не ломаются клиенты, которые
картинки в ответе инструмента не принимают.

**Новые инструменты и параметры.** Список инструментов клиент берёт при подключении и запоминает.
Когда в Spiridus появляется новое (инструмент, параметр), клиент увидит его после переподключения: в
Claude Code — `/mcp`, выбрать `spiridus` и «Reconnect» (или перезапустить), в других клиентах —
перезапустить или переподключить сервер. REST (`GET /api/v1/tools`) всегда отдаёт текущий список.

**Модель не видит инструмента.** `/mcp` отдаёт только ядро: инструменты нотаций (`cad_run`,
`plantuml_run` …) — в пресетах, подключите адрес нужного (`/mcp/p/cad`, список — в `instructions` `/mcp`)
или зовите через `code_run`. REST отдаёт все инструменты, поэтому сверка с ним годится только для
инструментов ядра (чаще всего — `render_check`). Каталог отдаётся одним списком, без страниц
(`nextCursor` нет); проверить, что сервер отдаёт вам:

```sh
curl -s https://v2.spiridus.ru/api/v1/tools -H "Authorization: Bearer $SPIRIDUS_KEY" | grep -o '"render_check"'
```

Если там он есть, а у модели нет — его отсёк клиент: старый список (переподключите сервер, см. выше),
предел числа инструментов на все серверы вместе (есть у некоторых клиентов; отключите лишние
серверы), фильтр инструментов в настройках подключения или выбор «только часть инструментов».
Пока клиент не починен, тот же инструмент зовётся через REST: `POST /api/v1/tools/render_check` с
теми же аргументами ([api.md](api.md)). Модель, которой нечем проверить документ, должна сказать
об этом пользователю, а не писать «проверено».

Клиенты только с локальным stdio подключаются через мост:
`npx mcp-remote https://v2.spiridus.ru/mcp --header "Authorization: Bearer $SPIRIDUS_KEY"`.

## Выбор адреса

Пишете статьи — выбирайте **`/mcp/p/projects`**. Если модель уверенно пишет JavaScript/Python —
`/mcp/code`; остальные адреса выбирают под конкретную задачу.

Для моделей, которые уверенно пишут код, есть компактный
адрес `https://v2.spiridus.ru/mcp/code`:
в нём только `search` и `execute` (плюс `account_register`, `account_delete`), поэтому каталог занимает меньше
2 тысяч знаков и не растёт при добавлении нотаций. Модель находит инструмент через `search`, получает
его сигнатуру через `search({describe:[...]})`, а затем вызывает нужные инструменты из JavaScript или
Python как `tools.<имя>(args)`. Большие ответы остаются в приватном `private:`-артефакте владельца и
читаются фрагментами через `tools.read`. Вне проекта их можно явно опубликовать через
`files_publish`, получая общий `artifact:`; проектные результаты публиковать нельзя,
для статьи их копируют ресурсами проекта. Через `execute` доступны и инструменты нотаций, которых нет в `/mcp`; подробности — [Code Mode](code.md).

Для моделей, которым проще вызывать инструменты напрямую, есть `https://v2.spiridus.ru/mcp/lite`.
В нём справка, проверка и обновление прежнего документа: `render_blocks`, `render_block_docs`, `render_examples`,
`lint_check`, `render_check`, `document_share`, а также `account_register` и `account_delete`. Новую статью здесь не сохранить:
для записи подключите `/mcp/p/projects`. Каталог занимает меньше 8 тысяч знаков;
`render_check` автоматически использует краткий ответ и один снимок страницы. Полный структурированный
результат сохраняется, а точный формат сценариев взаимодействия доступен как `render_block_docs check`.
`document_share` здесь только сохраняет новую версию своего `/d` по `id`; новый
документ — статья проекта ([ниже](#новые-d-не-создаются)).

`https://v2.spiridus.ru/mcp` — **ядро**: документный цикл, файлы и публикация (`files_*`, `documents_*`),
учётная запись, `code_run` и `tools` для загрузки инструментов по ходу разговора. Каталог ядра вместе с `instructions` — не больше 25 КБ и не растёт с новыми
нотациями. Инструменты нотаций (CAD, PlantUML, QElectroTech, HDL, Modelica…) прямыми вызовами доступны
в **пресетах**: адрес `https://v2.spiridus.ru/mcp/p/<пресет>` — это ядро и инструменты пресета, например
`/mcp/p/cad` (FreeCAD), `/mcp/p/graphics` (Blender, ffmpeg, шейдеры HLSL/Slang) или
`/mcp/p/diagrams` (PlantUML, Structurizr). Адрес выбирает начальный набор. В `/mcp` основной путь — подключать нужное в разговоре
через `tools({use:"diagrams"})`; клиент, который умеет, перечитывает список после `notifications/tools/list_changed` (какие умеют — в [«Набор инструментов в разговоре»](#набор-инструментов-в-разговоре)). Список пресетов с адресами —
в `instructions` сервера `/mcp`; на неизвестный пресет сервер отвечает 404 со списком. `/mcp/p/docs` — то же,
что `/mcp/lite`. У каждого пресета свой бюджет каталога. Полного каталога через MCP нет:
инструменты вне начального набора подключаются через `tools` или вызываются через Code Mode (`/mcp/code`, `code_run`),
если разрешены из кода. REST и `/api/v1/openapi.json` описывают все REST-инструменты; управление каталогом `tools` доступно только через MCP.

Выбор адреса:

- `/mcp/p/projects` — основной адрес для записи и проверки статей;
- `/mcp/code` — вариант для модели, которая уверенно пишет JavaScript или Python: каталог
  короткий, а тёплый пул убирает обычную цену запуска одноразовой песочницы;
- `/mcp/lite` — справка, проверка и обновление своего прежнего `/d`; для нового документа
  используйте `/mcp/p/projects` или Code Mode;
- `/mcp` — ядро и загрузка нужных инструментов через `tools` в разговоре;
- `/mcp/p/<пресет>` — то же и прямые вызовы инструментов одной области (CAD, схемы, электрика…).

Если задача меняется по ходу, начинайте с `/mcp` и добавляйте только нужное:
`tools({add:["project_read","project_write"]})` — чтение и запись статьи без остальных операций
управления проектом; `tools({add:["session_open","session_call","session_close"]})` — работа
с вычислительным ядром, если сеансы включены. Справка `render_block_docs` и проверка `render_check`
уже есть в ядре. Для клиента, который не обновляет список после `list_changed`, выбирайте
готовый пресет при подключении или Code Mode. `/mcp/lite` не содержит `tools`.

Короткий каталог уменьшает начальные затраты контекста, но не гарантирует меньшую цену всего
разговора: поиск, сигнатуры, код, ответы и повторные ходы тоже занимают токены. При добавлении
нотаций начальный каталог `/mcp/code` не растёт, однако близкие описания инструментов могут
затруднить поиск. Уточняйте запрос или задавайте пространство `ns`. Адрес
`/mcp/code/p/<пресет>` даёт приоритет инструментам пресета, но не ограничивает поиск
его областью и не гарантирует улучшения выдачи. Читайте сигнатуру перед вызовом.

Цикл `/mcp/code`: `search({query})` находит имя, `search({describe:[...]})` возвращает сигнатуру,
а `execute` вызывает `tools.<имя>(...)` в одноразовой песочнице. Проверку `render_check` и запись статьи
`tools.project_write` удобно сделать в том же `execute`, вернув в чат только `verdict` и URL.
`document_share` — только новая версия своего `/d` по `id`.

## Набор инструментов в разговоре

После `initialize` с рабочим ключом шлюз выдаёт `Mcp-Session-Id`; гостю сессия не создаётся. Клиент передаёт его в следующих запросах и открывает
`GET` на тот же MCP-адрес с `Accept: text/event-stream` для уведомлений. Набор принадлежит учётной записи
и её ключу: две сессии одного пользователя независимы. Он переживает перезапуск шлюза и удаляется после
24 часов без обращений, при `DELETE` с идентификатором или вместе с учётной записью. Чужой ключ получает
404 и не меняет срок жизни сессии. На владельца — до 100 сессий: новый `initialize` при пределе
вытесняет сессию с самым давним обращением и закрывает её поток. После истечения срока или
вытеснения клиент получает 404 и должен выполнить новый `initialize`.

В ядре `/mcp` есть инструмент `tools`; передавайте один режим за вызов:

| Вызов | Результат |
|---|---|
| `tools({list:true})` | Готовые пресеты (`presets`), свои с адресами (`own`), выбранный `default` и пространства имён |
| `tools({use:"diagrams"})` | Заменить набор на ядро и инструменты пресета |
| `tools({add:"cad_run"})` | Добавить один инструмент; можно массив имён |
| `tools({add:{ns:"cad"}})` | Добавить инструменты пространства имён |
| `tools({remove:["cad_run","cad_recompute"]})` | Убрать инструменты; можно имя или `{ns:"cad"}` |
| `tools({current:true})` | Текущие имена и компактные входные схемы |
| `tools({save:"my-diagrams"})` | Сохранить текущий набор сессии в своей учётной записи; повторное имя заменяет набор |
| `tools({delete:"my-diagrams"})` | Удалить свой пресет; если он был выбран по умолчанию, сбросить настройку |
| `tools({default:"my-diagrams"})` | Выбрать свой или готовый пресет для новых сессий без пресета в адресе |
| `tools({default:null})` | Сбросить выбор по умолчанию: новые сессии начинаются с ядра |

Ядро не снимается. После изменения шлюз отправляет `notifications/tools/list_changed` только в эту
сессию. Ответ `add`/`use` содержит имена всего набора и компактные схемы только вновь подключённых
инструментов; `remove` возвращает имена без схем. `current` явно запрашивает схемы всего набора.
Вызов без режима (`tools({})`) — ошибка. Предел — 100 инструментов и 35 000 байт компактного каталога `tools/list`
(без `instructions`); превышение отклоняется, прежний набор сохраняется. Уберите ненужное через
`remove`, выберите другой пресет через `use` или вызывайте инструменты через Code Mode. Если клиент
не обновляет каталог, используйте схемы и `code_run` для вызова разрешённых из кода инструментов.
Права сохраняются: гостю доступна только регистрация, админские инструменты — владельцу в `/mcp` и `/mcp/default`,
`code: false` по-прежнему запрещает вызов из кода.

Свои пресеты доступны через `tools({use:"my-diagrams"})`, `/mcp/p/my-diagrams` и
`/mcp/code/p/my-diagrams` только их владельцу. В обычном профиле это ядро и сохранённый набор;
в Code Mode каталог остаётся коротким, а поиск повышает инструменты набора. Пресет не выдаёт
дополнительных прав: при сохранении и применении учитываются доступные пользователю инструменты
на текущем адресе. Чужой пресет отвечает так же, как несуществующий. Гостям свои пресеты недоступны.

<summary>Подробности пресетов и выбора по умолчанию</summary>

На владельца — до 20 пресетов. Имя — 1–32 знака: строчная латинская буква в начале, затем
строчная латиница, цифры и дефис; имя готового пресета занять нельзя. Число инструментов и бюджет
каталога — как у набора сессии; превышение предела или неверное имя возвращает HTTP 200 с MCP
`isError` и понятной причиной, прежний пресет сохраняется. Ошибки инструментов REST возвращают
обычно HTTP 422, временная занятость — 503 ([API](api.md#ошибки)); управление набором `tools`
доступно только через MCP. Свои пресеты сохраняются в учётной записи, переживают перезапуск
и удаляются вместе с ней. Если сохранённые данные повреждены, шлюз продолжает работу с пустым набором.
Если новый готовый пресет занял имя своего, своя запись остаётся на диске, но скрывается;
`list` сообщает имена в `conflicts` и подсказку в `warning`. Удалить скрытую запись можно через
`delete`. Неподходящие отдельные записи пропускаются, неизвестный `default` считается `null`;
остальные пресеты доступны, файл не откладывается.

Менять `default`, включая `default:null`, может только основной ключ.

Выбор `default` действует при новом `initialize` на `/mcp`, `/mcp/default` или `/mcp/code`.
Пресет в адресе и `/mcp/lite` имеют приоритет. Наборы уже открытых сессий не меняются при сохранении,
смене настройки или удалении пресета. Если удалён пресет из адреса подключения, продолжите на `/mcp`
с тем же `Mcp-Session-Id`. Без `Mcp-Session-Id` выбор по умолчанию не применяется;
для такого клиента используйте адрес своего пресета.
Если при `initialize` пресет по умолчанию не читается или превышает бюджет текущего каталога,
сессия начинается с ядра, а `instructions` содержит подсказку о сбросе или смене настройки.
Явный `/mcp/p/<свой>` при превышении бюджета возвращает HTTP 400 с причиной. В Code Mode
бюджет схем набора не проверяется: наружу всегда выдаётся короткий каталог.
`default` и `use` выбирают имена инструментов и сохраняют форму текущего профиля; для сокращённых
аргументов и ответов готового `docs` подключайтесь к `/mcp/lite` или `/mcp/p/docs`.

Code Mode сохраняет короткий каталог `search`/`execute`. `search` и `tools.search` повышают инструменты
набора сессии, а без идентификатора — пресета из адреса; остальные разрешённые инструменты доступны
из кода. Идентификатор можно передавать и на `/mcp/code` или `/mcp/code/p/<пресет>`: набор сессии имеет
приоритет над пресетом нового адреса. Исходный адрес в записи — только справка: начальный набор
выбирается при `initialize`, при переходе на другой профиль он не изменяется. Адрес по-прежнему
определяет форму каталога и права: например, начав с `/mcp/lite`, при переходе на `/mcp` клиент
сохранит узкий набор без `tools`; для ядра с `tools` начните новую сессию на `/mcp`.

</details>

Клиенты, игнорирующие заголовок сессии, продолжают работать: каждый запрос без `Mcp-Session-Id`
использует ядро или пресет из адреса, включая `/mcp/code/p/…`. Для изменения через `tools` нужен
идентификатор; `save` также требует его. `list`, `current`, `delete` и `default` доступны и без него.
Анонимному клиенту по-прежнему доступна только регистрация.

Как клиенты работают с набором в разговоре (поддержка зависит от версии; проверка из командной строки через прокси,
который записывал методы и `Mcp-Session-Id`). Claude Code, Codex CLI и Cursor CLI открывают сессию при запуске,
держат один id на все вызовы запуска, а при следующем запуске получают новый id:

| Клиент | Перечитывает список после `list_changed` | После истечения сессии (404) | При выходе |
|---|---|---|---|
| Claude Code 2.1.312 (`claude -p`) | да: сразу запрашивает `tools/list`, новый инструмент вызывается в том же запуске | сам выполняет новый `initialize` и повторяет вызов | сессию не закрывает |
| Codex CLI 0.164.0 (`codex exec`) | нет: инструмента из нового набора в списке нет | сам выполняет новый `initialize` и повторяет вызов | закрывает сессию (`DELETE`) |
| Cursor IDE | зависит от версии клиента | при 404 должен выполнить новый `initialize` | не перепроверено |
| Cursor CLI 2026.10.22 (`cursor-agent -p`) | нет: ответ `tools` с новым набором модель видит, но вызвать новый инструмент в том же запуске не может | не переподключается: повторяет вызов с прежним id и получает «MCP-сессия не найдена»; переподключите сервер (новый запуск) | сессию не закрывает |

Если клиент не перечитывает список, подключайте сразу адрес нужного пресета (`/mcp/p/diagrams`) или
вызывайте инструменты из `code_run` по схемам из ответа `tools`. Сессия истекает после 24 часов без
обращений. На учётную запись — не больше 100 MCP-сессий: при открытии сверх предела закрывается наименее
недавно использованная. Claude Code и Cursor открывают новую сессию на каждый запуск, поэтому при частых
запусках старая сессия (например, скрипта) может исчезнуть раньше 24 часов. Новый `initialize` открывает новую сессию с ядром (или пресетом адреса, или выбранным `default`):
набор, собранный через `tools`, после 404 нужно собрать заново. Если клиент сам не переподключается и
MCP отвечает «MCP-сессия не найдена», переподключите сервер.

## Ошибки в MCP

Ошибка инструмента обычно приходит с HTTP 200 и `isError:true`; читайте текст `content`,
у проектов он начинается кодом (`409: …`). Это отличается от HTTP-ошибки транспорта.
У конфликтов устаревшего `base` есть также `structuredContent.error`: текущий `commit`,
прежний `base`, `reason` и ограниченный список `paths` с `pathCount`/`pathsTruncated`.
Прочитайте новый текст и слейте правки перед повтором; одной замены `base` недостаточно.
У отказов Markdown в этом же объекте доступны `parameter`, `limit`, `line`, `articles`/`errors`
по причине отказа. Текст `content` сохраняется для клиентов без структурированных ответов.

| Где | Код/признак | Что делать |
|---|---|---|
| Инструмент | `409:` конфликт проекта | Перечитать и наложить правку с новым `base`: [рецепт](projects.md#конфликт-записи) |
| Инструмент | `404:` проект/путь | Проверить роль и адрес; чужой и отсутствующий не различаются |
| Инструмент | 400/413/422/507 в тексте | Исправить аргументы, размер или освободить квоту; слепой повтор не поможет |
| Транспорт | 401 / 403 | Проверить ключ, адрес клиента и право `mcp` |
| Транспорт | 404 сессии | Новый `initialize`, затем собрать набор заново |
| Транспорт или инструмент | 429 | Дождаться срока из текста, убрать лишние сеансы/задания; `Retry-After` не гарантирован |
| Инструмент | `isError:true`, текст `503: …`, `_meta.busy:true` | Временная занятость: повторить после паузы. В MCP это HTTP 200 без `Retry-After`; REST возвращает HTTP 503 с `Retry-After: 5` |
| Инструмент | `isError:true`, текст `503: …` без `_meta.busy:true` | Уточнить причину; шаг с неизвестным исходом автоматически не повторять |
| Транспорт | HTTP 503 от внешнего прокси | Проверить доступность шлюза; отличать от ошибки инструмента в результате MCP |
| Транспорт | Разрыв/тайм-аут | Уточнить состояние; исход уже отправленного шага может быть неизвестен |

Не повторяйте автоматически запись или шаг с неизвестным исходом. Для долгих расчётов
используйте [фоновые задания](api.md#асинхронные-вызовы). Полная таблица — [REST](api.md#ошибки).

## Долгие вызовы

Ответ на `tools/call` приходит потоком SSE: пока инструмент работает или ждёт очереди,
шлюз каждые 20 секунд отправляет комментарий `: keepalive`, а затем — обычный ответ
JSON-RPC и закрывает поток. Комментарии игнорируются SSE-клиентом; это не сообщения
модели и не `notifications/progress`, даже если передан `progressToken`.
Streamable HTTP требует от клиента принимать и JSON, и SSE
(`Accept: application/json, text/event-stream`). `initialize` и `tools/list` остаются JSON.
Пример [`mcp.sh`](examples/mcp.sh) читает оба формата и пропускает комментарии.

Пинги защищают от разрыва промежуточным прокси из-за тишины. Они не продлевают
общий timeout клиента или предел времени инструмента: для `code_run` с очередью
может потребоваться около 610 с. Если клиент позволяет, настройте его timeout
соответственно. Отмена через `notifications/cancelled` должна передаваться с тем же
ключом и `Mcp-Session-Id`; разрыв соединения тоже прерывает ожидающий вызов.
Возобновление оборванного POST с ответом пока не поддерживается.

В [REST API](api.md#асинхронные-вызовы) ответы остаются JSON без пингов;
долгие инструменты удобно запускать с `?async=1` и опрашивать задание с `wait`
меньше таймаута вашего прокси.

## Из своего скрипта

MCP — это JSON-RPC запросами `POST` на один адрес. **Без `Mcp-Session-Id`** каждый запрос
самостоятелен, и при прямых запросах шаг `initialize` можно пропустить. Ответ
на `tools/call` — SSE, на `initialize` и `tools/list` — JSON; клиент разбирает оба формата.
Для изменения набора в разговоре начните с `initialize` и сохраняйте выданный заголовок сессии. Нужен заголовок `Accept: application/json, text/event-stream`.

```sh
curl -sS https://v2.spiridus.ru/mcp/p/projects \
  -H "Authorization: Bearer $SPIRIDUS_KEY" -H 'content-type: application/json' \
  -H 'Accept: application/json, text/event-stream' \
  -d '{"jsonrpc": "2.0", "id": 1, "method": "tools/call",
       "params": {"name": "render_block_docs", "arguments": {"lang": "mermaid"}}}'
```

`tools/list` — список инструментов. Скрипт целиком — [`examples/mcp.sh`](examples/mcp.sh).

**Сессия из командной строки.** [`examples/mcp.sh`](examples/mcp.sh) открывает сессию командой `init`
(`initialize` и `notifications/initialized`) и печатает `Mcp-Session-Id`; с переменной `SPIRIDUS_SESSION`
каждый следующий запуск передаёт этот заголовок. Сам скрипт сессию не закрывает: набор переживает выход
процесса и доступен из других процессов с тем же ключом (с другим ключом тот же id получает 404), пока не
пройдёт 24 часа без обращений, не будет вызван `close` (`DELETE`) или сессию не вытеснят более новые сверх
предела 100 на учётную запись. Ответ разбирается и как JSON, и как поток SSE. Код выхода 1 — ошибка HTTP
или JSON-RPC и ответ инструмента с `isError`.

```sh
export SPIRIDUS_MCP=https://v2.spiridus.ru/mcp
export SPIRIDUS_SESSION=$(./mcp.sh init)
./mcp.sh tools '{"use": "diagrams"}'   # заменить набор: ядро и схемы
./mcp.sh list                          # в любом новом процессе — уже с render_recipes, plantuml_run…
./mcp.sh render_recipes '{}'           # инструмент из нового набора
./mcp.sh tools '{"current": true}'     # текущий набор со схемами
./mcp.sh close                         # закрыть сессию явно
```

После `close` или истечения запрос с тем же id получает 404 «MCP-сессия не найдена»: уберите старый id
(`unset SPIRIDUS_SESSION`), откройте новую сессию (`export SPIRIDUS_SESSION=$(./mcp.sh init)`) и соберите
набор заново.

**Сеансы ядер** (Python, FreeCAD, Lean, Blender, Modelica, QET) живут независимо от MCP-сессии.
Открытие, работа из скрипта, передача модели и сохранение — [sessions.md](sessions.md).

Библиотекой — для Python `pip install mcp`. Библиотека работает по протоколу целиком и начинает с
`initialize` сама — его вызов в примере нужен ей, а не нашему серверу:

```python
import asyncio, os
from mcp import ClientSession
from mcp.client.streamable_http import streamablehttp_client

async def main():
    headers = {"Authorization": "Bearer " + os.environ["SPIRIDUS_KEY"]}
    async with streamablehttp_client("https://v2.spiridus.ru/mcp", headers=headers) as (read, write, _):
        async with ClientSession(read, write) as s:
            await s.initialize()
            r = await s.call_tool("render_block_docs", {"lang": "mermaid"})
            print(r.content[0].text[:300])

asyncio.run(main())
```

Для Node — `@modelcontextprotocol/sdk` (`Client` и `StreamableHTTPClientTransport`).

Те же инструменты есть и в [REST API](api.md) — там ещё асинхронные задачи для долгих песочниц.

## Что умеет

Список инструментов с описаниями отдаёт сам сервер (и `GET /api/v1/tools` в REST); для людей — [tools.md](tools.md). Главное:

- `render_blocks`, `render_block_docs` — какие блоки есть и как их писать;
- `render_examples`, `render_recipes` — готовые примеры и рецепты починки замечаний;
- `render_check` — нарисовать документ и получить замечания; снимки блоков и страницы;
- `lint_check` — только линтеры, без отрисовки: один блок кода или документ, за пару секунд;
- песочницы: `plantuml_run`, `structurizr_run`, `hdl_synth`, `hdl_sim`, `quantum_run`, `modelica_run`,
  `cad_run`, `cad_recompute`, `blender_run`, `qet_run`, `text_parse` — результат вставляется в документ
  строкой из ответа;
- в прежних `/d` модели с параметрами читатель пересчитывает полями без ключа; на `/p` пересчёта пока нет: FreeCAD — стройте
  от таблицы `Spreadsheet`, у каждого параметра — **псевдоним ячейки** (`setAlias`), в формулах —
  `Params.<псевдоним>`, не адрес ячейки (`cad_run` отдаст блок ```` ```freecad ````); Modelica — числа в
  `parameter Real имя = 300 "пояснение";` становятся полями, новые значения — строки `// set:`;
- `document_share` (прежний формат) — обновить документ `https://v2.spiridus.ru/d/<id>`: открывается без ключа,
  как у читателя; с тем же `id` — новая версия по той же ссылке. Новые `/d` не
  создаются, остаётся только обновление своего по `id` ([ниже](#новые-d-не-создаются));
- `documents_catalog` — одна ссылка на каталог всех своих документов, обновляется сам;
- `projects` в ядре и пресет `/mcp/p/projects` (ниже).

Ответы песочниц кешируются: тот же вызов второй раз приходит сразу, с `"cached": true` и временем
первого запуска — [api.md](api.md#кеш-результатов).

Хороший цикл для модели: прочитать [формат документа](markdown.md)
(`render_block_docs({lang:"markdown"})`) и справку нужного языка → написать документ →
`render_check` → исправить замечания → снова `render_check` с выбранным `strict` →
`project_write` → пригласить человека в проект и дать ссылку `/p/…`.

Лимиты и очередь — как у REST: [api.md](api.md#лимиты-и-очередь). Хранение запросов и исключения для проектов — [data.md](data.md).

## Фоновые задания

Добавьте `tools({add:["job_status","job_cancel","image_view"]})`, чтобы опрашивать задания и
смотреть картинки, сохранив проектные инструменты. `tools({use:"jobs"})` заменяет набор;
в `/mcp/p/jobs` нет `project_*`. Постановка, статусы, отмена, сроки и права —
[REST](api.md#асинхронные-вызовы) и [Code Mode](code.md#фоновые-задания).

## Проекты

Для статей выбирайте `/mcp/p/projects`: `project_read` → `project_write` с `base` →
`render_check` с `project` и `path`. Роли, приглашения, ресурсы, конфликт 409, навигация,
удаление и импорт — [«Проекты»](projects.md). Без `project` снимки проверки публичны по ссылке.

### Новые `/d` не создаются

`document_share {id}` обновляет только свой прежний документ. Совместимость, импорт
и **удаление записи без проектов через 7 дней простоя без письма** —
[«Прежние документы»](projects.md#прежние-документы-d).

## Структурированные результаты

У типизированного инструмента tools/list содержит outputSchema, а tools/call возвращает полный
объект в structuredContent. content содержит сводку для чтения, картинки и ссылки; разбирать
сводку как JSON не нужно. У ещё не переведённых инструментов сохраняется прежний текстовый JSON.
У render_block_docs полный текст справки сохранён и в content, и в structuredContent.result для
совместимости с клиентами, которые показывают модели только текст. Ошибки isError остаются текстовыми.

Схемы есть у проверки документа и линтеров, публикации документа, PlantUML, Structurizr,
FreeCAD (включая сеансы), общих сеансов, `code_run`, `ffmpeg_run`, `lean_check` и `lean_session_*`.
У Code Mode схемы ответов также попадают в сигнатуры `search({describe:…})`, `tools.describe`
и справку `render_block_docs {lang:"code"}` (TypeScript и Python). Неизвестные заранее
значения сценариев остаются `unknown`/`Any`; отсутствие поля отличается от `null`.

## Большие файлы


Большие файлы загружает клиент прямо в S3: `files_upload({name, size, type})` выдаёт PUT или
части по 64 МиБ, `action: "status"` обновляет ссылки для докачки, `action: "finish"` с
`upload_id` возвращает `blob:sha256/<хеш>` для инструментов. Base64 для этого пути не нужен.
[Протокол и лимиты](api.md#большие-загрузки-в-s3); исходные пределы инструментов сохраняются.
