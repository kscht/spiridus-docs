# Сеансы ядер

Ядро сохраняет переменные, импорты и рабочие файлы между шагами. На `v2.spiridus.ru`
сеансы включены; на других установках зависят от настройки сервера. Это не MCP-сессия:
`Mcp-Session-Id` выбирает набор инструментов разговора, `session` — живое вычислительное состояние.
Закрытие MCP-сессии не закрывает ядро. Ядро доступно ключам той же учётной записи с нужными правами;
отзыв ключа, которым оно открыто, закрывает его.

## Выбрать ядро

Срез `sandbox_builds` production от 28.10.2026; актуальный статус запрашивайте снова перед работой.
`next` — сборка на пробу, её выбирают явно; `stable` — рабочая, `default` — основная для своего инструмента.

| Ядро | Открыть | Шаг | Сохранить | Вернуться позже | Сборка и статус |
|---|---|---|---|---|---|
| Python | `session_open` | `session_call` или `code_run` с `session`, Python | `session_save` → `ref` пакета | `session_open {from: ref}` | `python-3.13.7-code`, `stable` |
| FreeCAD | `cad_session_open` | `cad_exec`, `cad_inspect`, `cad_view` | `cad_session_save` (пакет и модель), `session_save` | `cad_session_open {from}` или `session_open {from}` | `freecad-1.1.4-timashkovy`, `default` |
| Lean | `lean_session_open` | `lean_session_command`, `lean_session_tactic`, `lean_session_goals` | `lean_session_save` → пакет | `lean_session_open {from}` | `lean-4.34.0-widgets`, `default` |
| Blender | `blender_session_open` | `blender_exec`, `blender_inspect`, `blender_view` | `blender_session_save` → `.blend`, STL, `script.py`, файлы | Новый сеанс с прежними `inputs`, повторить `script.py`; `.blend` можно скачать для локального Blender, пакета `from` нет | `blender-5.2.2-session`, `next` |
| Modelica | `modelica_session_open` | `modelica_simulate` | Пользовательского save/from нет | Снова открыть из исходного `.mo` и параметров | `openmodelica-1.27.1-session`, `next` |
| QET | `qet_run` → `session` | `qet_tools`, `qet_call` | `qet_save` → `.qet` и результаты | Новый `qet_run` с сохранённым `.qet`; не пакет `session_open` | `qelectrotech-0.200.1-dev-f4dcbcc-kernel`, `default` |

Для Blender сохраните `script.py` и исходные входные файлы: в новом сеансе передайте те же
`inputs` и повторите сценарий. Экспорт `.blend` сохраняет сцену для скачивания и локального Blender,
но **`blender_session_open inputs` сейчас не принимает `.blend`**, а `load()` его не открывает.
Своего пользовательского пакета восстановления ядра нет. Экспортированный STL можно загрузить
как геометрию в новую сцену, но он не возвращает материалы, камеру и Python-переменные.
Lean имеет собственный пакет
до 2 МиБ и 200 команд; при открытии proofState создаются заново. Подробности —
[Lean](blocks/lean.md), [QET](blocks/qet.md), [Modelica](blocks/modelica.md), [Blender](blocks/sandbox.md).

## Открыть и передать модели

В начальном `/mcp` инструментов сеансов нет: добавьте `tools({add:{ns:"session"}})`
или выберите предметный пресет (`cad-steps`, `proofs`, `graphics`, `modelica`, `electric`).
REST и Code Mode вызывают разрешённые инструменты без изменения каталога.

Открывая Python/FreeCAD/Lean/Blender/Modelica внутри `execute` или `code_run` для следующих
вызовов, задайте `keep:true` у инструмента открытия, например `tools.session_open({keep:true})`.
Без него сеанс закроется вместе с выполнением. Прямое открытие через MCP/REST оставляет
сеанс открытым; завершите его через `session_close`.
[Пример FreeCAD из Code Mode](code.md#пошаговый-freecad-из-code-mode).

```sh
export SPIRIDUS_MCP=https://v2.spiridus.ru/mcp
export SPIRIDUS_SESSION=$(./mcp.sh init)
./mcp.sh tools '{"add":{"ns":"session"}}'
K=$(SPIRIDUS_FIELD=id ./mcp.sh session_open '{}')
./mcp.sh session_call "{\"session\":\"$K\",\"code\":\"x = 42\nreturn x\"}"
./mcp.sh close
```

Используется [mcp.sh](examples/mcp.sh) с ключом из окружения. Скрипт может заранее загрузить
данные и вычислить агрегаты, затем передать модели только `id` ядра и имена переменных.
Модель вызывает `code_run` с `session`, `language:"python"` и коротким кодом, возвращая числа,
а не весь DataFrame. Завершив работу, закройте `session_close` (Lean также `lean_session_close`).
Для возврата после закрытия заранее сохраните пакет или исходные файлы.

## Сроки и восстановление

По умолчанию до двух открытых сеансов на учётную запись, гостю — ни одного. Начальный бюджет —
480 минут·ГБ в сутки; память оплачивается временем жизни ядра, включая простой. `session_list`
показывает сеансы и расход. 429 перечисляет занятые места; закройте ненужное ядро.

У всех шести текущих ядер `idleSec: 900`, `maxSec: 7200`: после 15 минут простоя или 2 часов
ядро сохраняется и выгружается, следующий шаг восстанавливает его. Python проигрывает команды,
FreeCAD/Blender используют точку сохранения, когда она полна; Modelica восстанавливает расчёт.
Это внутреннее восстановление, а не пользовательский пакет на неопределённый срок.
Выгруженный сеанс обычно закрывается через 7 дней без возобновления, **QET — уже через
30 минут без команд** (`abandonIdleSec: 1800`); `qet_save` может забрать сохранённый workspace
после закрытия, пока он ещё доступен. Предел времени отдельного шага берётся из сборки.
Ошибка шага не отменяет уже сделанных внешних действий; при неизвестном исходе не повторяйте
шаг автоматически. [Ошибки и повтор](api.md#ошибки).

Пакеты `upload:` гарантированно хранятся **сутки**, затем — пока есть место. Чтобы вернуться через
дни, скачайте пакет к себе. Для `upload:<id>/session.json`:

```sh
curl -fsS "https://v2.spiridus.ru/api/v1/files/$PACKAGE_ID/session.json" \
  -H "Authorization: Bearer $SPIRIDUS_KEY" -o session.json
curl -fsS -X POST 'https://v2.spiridus.ru/api/v1/files?name=session.json' \
  -H "Authorization: Bearer $SPIRIDUS_KEY" -H 'Content-Type: application/octet-stream' \
  --data-binary @session.json
```

Задайте `PACKAGE_ID` из своей ссылки `upload:<id>/session.json`, затем передайте новый `upload:…/session.json` в `session_open {from}`
(для Lean — `lean_session_open`). Нужны право `files`, записанные в пакете scopes,
текущий доступ к помеченному проекту и подходящий `imageId`; `rebuild` разрешает переиграть на новой
сборке с предупреждением. Повторная загрузка не снимает этих проверок и не является способом
снять метку проекта. [Сроки хранения](data.md#сколько-хранится).

## Пакеты Python и FreeCAD

Python восстанавливается исполнением успешных команд из журнала; явно записанные в `/out` файлы
сохраняются отдельно. Ответы `tools.*` при восстановлении берутся из журнала: инструменты второй
раз не вызываются. Для повторяемых вычислений фиксируйте случайные числа и исходные данные;
время и другие недетерминированные операции при повторном исполнении могут дать другой результат.
Ошибка шага сбрасывает частично изменённую память к последнему успешному состоянию; уже выполненные
внешние действия этого шага не отменяются. Журнал ограничен 200 командами и 8 МиБ.

### Сохранить сеанс и открыть позже

`session_close` освобождает ядро, и после него сеанс не поднять. Для возвращения позже перед
закрытием вызовите `session_save {session}`: шлюз кладёт в ваши приватные файлы пакет
`upload:<id>/session.json` (виден только вам, в документы не публикуется). Открыть —
`session_open {"from": "upload:<id>/session.json"}`: получится **новый** сеанс с новым `id`
(предел двух сеансов действует), в котором шаги проиграны заново.

В пакете нет снимка памяти и pickle — только то, из чего состояние воспроизводится:

- код каждого успешного шага и ответы инструментов, которые шаг получил (`tools.*`);
- файлы `/out` (base64) со списком и размерами, не больше `outMb` сборки (у Python — 4 МБ): `input` —
  какими они были до первого шага (с них шаги проигрываются), `files` — после последнего шага; у шага
  бывают свои `files` — итог прежнего пакета, если сеанс сам был открыт из пакета: они накладываются сразу
  после этого шага, и следующие шаги читают те же файлы, что и при первом сохранении;
- `seed` сеанса: при старте ядро задаёт `random.seed` и `numpy.random.seed`, поэтому случайные
  числа после проигрывания те же;
- сборка и `imageId` образа, на котором ядро выполнило шаги, дата и сценарий `script` — шаги подряд для
  чтения человеком.

При открытии ответы инструментов берутся **из пакета**: `render_check` и другие второй раз не
вызываются и квоты не тратят. `refresh: true` — вызвать их заново (дольше, тратит квоты, только
вне Code Mode); в ответе `differences` — шаги и вызовы, чьи ответы разошлись с записанными.
Если сборка удалена, заменена, устарела (`deprecated`/`sunset`) или у неё другой `imageId`,
открытие отказывает с причиной; `rebuild: true` проигрывает шаги на текущей сборке с
предупреждением «результаты могут отличаться». Образ сверяется и на самом узле перед проигрыванием:
сразу после пересборки, пока список сборок ещё показывает прежний `imageId`, открытие без `rebuild` тоже откажет.

Воспроизводится то, что зависит только от кода, ответов инструментов, файлов и seed. Время,
порядок обхода множеств, `id()` объектов, генераторы случайных чисел помимо `random` и
`numpy.random` (например `numpy.random.default_rng()` без seed) — недетерминированы: такой
результат сохраняйте файлом в `/out`. Пределы пакета: 200 шагов, шаги ≤ 8 МиБ, не больше 20
вызовов инструментов на шаг, весь пакет — не больше предела загрузки. Сеанс, закрытый сторожем
пробоя, сохранить нельзя. Сеанс, связанный с проектом, сохраняется вместе с меткой проекта: открыть пакет
можно, пока у вас есть доступ к этому проекту. Пакет помнит права ключа, которые понадобились сеансу (например, `docs` или
`files`): открыть его можно только ключом с этими правами. Если шлюз не знает, откуда сеанс (например, метка истекла
через сутки), сохранение отказывает — откройте новый сеанс.

Сеанс FreeCAD сохраняется так же: `session_save` или `cad_session_save` (он ещё выгружает модель и блок)
пишет пакет с `kind: "freecad"`: шаги, `files` — точка сохранения ядра (`checkpoint.FCStd`,
`bindings.json` с простыми переменными) и свои файлы `/out` без выгрузок экспорта и вида, `resume` —
переменные в точке полные (файл точки больше 32 МиБ в пакет не входит — тогда `resume: false` и `warning`).
Открывают его `cad_session_open {from}` или `session_open {from}`: при
`resume` новый сеанс открывает документ без проигрывания шагов, иначе шаги проигрываются; `rebuild: true`
(только `session_open`) всегда проигрывает шаги на основной сборке. `refresh` у FreeCAD нет.

Пакет можно править: он исполняется только в песочнице от вашего имени и в ваших лимитах, а
подставленный «ответ инструмента» получает лишь код этого же пакета. Схема строгая: лишние поля,
пути с `..` или абсолютные, неверные размеры — отказ.
