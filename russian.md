# Проверка русского текста

Русский текст документа Spiridus проверяет двумя способами:

- **`render_check`** вместе с рисунками проверяет и текст: опечатки, пунктуацию, кавычки и тире,
  канцелярит, повторы. Включено по умолчанию.
- **`text_parse`** — синтаксический разбор предложений: дерево зависимостей, части речи, члены
  предложения. Анализатор выбирается параметром вызова, можно несколько сразу — для сравнения.

Набор программ и моделей задан сборкой песочницы `text-2026.10-cli` (версии — [tools.md](tools.md#сборки-песочниц-версии-программ)).
Свою модель подключить нельзя: сборка закрыта и работает без сети. Новые модели появляются новой
сборкой ([blocks/sandbox.md](blocks/sandbox.md)).

## Проверка текста в `render_check`

| Проверка | Что находит | Правила в замечаниях |
|---|---|---|
| `typograf` (typograf 7.8.0) | кавычки «ёлочками», тире вместо дефиса, неразрывные пробелы | `кавычки`, `тире`, … |
| `languagetool` (LanguageTool 6.6) | орфография, грамматика, пунктуация, повтор слова | `spelling`, `WORD_REPEAT_RULE`, … — имена правил LanguageTool |
| `sage` (SAGE, модель `sage-fredt5-distilled-95m`) | второе мнение: опечатки и пропущенные запятые | `spell`, `comma` |
| `vale` (Vale 3.23.0 со стилем Spiridus) | канцелярит, «является», слова-пустышки, длинные предложения | `Spiridus.Kantselyarit`, `Spiridus.Yavlyaetsya`, `Spiridus.Fillers`, `Spiridus.SentenceLength` |
| `spiridus` (правила на морфологии pymorphy3) | слово повторилось, цепочки существительных в родительном падеже | `repeat`, `genitive-chain` |

Замечание о тексте — `kind: "text"`, текст начинается с проверки и правила:

```json
{ "line": 3, "kind": "text", "text": "vale Spiridus.Yavlyaetsya: «является» — связка канцелярита: …", "hint": "…" }
```

По умолчанию замечания о тексте **не меняют `clean`**; `strict: ["text"]` включает их в приёмку. Код, формулы и блоки
текстом не считаются и не проверяются.

### Как настроить

Параметров вызова у проверки текста нет, кроме одного: `"text": false` — проверить документ без
неё. Остальное пишут **в самом документе** HTML-комментарием (читатель его не видит):

```markdown
<!-- text-words: слайсер, кубит, перерегулирование -->
<!-- text-ignore: Spiridus.Fillers, WORD_REPEAT_RULE -->
<!-- text-ignore: sage -->
```

- `text-words` — свои слова: термины и названия, которых нет в словаре. Их не считают опечатками.
- `text-ignore` с именем правила — не показывать это правило. Имя — точно как в замечании, после
  имени проверки: `Spiridus.Fillers`, `WORD_REPEAT_RULE`, `genitive-chain`.
- `text-ignore` с именем проверки — выключить её целиком: `typograf`, `languagetool`, `sage`, `vale`,
  `spiridus`.

Комментариев может быть несколько, имена — через запятую.

`render_check` всегда проверяет текст основной сборкой проверки текста. Его параметр `build` —
сборка браузера, который рисует документ, а не сборка проверки текста.

## Синтаксический разбор: `text_parse`

```sh
curl -sS -X POST https://v2.spiridus.ru/api/v1/tools/text_parse \
  -H "Authorization: Bearer $SPIRIDUS_KEY" -H 'content-type: application/json' \
  -d '{"text": "Старый кот пил молоко.", "parsers": ["udpipe2", "stanza"]}'
```

Ответ — готовый блок ```conllu для документа (`data.block`): дерево над словами, части речи под
ними. Несколько анализаторов рисуются друг под другом, расхождения с первым выделены цветом. Время
и лицензия каждого — в `data.parsers`. Как блок устроен — [blocks/conllu.md](blocks/conllu.md).

### Как выбрать анализатор

| Аргумент | Что |
|---|---|
| `parsers` | список анализаторов, до 6; по умолчанию `["udpipe2"]`. **Первый — образец**: с ним сравниваются остальные |
| `terms` | подписи: `both` (по умолчанию) — термины UD и школьные, `ud` — только UD (`nsubj`, `NOUN`), `school` — только школьные (подлежащее, сущ.) |
| `text` | до 20 000 знаков; разбираются первые 60 предложений |
| `build` | сборка: `text-2026.10-cli` (по умолчанию); пробные сборки — `sandbox_builds({program:"text"})` |

Один анализатор:

```json
{ "text": "Мы пошли в лес, хотя было поздно.", "parsers": ["stanza"] }
```

Стихи — голова разбора, обученная на поэзии, и для сравнения — основная:

```json
{ "text": "Мороз и солнце; день чудесный!", "parsers": ["udpipe2-poetry", "udpipe2"] }
```

Быстро и грубо — только школьные термины:

```json
{ "text": "…", "parsers": ["slovnet"], "terms": "school" }
```

Через MCP — те же аргументы у инструмента `text_parse`.

### Анализаторы

Точность — **LAS**: доля слов, у которых верно найдены и главное слово, и тип связи. Меряли на
тестовых частях трибанков Universal Dependencies — текстах, размеченных лингвистами вручную:
SynTagRus (новости, научпоп, проза), Taiga (соцсети, блоги, форумы), GSD (Википедия), Poetry (стихи).
Скорость — на Taiga, 2 ядра. Подробно, с графиками — [замер анализаторов](https://v2.spiridus.ru/reports/text-bench).

| `parsers` | Модель | LAS: SynTagRus / Taiga / GSD / Poetry | Предложений в секунду | Лицензия |
|---|---|---|---|---|
| `udpipe2` | UDPipe 2, модель `ru_all` (UD 2.17), голова SynTagRus | 93,4 / 85,7 / 88,1 / 86,5 | ~20 | код MPL-2.0, **модель CC BY-NC-SA** |
| `udpipe2-taiga`, `udpipe2-gsd`, `udpipe2-poetry` | та же модель, головы разбора, обученные на Taiga, GSD, Poetry | на своём жанре ещё +1–2 | ~20 | код MPL-2.0, **модель CC BY-NC-SA** |
| `stanza` | Stanza 1.14.0, модели на SynTagRus | 92,1 / 81,7 / 82,9 / 78,7 | ~30, в сборке `-openblas` ~47 | код Apache-2.0, **модель CC BY-NC-SA** |
| `spacy-md`, `spacy-lg` | spaCy 3.8.16, `ru_core_news_md` и `_lg` | 82,6 / 74,1 / 80,4 / 67,4 (lg — так же) | ~430 | MIT |
| `udpipe` | UDPipe 1.4, `russian-syntagrus-ud-2.5` | 81,3 / 71,0 / 72,0 / 64,5 | ~650 | **CC BY-NC-SA** |
| `slovnet` | Slovnet 0.6.0 (Natasha) | 77,0 / 66,1 / 74,4 / 53,6 | ~2260 | MIT |

Что выбрать:

- **Точнее всего — `udpipe2`**, на всех жанрах. Для стихов, соцсетей и Википедии — его голова
  своего жанра (`udpipe2-poetry`, `-taiga`, `-gsd`).
- **`stanza`** почти так же точна на SynTagRus (новости, проза) и быстрее UDPipe 2 в полтора-два
  раза, но на стихах и соцсетях отстаёт на 4–8 пунктов.
- **`spacy-md`, `udpipe`, `slovnet`** — в десятки и сотни раз быстрее и на 10–20 пунктов грубее.
  `spacy-lg` не точнее `spacy-md`. Slovnet на стихах ошибается в каждой второй связи.
- Сравнить анализаторы на своём тексте — несколько в `parsers`: блок покажет, где они расходятся.
- `udpipe2` и `stanza` сначала загружают модель — на это уходит 10–15 секунд даже для одного
  предложения; дальше — со скоростью из таблицы.
- В сборке `text-2026.10-openblas` Stanza быстрее в 1,4 раза (те же модели, другая математическая
  библиотека); сборка пробная (`next`): `"build": "text-2026.10-openblas"`.

### Лицензии: что можно только некоммерчески

Модели **UDPipe 1 и 2 и Stanza** обучены на SynTagRus и выпущены под **CC BY-NC-SA**: их разборы —
только для некоммерческого использования, с указанием автора и под той же лицензией. Для
коммерческого проекта берите `spacy-md`, `spacy-lg` или `slovnet` (MIT). Лицензия каждого анализатора
приходит и в ответе — `data.parsers.<имя>.license`.

Проверка текста в `render_check` (LanguageTool, SAGE, Vale, typograf) синтаксические модели не
использует.
