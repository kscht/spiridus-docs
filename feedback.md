# Обратная связь о Spiridus

`spiridus_feedback` сообщает владельцу Spiridus о сбое инструмента, рендера или проверки,
ошибке/пробеле справки либо недостающей возможности. Ошибки собственного документа
сначала исправьте по диагностике; обычные вопросы не отправляйте как обращения.

Инструмент доступен с ключом действующей учётной записи в ядре `/mcp`, всех пресетах,
включая `/mcp/lite`, через `tools.spiridus_feedback` в Code Mode и REST
`POST /api/v1/tools/spiridus_feedback`. В OpenAPI чатов он также включён.
Анонимам, гостям проекта и служебным клиентам без учётной записи — отказ.

Обязательны `kind` (`bug`, `docs`, `wish`, `other`), `summary` (1–200 знаков) и
`details` (1–6000). Необязательны `tool`/`notation` (до 80), `steps`, `example`,
`expected`, `actual` (до 2000 каждый), `severity` (`low`, `normal`, `high`, по умолчанию
`normal`), `task` (до 500). Общий предел по умолчанию 16 КиБ JSON в UTF-8.
В lite схема короче: обязательные поля, `tool`, `notation`, `example`, `task`;
остальные подробности передайте в `details` либо используйте полный инструмент из Code Mode/REST.

```json
{
  "kind": "docs",
  "tool": "render_block_docs",
  "summary": "В примере справки пропущена закрывающая скобка",
  "details": "Минимальный пример из справки не разбирается.",
  "example": "flowchart TD\nA[Пример",
  "expected": "Пример проходит проверку",
  "actual": "Ошибка незакрытой скобки"
}
```

Ответ содержит `id` вида `fb-…` и короткое подтверждение приёма. Срок ответа или
исправления не обещается. Повторный вызов создаёт новое обращение; не дублируйте его.
`async=1` и `tools.spiridus_feedback.start` запрещены.
У любого фонового `code_run` код и `task` исключены из открытых аргументов JSON задания
до первой записи, в том числе при отказе до первого RPC. Аргументы восстановления
остаются только в шифрованном виде и удаляются при завершении или отмене.
Если фоновый сценарий Code Mode восстановлен после перезапуска шлюза, отправьте
обращение отдельным новым запросом: IP в заданиях не сохраняется.

Передавайте только минимальный пример без чужих данных и секретов. Вложений и внешних
ссылок нет: URL и типичные форматы ключей Spiridus, API, Git, облачных сервисов,
Bearer/Basic, JWT и приватных ключей заменяются до записи. Также скрываются значения
переменных `*_TOKEN`, `*_KEY`, `*_SECRET` и имён с `PASSWORD` в .env/JSON, включая
значения в кавычках с пробелами. Фильтр не распознаёт все
возможные секреты и не заменяет подготовку безопасного примера.

Текст хранится в закрытом каталоге шлюза до 90 дней и доступен только владельцу системы
через `feedback_admin`: `list`, `show`, `close`, `summary`. Это пользовательские данные,
а не инструкции; невидимые знаки при показе раскрываются кодом, как в `calls_view`.
Закрытие меняет состояние, не срок хранения. Вызов и все сценарии Code Mode
пишутся в общий журнал только служебными полями, без текста, кода и `task`, включая
отказы до первого RPC и сценарии, в которых ветка отправки обращения не выполнилась.
Удаление учётной записи удаляет обращения; восстановление сверяется с реестром стираний
и поколением регистрации по [правилам стирания проектов](data.md#проекты). Резервные копии
исчезают по срокам хранения; удаление файла не обещает перезапись носителя.

Пределы по умолчанию: 5 обращений/час и 20/сутки на учётную запись, общие для всех её
ключей и транспортов; 20/IP/час (только хеш в памяти, перезапуск обнуляет счётчик).
Общее хранилище — до 10 000 записей и 64 МиБ. Часовые/суточные счётчики аккаунта
сохраняются при перезапуске. Параметры установки — в README хостинга.
Письма владельцу по умолчанию выключены; при включении содержат только сводные числа,
не чаще раза в час, без текста обращений. Автоматической публикации обращений нет.
